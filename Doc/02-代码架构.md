# ⚠️ 全局编码规范：禁止使用 null 条件运算符 `?.`、禁止静默处理异常和非法兜底（最高优先级，适用于所有代码）

- 关于禁止使用 null 条件运算符 `?.`
- 本项目**一律不使用 `?.`**：GameObject、Component（含 Transform/Camera/各 Manager/EntityAnim 等）、普通 C# 类、委托、List——全部适用，无一例外。
- 写法：**非必要时一律写成 `if (x != null) ...` 判断**；确有充分理由需要 `?.` 的，必须先向用户说明并征得同意。
- 原因：① Unity 对象重载了 `==`，已销毁对象是"伪装 null"，`?.` 检查的是托管引用，会绕过 Unity 生命周期判断，产生语义错误；② `?.` 链与 out 参数、空条件组合会引发 CS0170 等隐蔽问题（历史案例：`Tool.X?.Method(out var v)` 中 `?.` 短路导致 v 未赋值）。
- 同理 `??`（null 合并）在 Unity 对象上也应避免配合伪装 null 使用；`??` 用于普通 C# 可空值类型（如 `float?`）不受限制。

- 关于禁止静默处理异常和非法兜底
- 本项目要求除非就是这么设计的，否则绝对不允许使用判空或别的处理静默处理异常的方式
- 原则：**非必要时一律不进行==null判断**，除非设计上为null就是允许的，设计上不允许null的地方，不要判空，或者判空时要添加日志。**非必要时一律不设置兜底值**，除非就是这么设计的
- 原因：静默判空会导致异常无法被及时发现，而且异常的兜底本身会造成后续的其它问题
- 举例：尝试获取InfoManager组件时没找到组件（为null），就代码直接添加组件，这只是一时解决了判空的问题，但它完全没有正常组件应有的值，后续调用它的位置也会全部错误，不如直接"Tool.InfoManager.xxx"引用所需字段，并立即导致报错，至少能立即发现错误并阻断而不是后续还要定位问题
- **判定口径**：出错时**有 error/warning 日志输出**、之后继续执行的，不算静默兜底（问题已暴露）；只有"完全无声地跳过、给默认值顶替、或造一个空对象"才算违规
- **允许"找不到就补一个"的唯一条件**：补出来的组件必须在**补的同一次调用里**把参数全部设成正确值——不依赖其它资产引用、也不存在"只在异常时才会用"的兜底参数。**按此口径逐个核对后的现状（模板与图形预制体均以 `Assets/Files/Prefabs/Entity` 现存资产为准）**：

| 补的位置 | 补的组件 | 预制体现状 | 参数是否在同处设全 |
| --- | --- | --- | --- |
| `EntityData.SetupBody` | `Rigidbody` | 全部实体预制体都没有 | 是：useGravity / constraints / interpolation / drag / angularDrag 全为常量或 `Config` |
| `EntityModelInfo.BuildCapsuleCollider` | `CapsuleCollider` | 多数没有；仅 `AlienTree00`（中立雕像模板）/ `GasTree00`（水晶雕像模板）/ `MeduseTree00b`（守护雕像模板）自带 | 是：自带即复用，direction / height / center 按 `EntityModelInfo` 的 y / x / zRange 覆盖，radius 固定写死为 `GlobalConfig.entity_capsule_radius`（0.22m）（自带那个必须 enabled 且非 trigger，现有 3 个都满足） |
| `BattleManager.SpawnEntity` → `EntityData.AddTo` | `EntityData` 子类 | 全部没有——模板与客户端图形是同一批预制体，故不挂 | 是：字段全部由随后的 `OnCreate` 赋值 |
| `EntityPlayerManager.CreateView` | `ClientEntityView` | 全部没有 | 是：id / type / camp / modelInfo / anim 在建视图流程内赋值 |
| `EntityPlayerManager.CreateView` | `Rigidbody` | 全部没有 | 是：isKinematic / interpolation / collisionDetectionMode / constraints 全定死 |
| `BulletPlayer.Create` | `BulletPlayer` | 124 个特效预制体全部没有 | 是：trajectory / lifeTime / rotation 由调用方传入 |

- 反之，**用空物体或不带数据的默认值顶替缺失资产不属于"可自我补全"**，必须报错：例如建视图时图形缺失就 `new GameObject` 且不打日志（`EntityPlayerManager.CreateView`）

总体原则
原则上客户端只是接收服务器的信息摘要并将其转化为表现展示给玩家的，核心移动/战斗内容都在服务器完成计算，不让客户端处理关键逻辑，非关键逻辑可放在客户端（减少服务器压力/简化服务器代码）
如果代码中涉及了需要在项目中制作预制体等ai不方便操作的相关内容，则应当向用户具体描述需求
Server场景挂 `AssetsManager`（同步直接引用），Client场景挂 `ResourceManager`（Addressables 按需加载），两者不同时出现；其余GameController下内容两端也都包含，服务器场景添加RSServerLauncher启动服务器。服务器场景要挂上 `ModularTerrainGenerator` 才能拿到地形点位与地面射线
Client场景包含GameController下全部内容
服务器上的实体应该只调用一个模板（只包含各类组件但没有图形的预制体，InfoManager引用），客户端的实体才会包含具体贴图模型表现
服务器上的实体模板可直接复制和销毁，不用Pool
尽量不要硬编码事件id或固定消息，可在GlobalData创建各类静态类，包含const的各类事件id，或者消息id和消息内容的映射表，便于后续修改和维护之类的，别的新功能有类似需求也可以添加相应的文件

代码规范：
需要在服务器和客户端之间来回传输的内容，如果只是特定方向的传输的，例如只是服务器传输到客户端，类名（或结构体名）和文件名要加上SC开头，客户端向服务器则为CS
一个类中，如果有一些函数是必要但影响可读性的，例如局部计算处理数据的函数，不被外部引用，只看函数名不看具体实现不影响理解代码的，统一放在类(或结构体)最后并用"#region//Local"包裹
必须及时暴露非预期内容为error，例如enum可能为0、1、2、3，严禁先判断是否是1、2、3并_=>Handle(0)//其它：0，必须处理每个预期的值并在遇到非预期内的值时throw error或logerror
- 单个 RPC 包体不得超过 Ens 临时缓冲上限（256B）。根因：所有 RPC 先经 `EnsTemporaryBuffer` 序列化，可变长集合塞进单个消息会写满缓冲产生残缺包、触发越界崩溃；结论：列表/数组不进单个 RPC。规范：① 拆为每元素独立包（自包含、无 count、无片段号），天然远小于上限；② 优先直接处理单包、由客户端增量应用，而非分片编号+客户端拼回（丢包时也能正常运作）；③ 与单条数据无关的公共状态不要塞进每一条最小单位的数据包，可另行用基本类型参数新增 RPC 传输，减少网络类定义；④ 设计单元素包时估算字节确保远小于 256B 并留余量。一帧同步一批同类数据（点位/列表/buff 等）皆适用，可靠性优先于带宽微优化。
- `Assets/ENS-Netcode` 为外部依赖，**严禁修改其源码**（改动无意义且会被覆盖）；需绕开其限制时只在项目侧解决。

【注释规范】禁止在代码中写大段注释，注释必须言语简短、简洁说明：
只解释"为什么"，不复述代码"做了什么"（代码本身已经表达）
不写变更历史、不写已废弃方案的对比、不写"曾经如何/现在改为如何"
长篇设计说明、机制原理、协议约定一律写进《代码架构说明》等文档，不占用代码
禁止把废弃代码以注释形式留在原地，直接删除

GameController文件夹：
各类管理器，全部跟随场景加载初始化，服务器与客户端场景都挂。资源管理器按端分：服务器挂 `AssetsManager`（直接引用）、客户端挂 `ResourceManager`（Addressables）
其中的Utils子文件夹，内容为需要依赖特定管理器的常用工具或者是对管理器的再次封装
其中的Sub子文件夹，放「客户端逻辑管理器」（ClientLogicManager）的子管理器

ClientLogicManager（客户端总控）：
服务器摘要进入客户端后统一由它分发给各子管理器。它本身只做四件事——Awake 建全部子管理器并逐个 Init、Update 统一 Tick、OnDestroy 统一 Dispose——不含具体业务
子管理器是**普通 C# 类**（继承 ClientSubManager，不挂场景、不进 Tool），用 Tool.ClientLogicManager.<属性> 取用，名字与类名刻意不同以避免与类型名冲突：
- EntityPlayers（EntityPlayerManager）：表现视图的创建/更新/移除、位姿与动画同步、持续 Buff 特效、迷雾表现、超时兜底移除。对外提供 TryGetEntityPosition / TryGetEntityTransform / TryGetAnchorPos(id, EntityAnchor, out pos)（通用锚点查询：按 EntityAnchor 取世界位置——名牌血条走 Bar、战斗飘字兜底走 LabelFallBack；须骨骼的锚点在非人形视图上会抛异常，调用方自选；轨迹按实体 id 取位走这里，服务器侧仍走实体容器）（弹道起点不走镜像接口：技能用自己的锚点常量在两端各自算，规则见《03-技能与Buff总表》三章）。本地玩家相机跟随用动态锚点 cameraAnchor（位置 = EntityAnchor.Camera 注视点、旋转取实体根，每帧由视图刷新），视图销毁时清理锚点；**观战跟随用 `GetOrCreateCameraAnchor(实体id)`**（目标视图没有锚点时按本地玩家同规则补建，建后由视图逐帧刷新接管；视图不存在返回 null）。**玩家→实体关系由 `SCPlayerEntity` 包维护**（名牌反查在 BattlePage 的 entityOwners，本类只管实体表现）
- Settlement（SettlementManager）：终局判定与结算数据组装（分数 / 击杀 / 守护点剩余血量）。**没有局外养成，结算不再写任何存档数值**；同时广播 ClientEvent.OnBattleEnd 与 ClientEvent.OnSettlementResult
- Save（`SaveManager`，挂场景的 MonoBehaviour，不属于 ClientLogicManager 的子管理器）：PlayerPrefs 键 `GameSaveDataV3`，串顺序为 `playerLevel | playerExp | 角色数 | 等级×N | 经验×N | 解锁×N | 玩家名 | 令牌 | 攻方选中下标 | 守方选中下标`（N = `CharacterTotalCount` = 12）。**解析严格、不兼容旧格式**：字段数 ≠ 3+3N+4、角色数 ≠ N、令牌越界、玩家名为空，任一命中即判无效存档并重建。**只有两处落盘**：建档/清档（`CreateNewSave`）与进程退出（`OnApplicationQuit`）；选中下标在载入时写进 `ClientSelection`，越界（配表改过角色数）退回 0
- Loading（ClientLoadingManager）：加载阶段流程（切加载界面 → 串行请求进攻方/防守方/AI 单位表 → 回执完成 → 收 `SCBattleStart` 切页）；**战斗期唯一的玩家名字与玩家↔实体来源**（`GetName` / `GetCombatants` / `HasSession` / `Camp` / `OwnEntityId` / `CharacterType`），观战候选列表也从这里取，禁止再读组队期缓存
- SkillVfx（ClientSkillManager）：客户端技能表现的唯一入口（PlayWave 由它调用，后续预测也在此扩展）
- BattleTime（ClientBattleTimeManager）：昼夜快照转交 EnvironmentManager；本机推演对局剩余时间；缓存权威分数快照
- HomePreview（HomePreviewManager）：**首页与组队大厅**的场景与角色展示。**两页的场景本身是 `Assets/Files/Arranger` 下的 Arranger 预制体**（`HomeArranger` / `LobbyArranger`，含布景、机位与锚点，脚本 `Display/HomeDisplayArranger` / `LobbyDisplayArranger`）：进页面时按 ResourceManager 的 `HomeDisplayArranger` / `LobbyDisplayArranger`（进游戏时已预加载）取模板复制一份，**两页互斥**——复制其中一个就销毁另一个，`BattlePage.Enter` 调 Hide 把两份场景与所有角色一起销毁。首页只摆当前选中的攻/守各一个（AttackerAnchor / DefenserAnchor），大厅按真人成员所选角色依次占 6/2 个锚点（与 `player_limit_attacker/defenser` 一致），机位取各自的 CameraPos。**角色模型复制后按战斗客户端同口径初始化动画**：`EntityAnim.Init(null)`（无 EntityData，攻击帧回调不传）+ `SetType(EntityAnimData.type)`。首页选角时相机留在 CameraPos、原地转向该阵营角色的胸口锚点（`EntityAnchor.UpCenter` → Chest 骨骼），退出选角回默认机位（`ResetHomeView`，同时清掉跟随点防战斗遗留的目标拽相机）

客户端数据流：NetworkManager 收到 SC 消息后，**表现类调用转给对应子管理器**，其余（战斗事件 `SCBattleEvent`＝事件列表唯一来源：type（事件语义唯一判别，icon 档位与条目版式由客户端按类型映射，FGUI 表现不进协议）+ 数字化文本 id——<10000 查 NoticeMessageMap、≥10000 映射为玩家名（clientId = id − 10000））；提示 `SCPrompt`（NoticeMessageMap 消息 id，当前用于开局校验 17/28/29 与技能失败 30/31/32）；战斗飘字 `SCCombatLabel`（数值 + 伤害类型 + 命中位置，按可见性定向、不可靠通道）；小地图/复活进度/房间状态）**仍走 EventManager 事件**，UI（FGUI 页面逻辑类 HomePage/LobbyPage/BattlePage，见 UI 文件夹节）照旧订阅 ClientEvent，不因这层介入而改动。事件飘字与战斗飘字的颜色一律由 FGUI 预设样式决定，代码不改色

Utils/MonoUtils/Timer.cs：
**全项目延时调用/过渡动画的唯一入口**（周期轮询用 Ticker，见下），由 Tool.Update 每帧驱动——Tool 在服务器与客户端场景都有，所以两端都能用。**禁止使用 FGUI 自带的定时器/延时调度**（GTween.DelayedCall、FTimer 等），一律走 Timer。
- `Timer.AddTimer<T>(T value, Action<T> act, float invokeInterval, int invokeTime, bool invokeInstantly)`：延时 invokeInterval 后执行 act(value)，共执行 invokeTime 次；`invokeInstantly = true` 表示**下一帧就执行第一次**（不是同步立即执行），false 表示第一次也要等满 invokeInterval。`invokeTime <= 0` 或 `act == null` 直接忽略
- `Timer.AddTransition<T>(T value, float duration, Action<T, float> onTick)`：过渡任务，持续 duration 秒，**每帧**调用 onTick(value, t01)，t01 = 归一化时间（0~1，最后一帧保证传 1），适合制作过渡动画；返回 `Timer.TransitionHandle`，可随时 `Cancel()` 取消（自然结束后再 Cancel 无副作用）
- 回调异常由 Timer 内部捕获并记日志，**不会中断同帧其它定时器**，也不会卡住自身（次数照常递减）
- `AddTimer` 返回 `TimerHandle`、`AddTransition` 返回 `TransitionHandle`，都能 `Cancel()`：置取消标记，**下一帧 Update 时移除**，之后不再触发；句柄丢掉就只能等次数跑完（过渡任务跑满 duration）
- 触发时刻按帧累减，实际间隔比 invokeInterval **略早（每周期约少 1 帧）**，不要拿它当精确计时基准（需要精确计时的地方用绝对时间戳比较）

Utils/SimpleUtils/Ticker.cs：
周期轮询用的轻量计时器，`if (ticker)` 为 true 表示又满了一个 interval（等价于显式 `ticker.Tick()`）。BattleManager 的节流同步、昼夜心跳、鲛人/珊瑚刷新尝试、掉落回收检查都走它。
- `new Ticker(interval)` 首帧即触发，之后每 interval 秒一次
- `new Ticker(interval, random: true)` 起始相位取 [0, interval) 内的随机值，用于把多个周期任务打散、避免同帧集中触发；该写法的第一次触发不保证在首帧
- `Reset()` 立即重开计时（下一次取值要等满一个 interval）；interval 在构造时固化，要换间隔须重建
- **掉帧欠账不丢弃**：触发后只往后推一个 interval，落后多少就在随后几帧连续返回 true 补齐——需要"掉帧也不许连发"的场合不要用它
- 间隔 ≤ 0.0001 直接抛异常（配表填错要立刻暴露，不静默兜底）

Transport文件夹：
每个文件都对应一个要在服务器和客户端之间来回传输的数据结构（class/struct都可以）
完成开发后按照EnsNetcode插件要求为其中每个数据结构在其文件内编写一个序列化器

**位级传输（`EnsInstance.enableBitTransform`，默认 true）**
每个序列化器都有两条路径：位级（开关为 true）与字节级（false）。原字节级实现原样保留在私有 `SerializeBytes` / `DeserializeBytes` 里，两条路径的字节流互不兼容，**收发两端的开关值必须一致**。
位级基于 `Assets/ENS-Netcode/Netcode/Common/BitField.cs`：把值按 `[min,max]` 映射成下标后按位写入，浮点按 `step` 量化；缓冲由调用方用 `SetBuffer` 提供、`Flush` 收尾并返回占用字节数。单个参数的位宽见各序列化器里的 `// 位级：...` 注释；每次 `Flush` 会补齐到字节边界，所以**位对齐不跨参数累积**（一个 RPC 的多个参数各自占整字节）。
`UNITY_EDITOR` 下 `BitField` 会校验写入值是否落在 `[min,max]`、`min<=max`、`step>0`，违规直接抛异常；发布构建无此校验，范围由调用方保证。反序列化用 `invalidIndex` 校验剩余长度，数据截断时抛异常。

**不支持位级的协议**（含 `string`，仍走字节级）：`CSChat`、`CSLobbyPlayerInfo`、`LoadingUnitEntry`、`SCChat`、`SCLobbyPlayerName`，以及三个 `SCLoading*Response`（装 `List<LoadingUnitEntry>`）。

**位级压缩实测（字节级 → 位级）**：`SCEntityDisplayInfo` 90→27、`SCLobbyInfo` 42→9、`SCEntityAnimInfo` 35→11、`SCCampAliveCount` 21→5、`SCLoadingStart` 5→1、`SCCombatLabel` 26/14→11/5、`SCMinimapEntity` 24→8、`CSGm` 25→21。无载荷协议（`SCBattleStart` 等）只有 null 标记 1 位，补齐后仍是 1 字节，无收益。

网络行为脚本，继承自EnsBehaviour
本项目唯一的进行服务器、客户端调用的位置

**投递语义（Delivery / SendTo 选择现状）**：
- `Delivery.Strive` = ENS 的「尽力可靠」通道：同一条消息按固定次数重发（默认 3 次、间隔 0.01s）、不等待回应，接收方按序号忽略重复包——介于 Reliable 与 Unreliable 之间的低延迟折中（语义以库 `Netcode/utils/KeyLibrary.cs` 为准）。使用范围：玩家操作上行（CSMove / CSMoveStop / CSJump / CSSlide / CSSkillCast）、实体动画摘要（SCEntityAnimInfo）、**含 buff 信息或完整同步的实体表现包（SCEntityDisplayInfo，纯位姿包走 Unreliable）**、战斗事件、昼夜快照、技能施放下发
- **Reliable 保留给**：连接与房间流程（进出房、玩家信息、开局请求、小地图半径切换）、BattleInfo、实体增删（ClientRemoveEntity）、**玩家→实体关系（SCPlayerEntity）**、Prompt、分数、复活进度；**Unreliable**：小地图点位（按间隔持续重发、丢一条无所谓）、战斗飘字（纯表现）与纯位姿的实体表现包（0.02s 一个，丢了等下一个）
- 服务器→客户端的**广播类**消息（战斗事件 / 战斗飘字 / 房间信息 / 昼夜快照 / 技能施放 / SCPlayerEntity）用 `SendTo.ExcludeSender`：广播不回送发送方（服务器）自己；定向单发仍 `SendTo.To(clientId)`

**组队期协议（仅组队大厅；战斗期一律不读）**：
- `SCLobbyInfo`：真人成员（`clientId` / `camp` / `characterIndex` / `ready`）+ 双方 AI 数量 + `battleStarted`。**AI 不进成员列表**，只用两个数量表达。
- `CSLobbyUpdate`：选队 / 准备 / AI 数量上行。`CSLobbyPlayerInfo`：进房上报角色与等级、名字。
- `SCLobbyPlayerName`：名字单独下发（新玩家名字广播给所有人 + 逐个补发给新玩家），避免成员包被长名字撑大。
- 客户端缓存：`NetworkManager.LatestLobbyInfo` / `lobbyPlayerNames`；`LatestLobbyInfo` 内含准备状态与阵营，只供大厅界面使用。

**加载阶段（开战前，取代原来的"倒计时结束直接开战"）**：
- 服务器 `BeginLoading`：兜底清残留实体（正常情况下 `EndBattle` 已清空）→ 重置实体 id 源（本局唯一一次）→ 给每个真人发 `SCLoadingStart{camp}`（客户端切加载界面）→ **为参战真人与 AI 预分配实体 id（只登记不生成：提前生成会让实体动画在加载期就开始播）** → 发 `SCLoadingPrepared{ownEntityId, characterType, serverTime}`。
- 客户端 `ClientLoadingManager`（`ClientLogicManager` 子管理器）串行请求，上一步回包后才发下一步：`CSLoadingAttackPlayerRequest` → `CSLoadingDefensePlayerRequest` → `CSLoadingAiUnitRequest`，各自对应 `SCLoading*Response`；列表项统一为 `LoadingUnitEntry{clientId, entityId, name, camp}`（AI 用虚拟负数 clientId，保留以便观战跟随）。三步收齐后还要等 `ResourceManager.LoadBattleNecessary` 把鲛人/雕像/珊瑚预加载完，才发 `CSLoadingComplete`。第一步开始前有一道地形门：`SCLoadingPrepared` 与「素材表加载完、地形生成完」两件事都到齐才发第一个请求（顺序不定，两边各到一次就放行）
- 服务器收齐**攻守真人**的完成包后 `StartBattle`（用预留 id 生成实体与世界），只对已完成的客户端发 `SCBattleStart`；观战方不阻塞开战，晚完成时补发「开始战斗」，表现数据靠首见全量补齐。
- 表现同步与小地图同步只发给「已加载完成」的客户端：未完成者可见集合为空，完成后第一轮自然全量。
- 观战方在加载期 `ownEntityId = 0`；玩家复活换新实体 id 时客户端以 `SCPlayerEntity` 为准更新自己的实体 id。
- 对局结束 `EndBattle` **立即销毁全部实体**（先置 `BattleStarted=false` 再销毁，避免误发守护雕像/水晶雕像摧毁事件），结算展示由客户端自己维持；客户端会话数据（camp / 实体 id / 角色）全部由加载期两条包填充。


**实体表现同步（`SCEntityDisplayInfo` + `SCPlayerEntity`，2026-10-18 位姿脏标记后）**：
- **四脏标记（`EntityData`）**：`transformDirty`（每帧 `CheckTransformDirty` 与「上次下发位姿」比，位置差 > `entity_sync_pos_epsilon`(0.1m) 或朝向差 > `entity_sync_yaw_epsilon`(3°) 置位；基准在清脏时对齐当前，所以误差恒定为阈值量级）/ `healthDirty`（仅生命值实际变化时置位，上限不变不参与）/ `buffDirty`（EffectController 增删 Buff 时置位）/ `skillDirty`（持有技能列表变化时置位——**使用技能、冷却推进不置脏**）。`GetDisplayInfo(includeRuntime, withSkills)` 按脏标记条件携带：`hasTransform` → position/yaw/velocity/yawSpeed（**条件序列化，位于包尾**）、`hasHealth` → health/maxHealth、`hasBuffs` → buffs（同类型多层聚合成一条，`level` = 各层等级之和，按协议 4bit 截断在 15）、`hasSkills` → skills（**仅持有技能 id 列表**，无冷却/库存字段；**只发给该实体所属客户端**，别人的技能栏没人消费）；**完整同步（0.2s 详细包）或该实体对某客户端首次可见时必带全量**（不依赖脏标记）
- **清位规则**：每轮同步后对「本轮至少被一个客户端可见」的实体清脏（标记是实体级的）；无人可见期间保留脏标记，等下次可见随完整同步下发
- **包内容**：0.02s 快包 = 仅按脏标记携带的段，**四段全无变化就整包不发**（跳过时仍要 `MarkClientVisible`，否则会被判成离屏而回 remove 包）；**动画包 `SCEntityAnimInfo` 独立发送，不受该跳过影响**（否则 `AnimSyncDirty` 会在轮末被清掉、这次状态变化永久丢失）；0.2s 完整包 = 全量（兼作静止实体的心跳，保证客户端 3s 超时不会误删静止单位）。**玩家操控关系不随包下发**——"哪个玩家操控哪个实体"走独立协议 **`SCPlayerEntity`**（每玩家一条：`clientId + entityId`，**-1 = 无实体**（死亡/观战方/退场清理）；开局出生循环全量下发、复活重建与死亡销毁（`DestroyEntity` 统一入口）增量下发；客户端维护 玩家→实体 与 实体→玩家 双字典，名牌反查与观战绑定都走它）
- **客户端消费门闸**：位姿/速度应用 = `hasTransform`（无位姿的包不能拿默认值覆盖，否则会把实体瞬移回原点）；UI/逻辑层事件（`OnEntityDisplayUpdate`）= `includeRuntime || hasHealth || hasBuffs`；Buff 特效/迷雾 = `includeRuntime || hasBuffs`；持有技能 = `includeRuntime || hasSkills`（只对本地实体，转交 `ClientSkillManager.SetHeldSkills` 维护持有表；槽位与冷却另走 `SCSkillRecharge`）
- **技能冷却与库存完全由服务器判定**：状态记在实体的 `EntitySkillController`（`SkillRecharge`，形态是每技能 cd 根时间戳），服务器校验冷却/库存后才释放（见 Entity 节「技能释放校验」），并回推一次 `SCSkillRecharge`（槽位技能 id 列表 + 根戳列表）。客户端 `ClientSkillManager` 只持有服务器下发的持有表与这份快照，读数按 `(服务器时间 − 根戳) / CD` 现算，**本地不 Tick、不扣次数、不做每帧同步**
- **服务器时间同步**：基准在**加载期一次性下发**——`SCLoadingPrepared.serverTime`（发包时刻的服务器时间），客户端 `NetworkManager.SyncServerTime` 补上单程延迟（`EnsInstance.LocalClientDelay/1000`）后算出「服务器时间 − 本地时间」偏移，`ClientToServerTime` / `ServerToClientTime` 负责双向换算

GameController/InfoManager.cs:
持有服务器实体模板引用与层掩码配置（entity_layer / ground_layer），均为 Inspector 内联字段；数值类配置（属性/技能/Buff 等）不在此处，统一由 ConfigManager 读配表

Config/ConfigManager.cs（配表系统）：
配表的唯一入口。源表是 `Config/Source/` 下的 xlsx，由 `Config/configtool.py` 生成两份产物：`Assets/Scripts/Config/Generated/*.cs`（结构体 + 加载代码）与 `Assets/Resources/Config/*.bytes`（二进制数据）。
- **源表格式**：一个文件一张表，表名 = 文件名；固定 4 行表头——1 中文名（A1 是表中文名）、2 变量名、3 变量类型、4 说明；第 5 行起是数据，A 列为主键。主键模式看 A5 能否解析成整数：能则 int 键，不能则该列所有值生成 `{表}Enum` 枚举当键。类型支持 `int / long / float / double / bool / string`、`List<T>`（`;` 与 `|` 等价分隔，留空 = 空列表）、`Vector2/3/4` + `Int/Float`（见 `ConfigStruct.cs`，按分量直读、不分配 List）、项目里已有的枚举名（支持 `A.B` 嵌套写法）；类型以 `?` 结尾表示该列可留空。
- **生成与校验**：`configtool.py` 在生成期做全量校验——缺表头、空格子、主键重复、数值类型不符、Vector 分量数不符、类型格误填成同表变量名，任一命中就整体不写文件。**加表只需往 `Config/Source/` 放一个 xlsx 后重跑脚本，不需要改代码**。
- **加载**：`ConfigManager` 是挂场景的 MonoBehaviour，`Awake` 里注册到 `Tool` 并 `Init()`：一次性把全部表读进内存，再烘培各表包装层的映射。运行期没有懒加载、没有文件 IO；编辑器工具走 `ConfigManager.EnsureLoaded()`（非播放态 Awake 不跑）。
- **包装层**：每张表一个静态类（`EntityConfig` / `SkillConfig` / `EffectConfig` / `GlobalVariable` / `TerrainGeneration` 等，见 `Config/TableConfigs.cs`、`Config/EnumKeyConfigs.cs`），对外只给查询与预先算好的派生数据：`entity` 的复合键字典（`EntityType → entity`）、技能品质序与 Buff 三元组解析、卡牌幸运区间、复活/愈战层数钳位。`GlobalVariable` / `TerrainGeneration` 一律按生成的枚举读（`GlobalVariable.F / I / L`、`RangeMin / RangeMax / RangeLength`），**不为每个键生成静态字段**——配表加行同样不用改代码。
- **红线**：生成的 `{表}Data` 字典是公开的，`ConfigManager` 与包装层在初始化后只读；外部**严禁修改**这些字典，增删改都会让烘培好的映射与字典脱节。

Entity/Attribute 文件夹（属性聚合）：
实际属性不再是"一份可覆盖的结构体"，而是「基础 + 词条 + Buff」按需求和出来的，查询入口统一是 `EntityData.attributes`（RuntimeEntityAttributes）。
- **RuntimeEntityAttributes**：构造传 `EntityData` + `EntityType`，基础值直接持有 `entity` 结构体（不存属性副本）；对外给 `Attack / CritRate / CritDamage / ViewDistance / MaxHealth / WeaponSlotCount / Health` 等 getter，按需现算
- 当前生命由它持有（`Health / MaxHealth`），对外只开 `ApplyDamage / Heal / Kill`；`Update()` 每帧只做一件事——重算生命上限，变化时**按比例换算当前生命**并置 `owner.healthDirty`（服务器当帧就把新的 maxHealth 一起发下去）
- `EntityAttribute` 退化成"基础属性容器"；Buff 增量由 `EntityEffectController` 用四个字段（`BuffAttack / BuffCritRate / BuffCritDamage / BuffViewDistance`）持有，`RecomputeAttributes` 只重算这份增量，不再全量重算属性
- **CardBonus**：一名玩家的词条聚合（幸运 / 生命% / 攻击 / 暴击 / 各类增伤 / 塔攻击 / 守护点减伤 / 一次性回复），百分比存小数、基准是基础属性；`CardType` 常量与 `card_option 表` 的「类型」列同名
- **出伤不存属性**：命中瞬间按攻击者与目标现算（`AttackData.GetDamage(target)`），等级压制、对玩家/鲛人/珊瑚/建筑增伤、斗士、反击都在 `BattleManager.GetOutgoingDamageMultiplier` 里一次算完；DoT 用 `DamageStat` 值类型快照（不分配）

GameController/Utils/VfxManager.cs:

GameController/EnvironmentManager.cs:

GameController/CameraController.cs（相机跟随与取景，纯客户端表现；三种模式 `CameraViewMode` = 第三人称 / 俯视 / 自由）：
跟随目标 = EntityPlayerManager 的动态锚点 cameraAnchor（位置 = EntityAnchor.Camera 注视点、旋转 = 实体根）。**绑定/换绑**（进战斗、复活换绑）时直接瞬移到**平滑目标位置**——水平后距取 `zRange` 中点、高度取 `yRange` 中点（即下面双轴平滑的稳态值），不做平滑；**俯仰在同一次调用里更新一次目标**（勾选自动俯仰角时先 `UpdateAutoPitch` 刷 `pitchTarget`、再 `TickPitch` 写一次旋转），此后由每帧 `TickPitch` 按 `pitchSmooth` 继续缓动收敛。**摆位与俯仰都必须落在平滑/目标值上**：若摆到别的距离或留着旧俯仰，下一帧就会被平滑拉走，表现为每次绑定/复活时相机抖一下。⚠ 调用方契约：绑定前必须让视体**真正就位**再取锚点。视体位姿由 `Rigidbody.MovePosition` 施加，**要到下一个物理步才生效**，所以 `EntityPlayerManager` 在 `if (view.cameraAnchor == null)` 里先用权威位姿直接写一次 `view.transform.position/rotation = info.position / info.yaw`（仅建视体这一次，之后仍由 MovePosition 驱动、不破坏碰撞解析），再取 `EntityAnchor.Camera` 锚点并调 `SetLookTarget`。否则锚点落在"假位置"上：水平位移下一帧就被 `LateUpdate` 重建位置补齐，但**高度只靠弹性平滑回归**（重建后的高度仍取自平滑值），表现为进游戏/复活后相机长时间停在角色下方仰视。**每帧 LateUpdate**：
- 偏航不平滑：相机 yaw 恒等于镜头自身的 `camYaw`（**只由鼠标水平滑动驱动，与角色朝向无关**；绑定新角色时 `camYaw` 重置为角色朝向）
- 先量当前水平后距（`toCam` 的水平分量长度）与高度，再按平滑结果重建位置——量距不受行进位移污染，避免边走边漂
- 横向对齐：相机相对锚点的横移量（投影到镜头自身 `right`）按 `xSmooth`(2) 回正到 0
- 水平后距 `zRange`(3~8) 与高度 `yRange`(1~3) **双轴弹性平滑**：区间内用 `slowSmooth`(2)、越出 `smoothDistance`(1.5) 缓冲带用 `fastSmooth`(10)，带内线性插值避免速率阶跃震颤
- 俯仰 `TickPitch`：`pitchTarget` 是**绝对俯仰角**（度，面向锚点下方为正、0 = 水平），每帧 `Quaternion.Lerp` 以 `1-Exp(-pitchSmooth·dt)` 向 `Quaternion.Euler(pitchTarget, camYaw, 0)` 收敛，roll 恒为 0。口径由设置里的**自动俯仰角**决定：勾选时保持期内 `pitchTarget` 取 `SetPitch(pitch, duration)` 的值、`pitchHoldTime` 到期后自动回正为「正看锚点」= `-Atan(垂直差 / 水平距离)·Rad2Deg`，并在写旋转前钳制到 `pitchClamp` ±45°；取消勾选时 `pitchTarget` 只由鼠标纵向滑动累加（`mouse_pitch_sensitivity` 度/像素），同样钳在 `pitchClamp` 内，**不回正**
- **自动取景**（`UpdateAutoPitch`，仅在勾选自动俯仰角时每 `autoFrameInterval`(0.2s) 跑一轮）：遍历客户端可见实体（`EntityPlayerManager.AllViews`；`autoPitchIgnoreSelf`=true 时跳过本地玩家角色、只对敌我其它单位取景），只取**镜头前方**且落在「水平视场中间 80%」的实体，把其模型上下边界对应的俯仰角约束进视野；视场装不下时俯仰取上下限平均，越界时经 `SetPitch` 传入**世界俯仰角**（与 `pitchTarget` 同口径，不是相对锚点的增量）按周期续期修正，未越界不刷新、由保持时间自然回正
- LateUpdate 改完变换后手动刷新 `worldToCameraMatrix`（Unity 渲染时才重算，否则同帧 WorldToScreenPoint 用上一帧矩阵，血条/飘字差一帧震颤），随后广播 `OnCameraUpdated` 事件

**鼠标转视角（`TickMouseLook`）**：只在第三人称生效，俯视下鼠标滑动完全忽略；GM 面板/文字输入期间不接管。用 `Input.mousePosition` 的逐帧差值换算（`GlobalConfig.mouse_yaw_sensitivity` / `mouse_pitch_sensitivity`，度/像素），切模式或被打断后先丢一帧，避免跨帧差值把镜头甩出去。

**俯视模式（`CameraViewMode.TopDown`）**：位置指数平滑追「跟随点 + `topDownOffset`」（速率 `topDownSmooth`），朝向 `LookAt` 跟随点但**偏航恒为 0**，只保留由偏移推出的俯角（`pitchSmooth` 收敛）；俯视下**鼠标滑动不参与任何方向计算**，也不跑自动取景。跟随点仍是 `cameraAnchor`（锚在 Hips 上），所以跳跃/受击时相机随角色上下起伏 —— 这是预期表现。
**自由视角（`CameraViewMode.Free`，仅纯观战）**：脱开跟随点自行积分；键位固定 WASD 水平平移（沿当前 yaw）/ K 升 J 降 / Q E 左右转 / Y H 抬头低头，`freeMoveSpeed` / `freeVerticalSpeed` / `freeTurnSpeed` / `freePitchSpeed` / `freePitchClamp` 全部在 Inspector。相机位置经 `CSFreeCamera` 上报（每 1s / 水平位移 ≥1m），服务器按上报位置下发该玩家周围的实体与小地图点位。
**模式切换（C 键 = `GlobalConfig.camera_mode_key`）**：非观战与死亡观战 = 第三人称 ⇄ 俯视；纯观战 = 第三人称 ⇄ 俯视，且**任意非自由状态按 W 进自由视角**，自由视角只能按 C 回第三人称（死亡观战不允许进自由视角）。第三人称 ⇄ 俯视由各自 Tick 平滑过渡、不瞬移；**自由视角回第三人称是瞬移**（`SnapToThirdPerson`），否则会横穿整张地图。
**设置开关（`ClientSettings`）**：`ThirdPersonCamera` = 勾选第三人称 / 取消俯视，`AutoPitch` = 勾选时俯仰交给自动取景、鼠标不控俯仰。**C 键切换会写回同一个开关**，`BattlePage.SyncSettingToggles` 每帧把勾选态跟过去，两边永远一致；两个开关默认都不勾选（进局 = 俯视 + 鼠标控俯仰），跨局保留、不进存档。
**会话规则**：`ClientLoadingManager.HasSession` 变为 true 时按 `ClientSettings.ThirdPersonCamera` 重建模式（俯视/第三人称）；相机模式不再上行服务器（移动方向已由 CSMove 的 yaw 表达）。`SetLookTarget(target, snap)` 的 `snap=false` 供观战在自由视角下只更新目标引用、不摆位；`snap=true` 时第三人称会把 `camYaw` 重置为角色朝向再瞬移。

GameController/BattleManagerVision.cs（视野锚点 / 实体可见性 / 小地图同步）：
**视野锚点（`visionStates`，键 = 玩家 clientId）**：值 = `VisionState`（当前操控实体 id / 判定位置 / 视野半径 / 是否在观战 / 观战目标 / 观战我的玩家列表 / 自由视角标志与相机 XZ）。`TickVisionStates` 每帧刷新：**纯观战处于自由视角 → 用客户端上报的相机 XZ 当锚点**（`freeLook`，半径沿用最后跟随实体的 `viewDistance`）；存活未观战 → 跟随自己实体；观战中 → 跟随目标实体；**无实体可跟随（死亡）→ 不刷新，冻结在死亡那一刻的位置/半径**。客户端切回跟随时发 `free=false`（`SpectateRequest` 同样清 `freeLook`），锚点回到实体。**全部可见性判定统一走锚点**：实体表现同步（`SyncEntitiesToClients`，按锚点位置+半径圆判、无朝向/遮挡）、战斗飘字（`SendCombatLabelToViewers`）、阵营视野源与小地图敌方点位过滤——死亡玩家以冻结位置继续为阵营提供视野并继续收到周围实体的表现数据（观感 = 动不了但看得到）；目标实体销毁的逐帧检测立即清空其观战列表（跟随中的操控方与观战方自然冻结在原地，自由视角观战方继续按上报的相机位置）。**观战**：协议 `CSSpectate`（客户端 `RequestSpectate(目标玩家clientId)`，非法/死亡/异阵营目标一律当作退出）；规则 = 观战方玩家可观战任意存活玩家、攻/守玩家仅同阵营（死亡临时观战不换阵营）；目标死亡逐帧清列表、观战者复活（`RespawnPlayer`）/退场（`RemovePlayer`）自动退出并从目标列表摘除。客户端接线（`BattlePage`）：纯观战（无实体进战斗）自动随机观战一名攻/守成员、目标死亡自动重选；死亡观战下拉（`m_onlookComboBox`，只列攻/守成员）手动选目标；相机跟随 = `EntityPlayerManager.GetOrCreateCameraAnchor(目标实体id)`（取/建目标视图相机锚点，与本地玩家同规则；自由视角下只更新锚点引用、调 `SetLookTarget(..., snap:false)` 不摆位）；`m_onlook=1` 由 FGUI gear 隐藏血条/技能栏等非观战元素。
**小地图同步**：服务器每 `GlobalConfig.minimap_sync_interval` 给每个客户端逐个发送阵营共享视野内各实体的独立包（`SCMinimapEntity`：单实体、无片段号、无批次/失效标志位）；夜间·致盲（`IsCampMinimapLost`）时**只下发本阵营成员的点位，敌方单位一律不进列表**（`BuildCampMinimapEntries` 的 `includeEnemies` = false，本阵营不按视野过滤、照常全量）。**阵营视野判定与下发过滤的圆心都用视野锚点位置**（观战跟随/死亡冻结/自由视角的相机位置同样生效；观战方玩家不贡献阵营视野源，其点位跟随观战目标所在阵营的共享视野，未在观战中时不发）；下发过滤的**半径**用该客户端的雷达显示半径（F 键循环 `GlobalConfig.minimap_view_radii` 100/200/300，服务器记录每客户端半径并回应 `SCMinimapRadius`；同阵营点位不过滤；纯显示裁剪，非视野判定）。客户端 `BattlePage` 分帧累积，按实体记录最后收到时间，超 `GlobalConfig.minimap_entity_timeout` 即隐藏该点位——覆盖「敌方停传」这类幽灵点，不再每帧清空。显示为**雷达式**：本地玩家图标固定在 mapBase 正中心并随自身 yaw 旋转（`EntityPlayerManager.TryGetEntityTransform` 每帧读推演朝向），上方=世界Z+、右侧=世界X+，**当前雷达显示半径**铺满 mapBase，其它点按相对本地玩家的偏移绘制、超出半径即隐藏；自身图标每次点位更新后置顶，不被遮挡。**雷达圆心由 `BattlePage.TryGetMinimapCenter` 决定**：有本地实体 = 该实体位置；纯观战无本地实体 = 观战目标实体位置；**自由视角 = 相机自身位置**（相机已脱开跟随点，圆心不跟相机就会让服务器按相机下发的点位按旧圆心换算、越飞越漂出雷达；地形底图对位同源）

TerrainGenerator/Runtime 下的 TerrainSpawns 片段：
地图信息与地形点位

**地图范围不设常量类**：区块尺寸、每边块数、地图起点与边长一律在调用点直接读 `global_variables`（`terrain_chunk_size` / `terrain_chunk_size_count` / `terrain_size` 的「最小;最大」，当前 24m / 16 块 / 0~384m），`ChunkSearcher` 划分区块、`TerrainPropCuller` 摆放区块节点、UI 小地图与上帝视角换算都按配表现算，代码里不写死；改地图范围只改配表。**可移动实体的区块索引每帧同步**（`BattleManagerCombat.TickMovement` 里对 `Entities` 同步）—— 范围索敌（GetNearestEnemy / GetNearestInCamp）只查区块桶，不更新就会一直按出生区块找人。**`GuardStatues` / `Corals` / `CrystalStatues` 三桶装的是静止实体，只在增删时定位，不逐帧同步**（新增会移动的实体类别时必须补上它所在桶的同步）。`ChunkSearcher` 内部用 `_chunkOf` 记录每个物体当前所在区块（位置会变，定位旧区块不能靠再读一次位置）。**按区块数个数用 `GetChunkCount(Vector2Int)`**（O(1) 查 `_chunkObjects` 的 HashSet.Count，零分配；未命中返回 0，不做越界校验）——珊瑚刷新的区块密度判定就走它，别用 `GetObjectsInChunk` 灌缓冲再数
`TerrainSpawns` 是静态类，承载**全部固定地图点位**，数据来自地形烘焙 bin：主守护点 ×1、副守护点（贤者雕像，下标即 value）、防御塔位（Tower，每个守护点 3 个）、普通点位。普通点位按离主守护点的距离派生：**最近的作防守方出生/复活点、最远的作进攻方出生/复活点、其余作中立雕像刷新点**。`TerrainGenerator.Generate` 读数据后调 `TerrainSpawns.Build(data)`，`ModularTerrainGenerator.Clear()` 调 `Reset()`；点位 Y 取地形可行走面 `ground_height`
**出生点与复活点共用同一个位置**（不做去重）；珊瑚与鲛人出生位置不存点位表：由 `TrySampleSpawnPoint` / `TrySampleSpawnPointInRing` 运行时随机采样，合法性判定为**向下射线**——从 `地形上表面 + terrain_height` 垂直向下，射线打 `InfoManager.ground_layer` 层，未命中即非法，命中高度与地形上表面相差 ≤0.5m 才算合法，落点 Y 用命中高度
地形**不需要**在服务器/客户端各摆一份锚点：两端用同一 seed 与同一份烘焙数据，`TerrainSpawns` 内容天然一致。服务器场景启动时调 `Tool.ModularTerrainGenerator.GenerateServer()` 一次性常驻整张地形、只放有启用碰撞体的类别（`ground_layer` 向下射线与点位要覆盖全图）；客户端在进战斗加载时调 `Generate(回调)` 按主相机位置逐区块取还，离开战斗页 `Clear()` 销毁。客户端的素材表 `BuildingKitSet` 走 ResourceManager 的 `BuildingKit`（AssetReference）异步加载，加载完才生成，故场景里的 `kit` 字段必须留空——直接挂会让地形预制体被重复打包。详见《10-地形生成》

Env文件夹（相机全屏特效，纯客户端表现，不改动任何材质）：

两者共用同一套深度重建口径：`OnPreCull` 每帧补 `cam.depthTextureMode |= DepthTextureMode.Depth`（别的脚本会覆盖该标志，必须每帧补）；脚本每帧用 `cam.projectionMatrix.inverse` + `cam.cameraToWorldMatrix` 算出**四个视锥角方向**（归一到视空间 z = -1）传给 shader，shader 里 `worldPos = _CamPos + lerp(角方向) * LinearEyeDepth(深度)`。视锥角方向按像素 uv 插值，别改成 `unity_CameraToWorld` / `unity_CameraInvProjection` 反投影——本工程相机是 HDR + MSAA 前向，D3D 下渲到中间 RT 会翻转投影，内置矩阵与像素行对不上。

- **顶点与 uv 约定**：两个全屏 pass 都走 `cmd.DrawMesh` 画自建 NDC 四边面（顶点已在 -1~1，直接 `o.pos = float4(v.vertex.xy, 0, 1)`，不进矩阵）；uv 相对屏幕上下镜像，采样深度、插值视锥角方向、屏幕上下渐变都要取 `1 - v`。

Env/Caustics/ScreenSpaceCaustics.cs（全屏焦散投影，挂主相机，shader `Hidden/Caustics/ScreenProjection`）：

- 形态：`CameraEvent.AfterForwardOpaque` 上挂 CommandBuffer 画一张全屏 quad（自建 NDC 四边面），`Blend One One` 纯加色，位置在 Bloom 之前所以高光会被 Bloom 吃到；开销与场景复杂度无关，只与像素数有关（每像素 1 次深度 + 1 次高度图 + 6 次纹理采样）。
- 作用面：法线 `mask = saturate(normal.y + _NormalBias)²`（朝上最亮、立面约 12%、朝下为 0）；法线由屏幕导数重建（`cross(ddy, ddx)`），不含法线贴图，纵深突变处有噪点；重建后强制朝向相机。
- 遮挡：只对 `normal.y > 0.3` 的像素做，读地形工具烘焙的高度图（见《10-地形生成》8.7），判据是**同一 XZ 列上方是否有更高的表面**（光从正上方来），因此只覆盖屋顶下、桥下、悬崖正下方，障碍旁边不投倾斜阴影；`_MapSize` 为 0（未开遮挡/资产缺失/配表无效）时整段跳过。高度图缺失只打 warning 并关闭遮挡，焦散照常显示。
- 网纹：三层 `CausticsMap` 分别按 `Tiling × 1/2/3` 采样、各带独立流速与相位，每层用 `FlowMap.rg` 做 `lerp` 扰动；合成 `Intensity × (w1 + w2) × w3`（前两层相加再乘第三层，压暗整体并让交叉处更锐利）。
- 贴图：`Assets/Files/Shaders/Caustics/T_Caustics.TGA`、`T_CausticFlowMap.TGA`（独立 GUID，不引用素材包）。
- 不生效/不覆盖：相机非 Forward 路径、正交投影（Awake 打 warning 后直接退出）；天空与远平面不铺；透明物体不叠（pass 在透明队列之前）；角色与动态物件不挡焦散（高度图是静态烘焙）；无距离衰减，掠射角下远处地面会压成长条。
- 参数（Inspector）：`causticsMap` / `flowMap` / `projectionShader`（添加组件时 `Reset()` 自动填 shader）、`color`、`intensity`、`tiling`、`layerSpeeds`、`flowIntensity`、`flowScale`、`normalBias`、`useOcclusion`、`occlusionBias`、`occlusionFade`。地图范围取 `global_variables` 的 `terrain_size_min` / `terrain_size`，在 `Start` 读（`ConfigManager` 此时已加载），故组件只在运行时生效。

Env/Fog/ScreenSpaceFog.cs（全屏雾，挂同一台主相机，shader `Hidden/Fog/ScreenFog`）：

- 形态：`CameraEvent.BeforeForwardAlpha` 上挂 CommandBuffer 画一张全屏 quad（自建 NDC 四边面），`Blend SrcAlpha OneMinusSrcAlpha` 按雾浓度把雾色混到画面上；位置在天空盒之后、透明队列之前（雾是背景层，透明物体照常叠在雾上），像素开销 = 1 次深度。
- 两种雾都作用在同一个像素上并按 `1 - (1 - dF) × (1 - hF)` 合成（不是相加，避免叠加超过 1）：
  - 距离雾：`dF = saturate((dist - distanceStart) / (distanceEnd - distanceStart)) × distanceDensity`，`dist` 是像素世界坐标到相机的欧氏距离；
  - 高度雾：`hF = (1 - saturate((worldPos.y - heightLow) / (heightHigh - heightLow))) × heightDensity`，按**表面世界高度**算、不做沿视线积分——所以同一物体下部浓、上部淡；
  - 两者可各自单独关闭（`enableDistanceFog` / `enableHeightFog`）。
- 天空与远平面（`Linear01Depth(rawDepth) ≥ 0.995`）按满浓度取雾色，天空盒被完全覆盖；雾色取组件自己的渐变色，不读 `RenderSettings.fogColor`。
- 雾色按角度取：视线方向的 `viewDir.y`（世界空间俯仰角正弦）与 `uv.y × 2 - 1`（屏幕上下）各自经 `smoothstep(angleCenter ± angleSoftness)` 得到 0~1，用 `screenAngleWeight` 加权合成方向因子，在 `fogColorBottom`（下方深）与 `fogColorTop`（上方浅）之间插值；再按宽高比校正后的屏幕半径 `r`（角点 = 1，取内置 `_ScreenParams`）算 `smoothstep(edgeStart, 1, r) × edgeIntensity`，把雾色混向 `fogColorEdge`，使屏幕边角更暗。天空与远平面同样参与角度取色与边角暗色；场景内像素的雾浓度仍只由距离雾与高度雾决定。
- 与 EnvironmentManager 的关系：`EnvironmentManager` 在 `Awake` 关闭 `RenderSettings.fog`，通过 MainCamera 上的本组件设置 `distanceScale`（`[HideInInspector]`，默认 1），在 1 ↔ `fogDistanceScale` 间按 `fogTransitionDuration` 过渡；`distanceScale` 同时乘到 `distanceStart` 与 `distanceEnd` 上，只改变距离雾的起止距离，不改颜色与高度雾。
- 透明物体：透明队列写不进深度图，也不参与这套屏幕空间雾——雾在透明队列之前就画完了，半透明物体直接叠在雾色背景上（背景是天空时不会被雾色抹掉）；代价是透明物体不按距离上雾，远景半透明特效会比周围亮。`Assets/Scenes/MainScene` 的 Canvas 是 Screen Space - Overlay（`m_RenderMode: 0`），UI 不经过这台相机，不会被雾染色。
- 参数（Inspector）：`enableDistanceFog`、`distanceStart`、`distanceEnd`、`distanceDensity`、`enableHeightFog`、`heightLow`、`heightHigh`、`heightDensity`、`fogColorTop`、`fogColorBottom`、`fogColorEdge`、`angleCenter`、`angleSoftness`、`screenAngleWeight`、`edgeStart`、`edgeIntensity`、`fogShader`（添加组件时 `Reset()` 自动填）。`heightLow` / `heightHigh` 按地图绝对高度配（地形可行走面 4m、最高面约 60m）。

[F]Entity/Anim:
它只是管理动画播放的，不处理任何复杂逻辑
**动画机（Animator）地位一律相同、不分主次**：实体上的每个动画机都承载同一套动作语义，任何动画机的行为脚本都按同一套规则参与"状态推送"与"速度声明"。不要按"主动画机 / 子动画机"去理解，也不存在"某个动画机更特殊"这回事——挂 AnimEvent、配 AttackType/threshold、声明速度，对所有动画机一视同仁。（`AnimEvent.Init` 的 `main` 形参只是让状态推送与速度声明由单个动画机统一发出、避免重复，不代表动画机有主次。）
通常开发只需要阅读其中的EntityAnim文件，其余文件不必管。该文件提供了控制动画的方法和动画会触发的事件（如特定时刻触发攻击）
- `EntityAnim.Init(data)` 只装配数据与复位参数包，**不接收攻击帧回调**：`EntityAnim.onAttack` 只由技能 `BeginCast` 赋值（见《03-技能与Buff总表》三章）；客户端表现视图 Init(null)（无 EntityData，攻击帧回调不传——伤害只由服务器算）
- 骨骼查询统一走 `EntityAnim.GetBoneTransform(HumanBodyBones)`：内部带逐骨骼缓存（每骨骼只查一次 Animator），供 EntityAnchor 等高频取骨处复用
- **动画机控制器由预制体决定**：`EntityAnim.Init` 不改 `runtimeAnimatorController`，实体预制体上的 Animator 必须配好控制器；为空时 `Init` 逐个报 `LogError`（状态机为空时动画不播且不会另有报错，只能靠这条拦）。换动画机直接改预制体
- **武器显示属于动画模块**：`EntityAnim.SetWeapon(武器编号, 武器显示类型)` 只在初始化时调一次（服务器 `EntityData.OnCreate`、客户端建视图、首页角色各一次），编号取 `entity 表`、显示类型与动作集取 `weapon 表`；之后只由 `AnimEvent.ShowWeapon` → `EntityAnim.SetWeaponPos` 驱动，外部（战斗、同步、视图）不再关心武器
- `WeaponPos` 四值决定武器位置：`Hide` 不显示 / `Show` 收起（长枪挂背、刀与双刀挂腰）/ `Hand` 拿在手上 / `DontSet` 该片段不参与武器显示、保持上一个状态；`WeaponDisplayType` 三值：长枪 / 刀 / 双刀。逐状态在 Inspector 配 `AnimEvent.ShowWeapon`，攻击类用 `AnimAttackEvent.WeaponInHand` 在「手上」与「收起」之间选；挂点骨骼、偏移与倾斜见「武器显示（技能三要素①）」节
**动画同步 = 事件驱动（唯一通道）**
- **动画事件（唯一通道，事件驱动，可靠）**：服务器在实体动画**状态 hash 变化**或**播放速度变化**时对该实体的可见客户端补发一条 `SCEntityAnimInfo`（`NetworkManager.SendEntityAnim` → BattleManager 在同步 pass 内 `SendEntityAnim`）。内容 = 实体 id + 状态 hash（`EntityAnim.GetDisplayAnim`）+ 发包时刻的归一化进度 + 持久参数包 + 播放倍率 `moveSpeedScale` + 强控暂停 `paused`。客户端 `EntityPlayerManager.OnEntityAnim` 的应用顺序（**参数先行、片段切换延后一帧**）：**立即**还原参数 + 镜像播放速度（含暂停）→ 若 hash 与本地不同，只登记"待切换"（hash + 进度 + 帧号）→ **下一帧**再决定：本地状态机若已经切到（或正在向目标过渡）就不动它（走控制器自己配的过渡时长），否则才 `Play(hash, 0, 进度)` 强制对齐。这样"参数变化引起"的切换在客户端是有混合的自然过渡，`Play` 只兜底真正不一致的情况。**该实体对某客户端首次可见时也补发一次**（客户端需要初始状态与参数才能摆对）。客户端在视图尚未创建时会**先把事件暂存**、建好视图后补应用。
- **姿态包 `SCEntityDisplayInfo` 不含任何动画信息**（0.02s 位姿/速度/角速度 + 按脏标记条件携带的 health/buffs/skills、0.2s 完整同步，见 NetworkManager 节「实体表现同步」）：动画一律走独立事件通道——若由姿态包兜底，20 次/秒的到达频率会抢在动画事件之前，把切换时机拖到轮询粒度并造成片段进度抖动。
- **客户端何时会被纠正**：切换判断延后一帧，所以"客户端自己跑偏"由**下一次事件到达**时纠正（那时它不在目标状态上 → `Play` 拉回）。因为持久参数现在始终跟随服务器，两端状态机判断一致，"需要拉回"应属少数情况；如果确实想让客户端完全不做状态判断，可再考虑冻结参数（只在建视图时设一次），目前没做。
- **调试日志（仅两条，联调排查用）**：
  - **服务器**：`AnimEvent.OnStateEnter` 里每次状态切换打一行（全英文，`AnimEvent.logStateSwitch` 开关）——`[Anim] id=… type=… state=<hash> progress=… length=…s cur=<片段> next=<目标片段>`；`cur` / `next` 是当前播放与正在切入的片段名（切换中会同时有值），只对主动画机打印（与同步的状态一致）。
  - **客户端**：只有**真正硬切**（下一帧判断后仍与服务器不一致、需要 `Play`）时才打 `[动画强制切换] 实体X(类型) hash=… 要求进度=… → 片段=… 进度=…`：前半是服务器要求的状态与进度，后半（再延后一帧读取）是客户端实际播到的片段名与进度。**命令行不出现就说明该次切换是状态机自己平滑过渡过去的**。开关 = `EntityPlayerManager.logForcedAnimSwitch`
- **trigger 不参与网络传输**：trigger 的作用就是驱动状态切换，而状态切换本身已经触发动画事件（hash 变化），再单独传 trigger 既重复又不可靠（原"本帧设置过"帧戳在服务器帧率高于发包频率时会被吞掉）。trigger 只推给本地 Animator（`EntityAnim.SetTriggerAll`），不写任何同步数据。
- **播放速度也是同步的一部分**：`EntityAnim.SetPaused` / `SetMoveSpeedScale` 只有在**值真的变化**时才置脏并触发一次动画事件——所以强控（动画置 0）与加速/减速/泥沼/死灵漫步都会在客户端如实体现。**移速倍率只有服务器一处计算**（`EntityEffectController.GetMoveAnimSpeedMultiplier`），客户端不自行按 Buff 列表换算，新增移速 Buff 时只改服务器一侧。
- **持久参数变化也要同步**：`EntityAnim.SetType` / `InAir` / `Move` / `DoSlide` / `EndSlide` / `DoAttack` / `DoHit` 全部经 `SetIntParam` / `SetBoolParam` 收口——**与 paramPack 里的当前值比较，值真的变化才写状态机并置脏**（`InAir` 每帧都被 `EntityData.UpdateGrounded` 调用，靠值比较避免每帧同步；`Move` 在 AI 每帧推进里也会重复写同一个值）。理由：参数陈旧会让客户端状态机按错的参数自行转换——`InAir` 停留在 `true` 时，客户端会满足「`InAir` → jump 子状态机」而反复进跳跃。`Init` 时用 `PushParamsToAnimators` 把参数整体推给 Animator，保证"值比较"的前提（paramPack 与 Animator 参数一致）成立。
- 脏标记 = `EntityAnim.AnimSyncDirty`（状态进入 / 持久参数变化 / 播放倍率变化 / 暂停变化时置位）；`BattleManager.SyncEntitiesToClients` 处理完**全部客户端**后统一清除（标记是实体级的、与客户端无关；不可见期间的变化由"首次可见补发"覆盖）。
- `EntityAnim.GetParamPack` / `ApplyParamPack` 只处理持久参数（CharacterType / AttackId / InAir / Moving / Slide / Hit），参数设置统一经参数包记录；AnimParamPack 不含 trigger
- **受击靠参数 + trigger 配合**：`Hit`（Int，0 短 / 1 长）选片段，`DoHit`（trigger）负责重播——`EntityAnim.DoHit(longHit)` 先写 `Hit` 再 `SetTriggerAll("DoHit")`。`Hit` 值没变时参数不会重写，所以**控制器里进受击的转换必须挂 `DoHit` trigger**，否则连续同档受击不重播；跨端仍靠状态 hash 同步，trigger 本身不传
AnimEvent 是纯推送制的唯一入口：EntityAnim.CurrentState 与同步用的 animId 都只由它在 OnStateEnter 更新（**进入状态的同时置动画脏标记，这就是动画事件的触发源**），Do* 方法只写状态机参数、不直接改状态（任何动画机都按同一套规则挂 AnimEvent，见上）。因此**每个需要同步的状态都要挂 AnimEvent**（攻击状态用子类 AnimAttackEvent，逐状态在 Inspector 配 AttackType、判定帧 threshold 与 WeaponInHand）。漏挂的状态既不会同步给客户端，也会让 CurrentState 停在旧值，AI 的 `IsActing` 与受击判定都会跟着错

**阵营（EntityCamp，[Flags]）——攻击判定与索敌的唯一依据**
`EntityCamp` 是位标记枚举：`None=0 / Attack=1 / Defense=2 / Neutral=4 / Prop=8 / Zombie=16 / DefenseTower=32`。**实体自身只占一位**，而「敌对阵营」是可含多位的**掩码**，两者是同一个类型，传参时注意区分"我传的是单个阵营还是掩码"。

| 阵营 | 归属实体 |
| --- | --- |
| Attack | 进攻方角色 |
| Defense | 防守方角色 + 守护雕像 |
| DefenseTower | 水晶雕像（防御塔，防守方设施） |
| Neutral | 中立雕像 |
| Prop | 可采集珊瑚（小/大两种尺寸，同尺寸共用一份属性） |
| Zombie | 普通鲛人 + 精英鲛人（夜刷与防守方角色5 召唤产出） |

敌对关系**只在 `EntityCampUtil.HostileOf(camp)` 一处计算**，禁止在别处再写阵营对立判断：
- 规则：敌人 = **除自身阵营外的全部阵营**；**若自身是中立或 Prop，再从结果中剔除中立与 Prop**；**鲛人与防御塔另按单向特判**（见下）；**防守方与中立/Prop 都不视防御塔为敌**
- 得到的矩阵：攻 = {守, 防御塔, 鲛人, 中立, Prop}｜守 = {攻, 中立, Prop}｜防御塔 = {攻}｜鲛人 = {攻}｜中立 = {攻, 守}｜Prop = {攻, 守}
- `EntityCampUtil.IsHostile(camp, target)` = 目标是否落在敌对掩码内；`All` = 全部阵营位，`NonCombat` = 中立|Prop

**鲛人与防御塔都是「单向」阵营**：它们只敌视进攻方，且**只有进攻方敌视它们** —— 防守方 / 守护雕像 / 中立 / Prop 都不与它们敌对。"除自己外全是敌人"表达不了这种单向关系，故 `HostileOf` 对二者单独特判（鲛人与防御塔直接返回 `Attack`；非进攻方一律把它们从敌对掩码中剔除）。鲛人也**不为防守方提供共享视野**（视野分组用 `camp ==`，阵营不同即自动不成组）。生成时传 `EntityCamp.Zombie`：夜刷 `BattleManagerWorld.SpawnZombie`、防守方角色5 召唤普通/精英鲛人。

**防御塔（水晶雕像）独立占用 `DefenseTower`**：它只索敌、只伤害**进攻方角色**，不打珊瑚、中立雕像与鲛人；反过来只有进攻方会打它。防守方视角仍把它算作己方：`BattleManagerVision.IsInDefenseSide` 让塔对防守方恒可见、小地图常显，`BattlePage.ToPlayerCamp` / `IsEnemyCamp` 把它归到防守方（血条阵营图标与敌我标记）。生成时传 `EntityCamp.DefenseTower`：`BattleManagerWorld.SpawnBattleWorld`、GM 刷塔 `BattleManagerGm`。

**攻击判定统一走敌对掩码，禁止再写"非同阵营即命中"**（避免误伤友方）：
- 子弹命中 `BattleManagerCombat.TryHitBullet`（近战与远程同一条管线）→ `EntityCampUtil.IsHostile`
- 范围索敌 `BattleManager.GetNearestEnemy`（内部取 `HostileOf`）/ `GetNearestInCamp` / `GetAllInCamp`、`SkillBase.AllInCamp` / `EnemiesIn` → **传掩码**，命中掩码内任一位即算
- 范围效果（泥沼 / 疫爆 / 迷雾 / 死灵漫步光环）与视野分组同规则

注意与「同阵营」判定的区别：**取友方**（`SkillBase.GetNearestAlly`、视野"己方单位恒可见"）仍用 `camp ==` / 单阵营掩码，不适用敌对掩码。

⚠️ 连带影响（攻/守角色的判定与旧的"非同阵营"等价，行为不变）：
- 中立（中立雕像）只索敌敌对阵营 → 它的孢子弹不会误伤珊瑚，也不会打防御塔
- 进攻方与防守方**角色**的**自动索敌掩码含中立与 Prop** → 角色侧的"最近敌人"可能在敌人之外锁到中立雕像或珊瑚；「全场/周围敌方」类效果（泥沼 / 疫爆 / 迷雾 / 死灵漫步光环）同样会把它们计入目标（防御塔掩码只有进攻方，不受此影响）
- 鲛人的敌对掩码 = {攻} → **不会误伤珊瑚与中立雕像**（若按"鲛人 = 防守方阵营"推导，中立与 Prop 会被计入敌对）；防守方 / 守护雕像 / 防御塔 / 中立雕像的敌对掩码都不含鲛人，因此也不会打自家鲛人

**锚点（EntityAnchor）——实体上"取某个参照位置"的统一入口**（`Entity/Identify/EntityAnchor.cs`，与阵营同文件、不新增 .meta）
扩展方法 `GetTransform(this EntityAnchor anchor, EntityModelInfo model, EntityAnim anim)` 返回 `EntityAnchorInfo{transform, position, rotation}`——**刻意不依赖 EntityData**：客户端表现视图（没有 EntityData）同样可取；带偏移的锚点 transform=null、position 已是算好的世界值。
**旋转语义**：骨骼锚点返回的 `rotation` 一律取**实体根（`EntityAnim.transform`）的旋转**，**不读骨骼自身的动画旋转**（骨骼旋转随动画状态变化，双端不可能一致），**也不读模型根的旋转**（模型根常带 ±90° 的 FBX 校正旋转，用它会把整组挂点拧偏）；非骨骼锚点本身就是实体根，直接用其 rotation。
按对骨骼的依赖分三档：
- **不依赖骨骼**：GameObjectPosition（实体根）、LabelFallBack（模型根 + 顶 + 0.75m，战斗飘字兜底）
- **可依赖骨骼、也支持非人形**：Bar（血条：人形 Head+0.5m / 非人形模型根+顶+0.5m）、UpCenter（中上：人形 Chest 骨骼 / 非人形模型根+75% 高）、UpFront（UpCenter + (zRange.y+0.5)×前方）
- **必须依赖骨骼**（非人形视图上取不到、会抛异常）：ModelRootPosition(Hips)、Head、LeftHand、RightHand、LeftFoot、RightFoot、Chest、Camera（模型根 + yRange.y×0.5+0.5，相机注视点）、WeaponHipLeft / WeaponHipRight / WeaponBack（武器挂点：Hips / Chest 骨骼 + 实体空间偏移与倾斜，**必须带回骨骼 Transform**；具体换算见「武器显示（技能三要素①）」节）
消费方收口（**不要再各写一套骨骼/包围盒换算**）：服务器 `SkillBase.OriginPos`（技能起点）、`SkillTools.BodyPos`（索敌取体中心）、`EntityData` 的落地检测脚部/头部高度（ModelRootPosition）；客户端 `EntityPlayerManager.TryGetAnchorPos`、相机锚点 cameraAnchor；`BattlePage` 名牌血条=Bar、战斗飘字兜底=LabelFallBack。骨骼查询统一走 `EntityAnim.GetBoneTransform`（带缓存，见 [F]Entity/Anim）。近战命中球不取骨骼，取武器实例的实际位姿（`EntityAnim.WeaponTransform`）

Entity/EntityPhysics.cs:
实体判定的唯一物理查询入口：按 InfoManager 配的层取掩码（`EntityMask` 实体层 / `GroundMask` 地面层），做球/胶囊查询并把命中解析成 EntityData（非实体的碰撞体直接丢弃）；结果先解析再返回，允许嵌套调用
命中判定统一发子弹：近战也发一颗隐形子弹（`SkillTrajectoryWeapon` 贴武器实例），一律用「上一帧位置 → 当前位置」的胶囊覆盖整段路径防穿模
实体的碰撞体由 `EntityModelInfo.BuildCapsuleCollider` 运行时补：半径固定 `GlobalConfig.entity_capsule_radius`（0.22m），高度先取包围盒 `yRange`、之后按脚/头骨骼动态收紧；没有判定体积参数
【必须配置】InfoManager.entity_layer 要填专用层「Entity」（Layer 8）：层掩码按它左移生成，填 0 会与地形等 Default 层 collider 混在一起，查询缓冲被占满后会漏判
【必须配置】InfoManager.ground_layer 要填地面专用层：落地检测只查这一层（否则站在角色身上也会被判成在地面）。**地形与所有可站立的平台/物件都要挂到这一层**，漏挂会被判成永远悬空
客户端为表现而创建的基础几何体（如血条）必须销毁自带 Collider——宿主模式下服务器与客户端同进程，客户端物体同样会进物理查询

子弹系统
玩法中所有攻击全部为各种类型的子弹，移动可跟随玩家/场景空间，可添加各类参数
注意：客户端不会实例化EntityData，处理移动应当通过id获取目标角色的transform
[E]BulletTrajectory 为弹道轨迹基类（abstract）：子弹系统（Bullet/BulletPlayer/BattleManager.ShootBullet）只依赖该基类，不关心具体轨迹。新增轨迹类型继承它并实现 Lerp(factor)（归一化进度 0~1 → 位置）即可，允许携带状态实现动态轨迹（如跟随目标）。现有实现（`Skills/Trajectory/` 下一类一文件，均直接继承基类、互不继承）：SkillTrajectoryLine（直线）、SkillTrajectoryPoint（定点静止）、SkillTrajectorySkyFall（升空超出视野后从目标位置天降）、SkillTrajectoryBezier（三次贝塞尔弧线，控制点在起终点正上方）、SkillTrajectoryFollow（跟随实体：位置恒等于目标当前位置+偏移，按实体 id 双端取位，护盾/Buff 等持续型特效与相关判定共用）、SkillTrajectoryPolyline（折线按弧长匀速）、SkillTrajectoryOrbit（绕实体转圈，半径/起始角/圈数固定）、SkillTrajectoryBoomerang（前半程飞到最远点、后半程回到施法者当前位）；SkillTrajectoryWeapon（贴武器：位置与朝向每帧取武器实例的实际位姿，近战隐形子弹用，握持期间跟随、收起后停在最后位置）。轨迹时长一律在构造时传入。直线与定点不要用贝塞尔模拟，直接用对应实现。
轨迹需要在服务器与客户端按相同参数各自构建：服务器用 Bullet 做逻辑判定推进，客户端用 BulletPlayer 播放表现。双端一致约定（2026-10-03 定稿）：
- **起点同源**：起点一律由 `SkillBase.OriginPos(caster, 锚点, 偏移)` 按实体骨骼锚点现算：`UpCenter`（人形 Chest / 非人形根+75%）或 `UpFront`，两个投掷类（抛出武器、回旋武器）用 `RightHand`；**水晶雕像 / 中立雕像也取 `UpCenter`**（不走雕像顶部）。服务器算完写进波次包，客户端直接用包里那个点。
- **落点高度与距离**：不索敌 → 与起点同高（水平射出），水平距离 = `CastRange`；索敌 → 目标体中心 `UpCenter`（**不锁脚**），水平距离仍 = `CastRange`。**距离一律从施法者自身位置起算**，终点到身体的距离恒等于射程，与发射锚点（体心 / 身前 / 手上）无关——锚点在身前时不会让实际影响距离变成「射程 + 锚点偏移」。专门做上下变化的技能（天降 / 头顶 / 贝塞尔 / 自身周围）自己覆盖瞄准点或轨迹。
- 地面落点类效果（`VfxHelper.PlayAt` 等）仍用包里的施法绝对点（不随位移漂移）
- **BulletPlayer 生成时立即应用初始朝向**（Tangent 模式 LookAt 轨迹切向、Camera 模式取主相机），否则首帧是预制体默认朝向、下一帧才转正（刀光等会先朝错方向再转）
- **子弹伤害判定（hits 驱动）**：`ShootBullet(caster, attack, trajectory, lifeTime, BulletHitSpec)`，`BulletHitSpec` = 命中球数组（来自特效预制体 `BulletVfxInfo.hits`，由 `VfxHitSource` 按 `(kind, 下标)` 解析并缓存）+ 每段伤害倍率 + 缩放倍率 + 同目标再伤害间隔 + 日志标签。`TickBullets` 每帧按 `age = now - spawnTime` 与每段的 `start/end` 直接比较（`end = 0` 视为全程），球心 = 轨迹位置 + 朝向（与 `BulletPlayer.Tangent` 同算法，`trajectory.TryGetRotation` 返回真时改用轨迹自带朝向）+ `center×scale`，半径 = `radius×scale`，判定用「上一帧球心 → 本帧球心」的胶囊；同一目标按 `damageInterval` 冷却重复结算（<=0 或留空的 100 都只结算一次）。寿命取 `BulletVfxInfo.lifeTime`，资产没填（-1）时用技能传的时长、再退回轨迹时长。没有命中球的子弹会在发射时报一次 `[子弹]` error 且不造成伤害。
- **近战（普攻 / 腐爪 / 裂骨爪）同样发子弹**：`SkillBase.StrikeWeapon` 发一颗无表现的子弹，轨迹 `SkillTrajectoryWeapon` 每帧取武器实例的实际位姿（位置 + 含 `WeaponFix` 的旋转），命中球只取武器预制体的 `center/radius`、**忽略资产里的 `start/end`**，存活固定 `MeleeBulletLife`(0.5s) 覆盖整段挥刀，每目标一刀一次（第 10 列留空 = 100）。武器收起（片段结束回到背后/腰间）后判定球停在最后一次握持位置，不跟着跑到腰上；取不到武器实例时不发弹并报一次 `[武器]` error。
- **战斗飘字类型**：飘字 = 数值 + 类型（`CombatLabelType`，12 个值按序对应 FGUI `UI_DamageLabel` 控制器页号：正常 / 暴击 / 闪避 / 失效 / 护盾 / 燃烧 / 苍白之火 / 中毒 / 死灵漫步 / 反伤 / 瘟疫引爆 / 治疗）；`SCCombatLabel` 带 `type`，客户端直接 `selectedIndex = (int)type`。闪避没有概率：`ProcessHit` 开头查目标是否带 `DodgeBoost`，带有则本次命中直接记 `Evade`（0 伤害、不进入受击，也不会被击退）。命中类伤害（正常/暴击）撞盾一律记「护盾」页、数值取名义伤害（整次数值），盾值不够的溢出部分照常扣血；DoT、反伤、瘟疫引爆无视护盾直扣血；非闪避却结算为 0 伤害的记「失效」。

速度（**改速度前必读**）——**允许的来源只有六种，其它一律不允许**（尤其"用输入自己算速度"）：
（1）**动画声明**（见④）—— **玩家主动操控的速度只能来自这里**，动画没声明就没有速度；（2）**地面停步衰减**（无声明且在地面时按帧快速衰减到 0，见①）；（3）**技能 / 特殊效果位移**（MotionBase，见⑤）；（4）**重力**（见③）；（5）**击退**（命中施加的独立速度项，逐帧衰减，见⑥）；（6）**飞行**（GM 专属垂直速度声明，见⑬）。
移动速度的"快慢"（加速/减速/泥沼/死灵漫步）**完全通过调整动画播放速度实现**（见⑨）——不存在第二条速度通道。
**速度来源枚举 `VelocitySource`**（三类写入者：Animation / Motion / Flight）：EntityData 的一切速度写入必须携带来源。内部**只记录当帧声明值**（declaredForward / declaredHorizontal / declaredVertical），不做来源分桶：Motion 的速度每帧由 TickVelocity 向 MotionBase 现取。**击退不走声明接口**，而是单独维护一个速度项叠加进最终速度（见⑥）。TickMovement 只做空检查并逐实体调 TickVelocity，MotionBase 三态、朝向与输入推进、混合写刚体、区块索引同步都在 TickVelocity 内部完成。
① 速度的**唯一决策处** = EntityData.TickVelocity（BattleManagerCombat.TickMovement每帧调用），**声明是"每帧"的**：declaredForward / declaredHorizontal / declaredVertical（含 declaredMotionEnter）在 TickVelocity **末尾无条件清零**——速度只存在于"当帧声明过"的那一帧，**不存在残留/陈旧声明**（不按动画状态缓存声明）。**击退速度 `hitbackVelocity` 不参与这套清零**，它按自己的速率衰减（见⑥），每帧并入最终速度。三条分支：
· **有 MotionBase**：SetMotion 当帧 Enter → `Time.time >= motion.endTime` 时 Exit → 否则 Update，取位移速度；`motion.canMove` 时叠加当帧动画声明（空中同样生效），最终速度**整向量**写刚体，**再叠加击退项**；
· **有声明**：`rb.velocity = DeclaredVelocity() + hitbackVelocity`（三路声明只取最后声明的那一路：水平 → 前后 → 垂直，后声明者覆盖；前后 = `transform.forward × 声明值`、水平 = 世界空间 x/z、垂直 = 向上）；**在空中保留当前 Y**（垂直声明除外，如起跳）；
· **无声明**：在地面 → 基础速度（先把上一帧击退分量从刚体速度里剔除）`*= Mathf.Min(0.9f, Time.deltaTime * 500)`（**按帧快速衰减到 0**，一帧最多保留 90%，约 0.2 秒内停住）；在空中 → 保持刚体速度（无空气阻力、无空中控制）。两条分支最后都叠加 `hitbackVelocity`，否则空中击退不会生效。
**没有"用输入自己算速度"的退化路径**：推进输入只提供方向（坦克式，见输入节）。
② 速度的**唯一写入处** = EntityData.TickVelocity（每帧结算，按分支写整个速度向量；空中无声明时也写，否则击退项无法生效）。
③ 垂直速度：重力自动积分（SetupBody把useGravity置true；**GlobalConfig.rb_drag必须为0**，否则空中会掉速、并在地面叠加出第二条衰减曲线）；起跳的向上初速度由**动画状态声明**（`AnimJumpStartEvent` → `EntityAnim.SetVelocityVertical(animData.jumpSpeed)` → `EntityData.SetVelocityVertical`），之后仍交回重力。**K 键只做跳跃，不按移动状态分派**：静止与移动一律进 `jump` 状态机（`Jmp_Base_A_Start` → `Jmp_Base_A_Keep` → `Land_Base_Wait/Move`，行为脚本 `AnimJumpStartEvent` / `AnimJumpEndEvent`），控制器里 `idle → jump` 与 `walk → jump` 都指向它。
④ 声明速度的三个入口：EntityAnim.SetVelocityForward/Horizontal/Vertical 直接调用EntityData的同名接口（**不经委托**：动画可在高频处声明，走Action会白白多一次间接调用；客户端无EntityData，调用即忽略）——**具体数值完全由动画模块决定**；**声明只在"声明它的这一帧"有效**（TickVelocity 末尾统一清零，见①）：持续移动必须**每帧都声明**（如 `AnimRunEvent.OnStateUpdate` 在 Run 状态里逐帧声明），一次性动作（起跳）自然只作用一帧。**前后 = 沿角色本地正前方 `transform.forward`（不带输入符号）**，**水平 = 世界空间（x→世界X、y→世界Z，支持正负）**；垂直不乘系数。**前后与水平在声明时会乘当前动画播放速度（EntityAnim.PlaybackSpeed）**，垂直不乘。**速度声明的唯一发出点是动画机状态的行为脚本**（`AnimRunEvent` / `AnimJumpStartEvent` / `AnimJumpEndEvent`；动画机地位一律相同，见 `[F]Entity/Anim`）——游戏逻辑**只触发动画与传参数、不自己产生速度**（唯一例外：击退，它不走声明而是独立速度项，见⑥）。
⑤ 位移效果（MotionBase，**不含击退**）：Enter/Update产出速度，**不吃输入也不吃任何速度系数**（冲刺不该被减速Buff缩水）；**生效期间无视停步衰减**，由 EntityData.TickVelocity 每帧向 Update 取本帧速度：canMove = 位移与动画声明混合，否则位移完全接管（阻断动画来源）。**Exit 仅在时间自然到期时调用**（TickVelocity 里 `Time.time >= motion.endTime` 时调 `motion.Exit`，返回值当帧写刚体）；中途移除一律**不调用 Exit**——破霸体命中（ProcessHit）、SetMotion 替换等直接 `motion = null`，强控施加（EntityEffectController.ApplyControl）只置零动画播放速度、不打断位移；位移速度消失后，残留速度交回停步衰减/动画接管）。
⑥ 击退（**命中施加的独立速度项，不走速度声明**）：`ProcessHit(attack, damage, damageType, hitOrigin)` 取 `AttackData.knockbackPower`（skill.csv「击退力度」，`BuildAttack` 的 knockback 参数可覆盖）作为配表力度，**v ≤ 0 视为不带击退**（实际初速 = 力度 × `hitback_force_multiplier`）。施加条件是**只有护盾能挡**：`rb != null`、非飞行模式、目标身上没有任何护盾（`GetShieldAbsorb() > 0`，含 Shield 与 StatueShield）——霸体、冰冻等控制状态都不阻断击退。方向优先取「目标位置 − 攻击者位置」压平 y 后的水平方向（攻击者由 `attack.shooter` 查实体容器），**攻击者实体不存在时**退回「目标位置 − hitOrigin」（子弹传上一帧的命中球心，近战传判定球心）；水平距离趋近 0 时沿目标自身面向。方向 × 实际初速**累加**进 `EntityData.hitbackVelocity`（Vector3，y 恒 0，连续命中会叠加）。`TickVelocity` 每帧把它并入刚体：先 `baseVel = rb.velocity - lastHitback` 剔除上一帧写入的击退分量（否则地面/空中的惯性分支会把击退反复读回、越推越远），三条分支全部用 baseVel 计算，最终 `rb.velocity = 结果 + hitbackVelocity`，再 `lastHitback = hitbackVelocity`，最后按 `hitback_friction` 线性衰减（`MoveTowards(zero, friction × deltaTime)`），衰减后模的平方低于 `hitback_threshold_squared` 立即归零并退出混合。**受击表现与击退并行**：enterHit = 有 EntityAnim 且（攻击破霸体，或目标无霸体），进分支 `motion = null`、`anim.DoHit(breakEndure)`（破霸体长受击、否则短受击）、转身面向命中来源；**不破霸体的攻击打中霸体目标仍不进受击、不停位移，但击退照常**。击退没有垂直分量：空中被击退只受水平推力，纵向仍由重力支配。
⑦ 空中/落地判定：EntityData.UpdateGrounded（**起跳后 0.4s 内一律算空中**：`AnimJumpStartEvent` 进入时把 `Time.time` 写进 `EntityAnim` 的起跳时间戳，`InJumpAirGrace` 期间直接置 InAir 并跳过下面的速度与射线判定——起跳当帧速度还没写进刚体、脚下探针仍踩在地面；其余情况**先判垂直速度**：上升速度 ≥ 1 m/s 直接离地并跳过物理查询；可能落地时从**脚部骨骼高度**（双脚取低者，反映动画姿态；非人形无脚骨骼回退实体位置）上方 0.1m 向下打一条 **0.6m 的射线**（`Physics.RaycastNonAlloc`），命中**地面层 InfoManager.ground_layer** 上任意非 trigger 碰撞体即算踩在面上、剔除自身碰撞体）写anim.InAir，**不用计时**判断落地（计时只用于上面的起跳后空中豁免）。**调用点：`EntityData.TickVelocity` 开头**（随移动结算每帧执行）。
⑧ 表现同步与客户端推演：服务器把刚体实际水平速度与yawSpeed随SCEntityDisplayInfo下发（BattleManager.FillDisplayVelocity），客户端在ClientEntityView.Update里按velocity/yawSpeed做包间推演（纵向不推演，位置仍以服务器包为准）；客户端表现刚体为 kinematic、由 Update 的 MovePosition/MoveRotation 驱动，**插值必须为 None**（可变帧率喂目标会与物理步拍子打架产生 judder，角色/武器/血条一起抖）；**动画完全不在这条通道上**（该包不含任何动画字段，动画走事件通道，见 `[F]Entity/Anim`「动画同步」）。
⑨ 动画播放速度（EntityAnim.PlaybackSpeed = 播放倍率，强控暂停时为0）：既写 animator.speed，也在 SetVelocityForward/Horizontal 里缩放声明值——于是"走得快"与"动画播得快"天然同步，**加速/减速/泥沼/死灵漫步（GlobalVariable.F(global_variablesEnum.buff_speed_up / buff_speed_down / buff_mire_speed_rate) 与 death_stroll_speed_up）的效果就落在动画侧**（策划案11.3：这些效果的载体就是动画移动状态的播放速度倍率）。移速类清单收口在 EntityEffectController.IsMoveSpeedEffect，倍率只在服务器算（GetMoveAnimSpeedMultiplier），通过动画事件随 `moveSpeedScale` / `paused` 下发，客户端只镜像、不自己按 Buff 换算。其它速度来源（MotionBase位移、重力、击退）完全不受这几个Buff影响。
⑩ 子弹**没有**"速度"参数：位置由BulletTrajectory按"经过时长/生命"插值，快慢由轨迹总时长决定（调弹速就调时长或改轨迹实现），判定用"上一帧→当前帧"胶囊扫掠。
⑪ 相关配置：GlobalVariable.F(global_variablesEnum.move_turn_rate)（转向角速度）、rb_drag（**必须0**）、rb_angular_drag（刚体旋转只锁 X/Z、**Y 轴不锁**，见 SetupBody）、anim_move_speed_up/down/mire（动画播放速度与声明速度倍率）、hitback_force_multiplier / hitback_friction / hitback_threshold_squared（击退的初速倍率、衰减速率、归零阈值的平方，见⑥）。**移动速度与跳跃初速不在 Config** —— 都是动画模块的模型数据（`EntityAnimData.RunSpeed = legHeight × 5`、`JumpSpeed = √(20 × legHeight × 0.4)`）；**击退力度逐技能**写在 skill.csv「击退力度」列，`BuildAttack(knockback:)` 可覆盖，力度到实际初速的换算才走 global_variables。
⑫ 可移动判据：**挂了 `EntityAnim` 的单位才是可移动单位**（`EntityData.SetupBody` 与 `BattleManagerCombat.TickMovement` 用同一判据 `anim == null`）；珊瑚/守护雕像/水晶雕像/中立雕像等非人形单位无动画，因此不挂刚体、不进移动循环。滑铲的**持续时长由动画模块自己决定**，外部不传时长。
⑬ **飞行模式**（GM 专属，开关 = `PlayerEntityData.SetFlightMode`，**仅真人玩家**，与 AI 控制互斥由数据保证；复活/重开局重建实体后状态重置，需重新开启）：
· 开启：`SetGravityEnabled(false)` 关重力 + 强制 `grounded=true`、`InAir(false)`；`TickVelocity` 每帧强制 `rb.useGravity=false`（防动画/技能状态经 `AnimEvent` 设回）。`UpdateGrounded` 关重力期间早退 → grounded 恒 true → InAir 全程 false，**动画自然走地面站/跑状态**（`anim.Move` 原链路不动，空中 = 平地）。
· 垂直速度：`PlayerEntityData.OnTickMove` 每帧声明（`VelocitySource.Flight`）——长按 K 升 / 长按 Shift 降，固定 `GlobalVariable.F(global_variablesEnum.fly_vertical_speed)`（5），无键声明 0 悬停；按住态由 CSPlayerInput 新增的 KRelease/LShiftRelease 抬起边沿维护（输入屏蔽期间一并清零）。**无阻力**：垂直声明恒存在 → 走"声明覆写"分支，松键即停、水平松 W 也立即停（与地面的 ×0.9 衰减滑行尾巴不同）。
· 免疫：`ProcessHit` 飞行时 enterHit=false（不受击退、不受击打断，**伤害照常结算**）；`ApplyKnockback` 对飞行模式直接早退；`SetMotion` 直接早退（不施加位移，含自身位移技能）；跳跃/滑铲分支被 `!flightMode` 包裹（K/Shift 转为升降长按）。
· 关闭：`SetGravityEnabled(true)` 恢复重力，grounded/InAir 交回地面检测——悬空则自然下落，不瞬移落地。
索敌：`SkillBase.TargetSector` / `TargetRadius` 读 `skill 表` 第 13 / 14 列，`SkillBase.Aim(caster, origin)` 据此定落点——**夹角 ≤0.1 不索敌**（朝自身面向、水平距离 = `CastRange`、落点高度 = 起点高度）；夹角 >0.1 时朝目标**体中心**（水平距离仍为 `CastRange`、落点高度 = 体中心）；夹角 >179.9 不限方向；半径 >9999 不限距离。目标只在服务器 `OnCast` 里解析一次（`ResolveTarget`）并随波次包下发，客户端用包里那对点、不复算；范围内没锁到敌人时落点等同「不索敌」，**禁止回退为自身**。非射击类（防守方 / 水晶雕像 / 中立雕像）走 `SkillTools.AimPos(entity, 夹角, 半径, 射程)`，取点口径相同。
轨迹实现需要实体位置时必须用BulletTrajectory.TryGetEntityPosition（只要位置）或TryGetEntityTransform（位置+朝向）（按实体id读取，双端通用；服务器查实体容器、客户端查表现视图）；需要武器实例位姿时用TryGetWeaponPose（位置+朝向+是否握在手上）。禁止直接读取EntityData组件（客户端不存在该组件）。
瞄准点不由外部传入：技能自己在 OnCast 里按配表索敌口径算（`SkillBase.Aim`），算完写进波次包。

武器显示（技能三要素①）：
**武器的唯一来源是配表**：`entity 表` 末列「武器编号」+ `weapon 表`（编号 / 名字 / 武器动画类型 / 武器显示类型）。实体持有固定武器，**技能不携带任何武器信息**（`skill 表` 里没有武器列）。武器编号是一维下标，同时是 `weapon 表` 主键与 `WeaponPrefabs` 下标（服务器取 `AssetsManager`、客户端取 `ResourceManager`，两端同名同序）；留空 = 无武器（此时模型不该挂 `EntityAnim`，一旦有动画却缺编号会直接报错）
**没有常驻悬浮武器**——角色身边不摆任何武器外观，只有"手上拿的 / 收起的"两种；`SpringWeapon`、实体锚点的武器槽位、`SkillManager.GetFlyWeapon` 全部已移除
远程技能发射点 = 技能自己在 `OnCast` 里传给 `OriginPos` 的锚点（`UpCenter` / `UpFront`，两个投掷类用 `RightHand`）；`UpCenter` = 人形 Chest 骨骼 / 非人形模型根+75% 高度，水晶雕像与中立雕像同样用 `UpCenter`
**投掷类技能的武器本体取实体固定武器**：服务器 `SkillBase.WeaponOf(caster)`（即 `EntityData.weaponId`），客户端 `DisplayWeapon(context)` 按施法者 id 取表现视图上的 `EntityAnim.WeaponId`；命中球与特效下标都跟着这把武器走，技能之间不再各自指定武器
**显示位置完全由动画驱动**：每个状态在 Inspector 配 `AnimEvent.ShowWeapon`（攻击类另有 `WeaponInHand` 决定「手上」还是「收起」），`AnimEvent.OnStateEnter` 调 `EntityAnim.SetWeaponPos`。挂点分两种：

**手上**：骨架本身没有武器槽，`EntityAnim.Init` 在 `hand_r` / `hand_l` 下各建一个空物体挂点（`WeaponSocket_R` / `WeaponSocket_L`），武器作为它的子物体。位置 = `EntityAnimData.weaponHandLocalOffset` / `weaponLeftHandLocalOffset`（**单位米**，沿手骨局部轴：y 手腕→指尖、z 掌心法线、x 剩余轴；逐帧写入，运行时改能实时看到），朝向 = 手骨旋转 × 标定角（右手 `(0,90,180)`、左手 `(0,-90,180)`，常量在 `EntityAnim`；**这两个角是标定值，换骨架或换模型要重标**）。双刀左右各一把，单手武器只用右手。

**收起**：长枪挂背、刀挂右腰、双刀左右腰各一把，走 `EntityAnchor.WeaponBack` / `WeaponHipLeft` / `WeaponHipRight`，父节点是 Chest / Hips 骨骼（**锚点必须返回骨骼 Transform**——只给位置的话武器不会跟着人物动画动）。偏移是实体空间常量：长枪 `(0, -0.05, zRange.x-0.08)`，腰部 `(±(模型半宽 + WeaponHipSideExtra), WeaponHipHeight, WeaponHipForward)`；倾斜是 `WeaponHipTilt` / `WeaponBackTilt`——长枪竖直后向右侧倾 30° 且刀面与背平行，刀的刀锋朝后下方、刀面贴腰侧。挂载时偏移与倾斜都换算成**骨骼本地常量**（`CacheAnchorRestOffsets` 在绑定姿势下缓存骨骼相对实体的朝向），所以胯/胸随动画转动时武器跟着腰背走，不会停在实体的左右两侧。

**缩放**：骨骼普遍带百倍量级缩放（美术导出遗留），挂点按骨骼 `lossyScale` 反向抵消，武器保持预制体的原大小。武器外观不参与协议：动画状态一致，两端算出的显示位置就一致

实体 AI（服务器侧）：
唯一落点是 `EntityData.TickAuto()`（虚方法，默认空实现）——需要自动驱动的实体自己覆写；`BattleManager.UpdateAI()` 每帧遍历全部实体调用它，**不按类别分支、不做全局节流**（决策频率由各状态机在自身 Tick 内按 id 错峰）
自动驱动的实体分两类接法：
① 自带决策的四类（鲛人 / 水晶雕像 / 中立雕像 / 人机）：**双层状态机** —— 决策层 `DecisionMachine` + `DecisionState`（每类实体独有），行为层 `BehaviorArbiter` + `Behavior`（四类共用一份），中间由 `IBehaviorHost` 接缝把行为落到具体实体
② 外部指令驱动（被 AI 接管的真人玩家）：**只有行为层、没有决策层** —— `AiIntentRelay`（`Scripts/AiInterface/`）持一个 `BehaviorArbiter` + 永远返回 null 的 `RelayState`，意图由客户端经 `CSAiIntent` 上行、`BattleManager.ReceiveAiIntent` 翻译成 `RequestIdle` / `RequestMove` / `RequestAttack`；`ThinkInterval = 0`（命令到达当帧就落行为层），`NotifyStuck` 转 `SCAiFeedback` 回执给客户端；技能释放走独立协议 `CSAiSkillCast`，不经键盘链路
接管标志是 `PlayerEntityData.aiControlled`（起于会话级 `BattleManager.AiClients`，复活重建实体时恢复），**不能标 `robotControlled`**（那是 RobotAi 的入口）；`OnTickMove` 的自动移动分支与 `TickNavRescue` 一起按 `aiControlled` 走，**不复制第二份移动逻辑**；接管期间服务器丢弃该客户端的按键与技能键
这一类不进 `StateMachine/` 目录，行为层与 ① 共用同一份；完整设计见《09-AI实时操控交互》
① 的两层节奏不同：决策层按 `ThinkInterval` 节流（`DecisionMachine.Tick` 开头判断 `Time.time < nextThinkTime`，≤0 表示每帧思考）；行为层每帧仲裁（各状态机 Tick 末尾调 `arbiter.Tick(dt)`）
`TickAuto` 只决定"去哪、放什么"：转向与推进仍由 `OnTickMove` 每帧负责，**AI 自身不产生任何速度**（速度五来源不变）。寻路共用 `EntityData` 上的 `MoveTo` / `StopMoving` / `ResolveNavDirection`（只借 NavMesh 算方向：`SamplePosition` + `CalculatePath`），**不用 NavMeshAgent**；目标没挪窝不重算路径，所以逐帧调用也安全。
**前置**：服务器场景必须烘焙 NavMesh —— 未烘焙时 `CalculatePath` 失败会**静默回退"直线朝目标走"**（不报错，但会穿墙/穿地形）。
另：AI 的移动意图靠 `OnTickMove` 每帧消费，而移动循环的判据是 `anim == null` 跳过 —— 所以**会移动的实体预制体必须挂 `EntityAnim`**，否则 AI 给出目的地也不会动。
`TickAuto` 在 ManagedUpdate 中位于移动与子弹推进**之后**，因此能看到本帧最新位置；它释放的技能子弹要到下一帧 `TickBullets` 才结算

状态机目录（`Scripts/StateMachine`）：
`Core/DecisionFrame/`：`DecisionMachine`（节流 + 决策态切换 + `OnThink` 钩子）、`DecisionState`（`Decide()` 返回下一个决策态，null = 保持）
`Core/Behavior/`：`Behavior`（`Kind` / `CanInterrupt` / `Bind` / `Tick`）与 `IdleBehavior` / `MoveBehavior` / `AttackBehavior`
`Core/` 根：`BehaviorArbiter`（行为仲裁）、`BehaviorRequest`（`Kind` + `Point` + `Target`）、`IBehaviorHost`（接缝）
`Zombie/` `CrystalStatue/` `NeutralStatue/` `Robot/`：各实体的决策机与决策态；`Robot/` 另含 `RobotSkillBar`
行为层只有这一份实现，实体差异全部落在 `IBehaviorHost` 的实现里

行为层（三个通用行为）：
`BehaviorKind` 只有 `None` / `Idle` / `Move` / `Attack`；`None` = 决策层本拍没意见，行为层保持当前动作
`IdleBehavior`：停步 + 按请求里的 `Target` 朝向（可空）
`MoveBehavior`：请求带 `Target` = 跟随目标物体（`Tick` 每帧按目标最新位置重发 `MoveTo`）；`Target` 为空 = 走向 `Point` 静止坐标，只在请求变化时下发一次。目的地算不出路（`NavUnreachable`）时停步并 `NotifyStuck` 交回决策层
`AttackBehavior`：停步 + 朝向 + 出手；`CanInterrupt = !host.IsActing`，动作没播完就压住切换；离开时 `ClearFace`
`BehaviorArbiter`：请求种类与当前一致且被重写 → 重新 `Bind`；种类不同且当前允许打断 → `Exit` / `Enter` / `Bind`；每帧对当前行为调 `Tick`

接缝 `IBehaviorHost`（行为层只认这个接口，不认具体实体类型）：
`Owner` 实体 / `Stop` 停步 / `FaceTarget` 朝向目标 / `TryAttack` 出手一次并返回是否放成 / `IsActing` 动作是否未播完 / `ClearFace` 清朝向 / `NotifyStuck` 目的地算不出路
三种执行口径：鲛人 `Stop()` 连带停动画与移动输入、`SetFaceTarget(id)` 锁朝向、出手按距离在爪击与嘶吼之间选；人机 `StopMoving()` + `SetRobotFacePoint(pos)`、出手走 `RobotSkillBar`；雕像 `StopMoving()`、不转向、出手直接放技能

技能冷却与库存（服务器权威）：
状态只有一份，记在实体的 `EntitySkillController` 上；`SkillRecharge` 的形态是 (skillId, cd 根时间戳)：库存 = `(now − root) / CD` 的整数部分、本轮进度 = 小数部分，**没有每帧推演、没有 Tick**，时间源是服务器 `Time.time`
`GetStore(id)` 返回库存次数（`-1` = 无限库存，`0` = 用完了），`GetCycleProgress(id)` 返回本轮 0~1 的进度
首次获得技能按**满库存**入账（`root = now − CD × 上限`）；释放成功才 `Consume(id)`（根前移一个 CD），失败不扣
技能栏由服务器持有：`EnableSlotBar(容量)` 在真人玩家实体生成后启用，栏位按持有顺序补满；选择面板提交走 `TrySetSlotSkills`（必须都持有、不重复、不超过容量）
栏外冻结：卸下槽位时记下解冻瞬间（`frozenAt`），恢复量停在这一刻；重新选上只把根戳平移 `now − frozenAt`，**不补次数**，反复装卸刷不出使用次数
只有真人玩家有栏位冻结；AI 玩家与 NPC 没有技能栏概念，持有即恢复
`store = -1` 表示无限库存、不消耗，恒可用 —— 鲛人爪击与空手三连即此，等于由动作节奏限流
CD 与存储上限一律读 `skill 表`，**代码里没有独立的施法间隔**；两个 NPC 共用一个技能的场合要按次数配表，不要退回"定时器 + 随机取技能"

客户端（`ClientSkillManager`）：只做显示，不推演库存
服务器只在**槽位改变 / 释放成功 / 持有表全量或增量下发**时下发一次 `SCSkillRecharge`（槽位技能 id 列表 + 对应根戳列表）；客户端 `ApplyRecharge` 整体替换本地 `SkillRecharge`，读数同样只是 `(服务器时间 − 根戳) / CD`
时间源是 `ClientToServerTime(Time.time)`，与服务器时钟对齐；本地不 Tick、不 Consume、不自己判断栏外冻结
选择面板提交走 `CSSkillSelection` 上行，服务器校验后回推快照，本地不预演
技能没有等级与经验：**服务器无限量记持有**（抽卡只判"是否已持有"）；玩家复活重建实体时持有表与槽位原样继承（`CaptureLoadout` / `ApplyLoadout`），冷却随新实体从满库存起算

技能释放校验（`EntitySkillController.TryUseSkill`，所有释放路径的唯一收口）：
按顺序校验：技能 id 存在且在该实体**持有表**内（空手三连为通用技能，不持有也放行）→ 未被沉默 → 未被强控 → 技能已注册（未注册属配置错误，`LogError`）→ **库存为 0 则拦下**。返回 `UseResult`（Success / NoSkill / Silenced / Controlled / Unregistered / Cooling）。玩家释放走 `BattleManager.ReceiveSkillCast(clientId, skillId)`：技能 id 由客户端上行，服务器再拦一次攻击屏蔽（`InputBlocked(InputBlockOp.Attack)`，攻击动画期间）；NPC 由状态机按自己的技能表槽位直接调 `TryUseSkill`
释放失败提示：玩家路径（`ReceiveSkillCast`）失败时调 `BattleManager.NotifySkillUseFailed`，按原因下发 `SCPrompt`（30 = 被沉默 / 31 = 被控制 / 32 = 冷却中），同一客户端 1 秒内只提示一次；`Cooling` 在提示之外同时回推一次 `SCSkillRecharge` 纠正客户端显示；NPC 失败不提示
**没有施法距离门闸**：任何实体在没有目标时也能释放技能，"该不该放"由各自决策层判断 —— 玩家不受限、随时可放（空手攻击亦然）；鲛人按距离分档；雕像是"技能就绪 + 索敌范围内有敌人"；人机由决策态判断
没锁到敌人时的落点由技能自己按「自身面向 × 技能射程」定距给出（射程读 skill 表 第 14 列，为 0 时该技能不产生落点），不回退到自身；近战技能自身不做距离判定，命中球取武器预制体的 `BulletVfxInfo`（见「子弹伤害判定」）
`SkillBase.CastRange` = 技能能影响到的距离，同时作直射落点距离、索敌半径与人机接敌参考，不影响能否释放；索敌范围 = 第 13 列夹角 + 射程（没有独立的半径列）逐技能读表

鲛人（`ZombieStateMachine`，普通与精英鲛人共用一套决策层）：
三个决策态：`Wander`（无目标：出生点附近随机取点游荡，到点停 `GlobalConfig.zombie_wander_pause` 秒）→ `Chase` → `Attack`
`Chase`：超 `GlobalConfig.zombie_max_chase_distance` 放弃并回游荡｜`dist <= zombie_attack_range` 进攻击态｜`dist > zombie_roar_range` 且嘶吼就绪 → 进攻击态｜其余 `Move(目标)` 跟随
`Attack`：动作未播完 → 保持｜`dist <= zombie_attack_range` 出手（爪击）｜`dist > zombie_roar_range` 且嘶吼就绪 → 出手（嘶吼）｜超 `zombie_attack_range × GlobalConfig.zombie_attack_exit_scale` 回追击｜退出缓冲区内 `Move(目标)` 贴近
**嘶吼与爪击由 `TryAttack` 按距离选**：远于 `zombie_roar_range` 放嘶吼（吃冷却与次数），否则左右爪交替（`store = -1`，不消耗次数）
技能表槽位约定（顺序见 `GlobalConfig.initial_skills`）：0 爪击右 / 1 爪击左 / 2 嘶吼；普通鲛人只有 0、1，第 3 槽不存在时嘶吼判定恒不可用，因此两类鲛人共用同一套决策层、**无需按精英分叉**
索敌半径为属性 `viewDistance`（未配则回退 `GlobalConfig.zombie_acquire_range`）并夹到最大追击距离内，避免"刚索敌又要放弃"的空转；**已锁定目标仍有效就不换**
目标连续算不出路时忽略该目标一段时间（`GlobalConfig.ai_ignore_unreachable_time`），避免放弃后下一拍又锁回同一个
攻击档停下后由 `OnTickMove` 的无目的地分支继续朝目标转向（只转不走），贴身时不会丢失朝向

雕像（`CrystalStatueStateMachine` / `NeutralStatueStateMachine`）：
各只有**一个决策态**，产出 `Attack`（技能就绪且索敌范围内有敌人）或 `Idle`，**从不产出 `Move`**；不移动、不转向、不产生任何速度
水晶雕像固定放自己那一个技能（带灵火时换成灵火喷吐）；中立雕像从技能表里随机取一个已就绪的技能
索敌全向不限朝向，半径见 `GlobalConfig.crystal_statue_attack_range` / `GlobalConfig.neutral_statue_attack_range`；敌对掩码见「阵营」节
就绪判定本身已节流（没冷却好就不做范围查询）；就绪时范围查询再按固定扫描间隔执行（见代码）
新增同类固定单位按文末四步接入，不要再写"定时器 + 随机取技能"的独立施法逻辑

人机（`RobotAi`，服务器侧虚拟玩家）：
`PlayerEntityData.TickAuto` → `RobotAi.Tick`，仅 `robotControlled` 时创建；由服务器在生成玩家实体后置位（`StartBattle` 与 `RespawnPlayer` 两处），真人玩家不受影响、输入仍来自网络
15 个决策态按战术意图分（搜索 / 追击 / 护送 / 集结 / 突袭 / 危险规避等），状态图与快捷消息矩阵见《08-游戏AI逻辑》
**目标选择取「索敌范围内最近的敌对目标」**，敌对由 `HostileOf(自身阵营)` 现算，**攻守不分叉**
技能栏 `RobotSkillBar` 只负责选栏与出招顺序：按持有表「品质降序、同品质 id 降序」取前 `weaponSlotCount` 个入栏（每次思考时 `Rebuild` 重排），出招时栏内从高到低试，再退到空手三连（远了直拳、贴身崩拳）；冷却与库存由实体的 `EntitySkillController` 记账，技能栏本身不存冷却
卡住检测：一段时间没有位移就 `StopMoving` + `NotifyStuck`，由当前决策态换目标；决策按 `GlobalConfig.ai_think_interval` 节流，快捷消息任务单槽后到覆盖

新增一类自动驱动实体（四步）：
① 建 `XxxStateMachine : DecisionMachine, IBehaviorHost`，覆写 `MachineOwner` 返回自己的实体
② 实现 7 个宿主钩子，只写本实体的执行动作，不写移动/攻击时序
③ 写决策态（`DecisionState` 子类），在 `Decide()` 里调 `arbiter.RequestIdle` / `RequestMove` / `RequestChase` / `RequestAttack`

Editor文件夹（编辑器工具，只在 Unity 内使用，不参与打包）：

Test文件夹：
本地动画/移动测试工具，不依赖网络与 BattleManager，Play 即生效；仅测试用途，打包会一起编译（暂未做条件编译隔离）
`AnimationTest`（驱动器，挂场景任意物体）：Start 时随机实例化一个人物模型（编辑器下扫 `Files/Prefabs/Entity` 的 Attacker/Defenser 目录，打包运行或目录为空时读 Inspector 的 manualPrefabs）并挂 `TestEntityData` 装配；每帧读本地键盘调 `TickVelocity`，与服务器循环同一条结算链路。键位与正式版语义一致（坦克式）：W 前进 / A D 转向（S 弃用）/ Space 或 K 跳 / 左 Shift 滑铲 / R 重新随机生成
`TestEntityData`：EntityData 空壳子类——**不走基类 OnCreate**，不创建属性/效果/技能、不进 BattleManager 容器，只装配 EntityAnim（`Init` + `SetType(testAnimType)` + `SetWeapon(testWeaponId, testWeaponDisplay)` + `DoSpawn`——空壳没有 entity 表 行，动作集与武器走 Inspector 上的三个测试字段）+ 刚体（对齐 SetupBody 参数）+ 胶囊碰撞体（EntityModelInfo.BuildCapsuleCollider）；`OnTickMove` 复刻 PlayerEntityData 真人分支的转向推进
**为什么必须继承 EntityData**：`AnimRunEvent` 等行为脚本 `data == null` 即不声明速度——动画声明链路（`anim.SetVelocityForward` → `data.SetVelocityForward`）必须挂一个真实 EntityData 才通
**坑：SetupTestBody 必须把刚体写入基类字段 `rb`**——基类的 `SetVelocityForward` / `TickVelocity` 入口都有 `if (rb == null) return;`，只配置局部变量不赋字段的表现为"动画照播、零位移、按 T 直写也无效"（2026-09-30 踩过）
其它注意：① 场景无 InfoManager 时驱动器自动补最小实例（落地检测 `EntityPhysics.GroundMask` 需要层号；ground_layer 优先取 Ground 层，无则 Default）；② 测试场景若没有相机对准角色，需强制 `Animator.cullingMode = AlwaysAnimate`（默认剔除模式在渲染器不可见时停更状态机，速度声明同样会断）；③ HUD（OnGUI）实时显示 state/grounded/moveInput/v，按住 T 绕过动画声明直写 3m/s 用于二分定位断点
