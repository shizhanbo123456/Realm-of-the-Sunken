# 地形生成（战斗地图）

> 代码位置：`Assets/Scripts/TerrainGenerator/`
> 菜单：`Tools/模块化地形/建筑生成器`（工具窗口）、`Tools/模块化地形/碰撞体预处理/*`（素材预处理）

本文只描述**当前实现**。改代码前先看第 10 节「约束与坑」和第 11 节「扩展指南」。

---

## 1. 这个系统做什么

输入生成参数配表 `terrain_generation.csv`、素材表 SO 与只带 `seed` / `version` 的标识 SO，输出**一份纯数据**：

- 一张由房间、走廊、围墙组成的战斗地图；
- 每个物件的位置 / 朝向 / 缩放 / 用的是素材表里哪一项；
- 若干战斗点位（主守护点、副守护点、普通点、防御塔点）。

生成过程**不实例化任何预制体**。客户端由 `TerrainPropCuller` 按区块从对象池取用：区块进视野取、出视野还，实例全程不销毁；服务器不做剔除，由生成层一次性铺满整张图（且除地面外只留碰撞体）。

不负责的部分：地形贴图、Unity `Terrain` 组件、单位寻路网格烘焙。

## 4. 布局生成（BuildingField）

### 4.1 数据结构

| 成员 | 含义 |
| --- | --- |
| `Layer[x,z]` | `-1` 无地面，`0` 有地面（当前全图同一高度） |
| `Region[x,z]` | `>=0` 房间号，`-1` 走廊，`-2` 虚空 |
| `Door[x,z]` | 该格是门洞（不建墙） |
| `Rooms` | 房间矩形列表 |
| `Points` | 点位列表 |
| `SizeX / SizeZ` | 地图格数 |

### 4.2 切分房间

- BSP 递归二分，**切到每个叶子两条边都 ≤ `max_room_cells`** 为止（边长不足 `min_room_cells × 2` 时不再切）；
- 切点限制在**中间 1/3**（`PickCut`），避免 `2 + 62` 这类细长条，递归深度为 O(log)；
- `min_room_cells * 2 > max_room_cells` 时自动把 min 收到 `max_room_cells / 2` 并 `LogWarning`；
- 每个叶子按 `room_margin` 内缩得到房间矩形。

### 4.3 走廊

- 沿 BSP 兄弟节点递归连通（`Connect`），路径为 L 形，宽度在 `1 ~ corridor_max_width` 之间每条独立随机；
- 起点用 `BorderPoint`：在朝向对方的房间边上随机取点，不是房间中心；
- `EnsureCycles`：每个房间强制再连上最近的 `min_room_links` 个未连通房间，形成环路；
- `AddExtraLinks`：按 `extra_link_chance` 再补随机环路；
- `PruneStubs`：迭代删除只有 1 个邻居、且不贴房间的走廊末端（死胡同）。

### 4.4 房间形状

`NotchRooms` 按 `notch_chance` 在房间某个角挖掉一块，产生 L 形房间，避免所有房间都是同尺寸矩形。

### 4.5 门洞与墙

| 方法 | 判定 |
| --- | --- |
| `MarkDoors` | `open_along_corridor = true` 时，房间格只要贴着走廊就整段开门；`false` 时只有走廊端点开门 |
| `NeedWallAt(x,z,d)` | 邻格无地面 → 建墙；房间格朝走廊且不是门洞 → 建墙；否则不建 |
| `IsOuterEdge(x,z,d)` | 邻格越界或无地面，即"地块外轮廓"（藤蔓只贴这种面） |
| `RegionGroup(x,z)` | 区域分组：房间用房间号，走廊用 8 格街区 `900000 + x/8*1000 + z/8`，保证同一区域取同一套素材 |

## 5. 点位选择（SelectPoints）

1. **空置度**：以"虚空格 + 走廊格"为障碍做多源 BFS，得到每格到最近障碍的曼哈顿距离 `openDist`；
2. **候选池**：有地面、`openDist >= point_open_radius`、且离地图边缘 `>= point_edge_margin` 格；
3. **主守护点 ×1**：在候选池里取 `-到中心距离*4 + min(空置度,12)` 最高者；
4. **副守护点 ×`sub_guard_count`**：硬性约束**离地图中心 ≤ 0.25 × 边长**，在圆内做最远点采样（互相尽量拉开），并要求与已有房间不同；
5. **普通点 ×`extra_point_min~Max`**：最远点采样，间距 `point_spacing`；
6. **防御塔点**：每个守护点周围 `[tower_min_distance, tower_max_distance]` 环形范围内取 `tower_count_per_guard` 个，按角度扇区均分，扇区内取离守护点最远者；候选不足时搜索半径 +2 递增，仍不足则 `LogWarning` 并少放。

点位在运行时是**空物体 + Gizmo**，不产生渲染开销，也不参与剔除（常驻）。

## 6. 尺寸与碰撞体约定

### 6.1 生成期只读 BoxCollider

`PrefabBounds.TryGet` 的实现是：

```csharp
BoxCollider box = prefab.GetComponent<BoxCollider>();   // 仅此一次，O(1)
if (box == null) { LogWarning("没有 BoxCollider，已跳过"); return false; }
bounds = new Bounds(box.center * scale, box.size * scale);
```

**不做任何网格遍历**，结果按 prefab 缓存。缺 BoxCollider 会明确告警并跳过该件，不会静默改用其它算法。

`BuildPlan` 结束时输出一行汇总日志，写明本次只用 BoxCollider、无网格计算。

### 6.2 哪些类型需要 BoxCollider

| 需要（读尺寸） | 不需要（纯生成点） |
| --- | --- |
| 建筑、装饰、摆件、灌木、障碍 | 藤蔓、障碍装饰、漂浮装饰、鱼群 |
| 用于底面对齐、互相间距、障碍重叠判定 | 只用格子坐标与参数算位置 |

### 6.3 碰撞体预处理菜单

`Tools/模块化地形/碰撞体预处理/{类别}` 与「全部处理」：读素材表 → 逐个 `LoadPrefabContents` → 清空所有 Collider → 在根物体写一个 BoxCollider（尺寸由一次 Mesh 包围盒算出）→ 保存。

| 模式 | 含义 | 适用 |
| --- | --- | --- |
| `BoxEnabled` | 写启用的 BoxCollider | 地面、围栏、矮/高石柱、支撑、建筑、装饰、障碍 |
| `BoxDisabled` | 写的 BoxCollider `enabled = false`，只供生成期读尺寸；服务器铺设与 NavMesh 烘焙都会跳过这类物件 | 灌木、摆件 |
| `RemoveOnly` | 只删碰撞体，不加 | 藤蔓、障碍装饰、漂浮装饰、鱼群 |

服务器铺设时的过滤**不读这张表**：它按预制体上是否真有 `enabled` 的 `Collider` 现算（见 8.2），改模式后不用同步改生成代码。

这是**唯一**会遍历网格的地方，只在手动执行菜单时运行，有进度条与汇总日志。

## 7. 素材表与摆放规则

### 7.1 素材表（BuildingKitSet）

| 列表 | 类别枚举 | 摆放规则 |
| --- | --- | --- |
| `ground` | `Ground` | 每格一块，底面中心对齐格心 |
| `fences` | `Fence` | 沿 `NeedWallAt` 的边，位于边中点，东西向的边转 90° |
| `shortPosts` / `tallPosts` | `PostShort` / `PostTall` | 每段栏杆的两个端点各一个，格角去重；同区域固定高或矮（`UseTallPost`） |
| `supports` | `Support` | 只在**高石柱**下方，原点为柱顶中心，放在地块下表面 y=0 |
| `buildings` | `Building` | 格心，密度 `cells_per_building` |
| `decorations` | `Decoration` | 同建筑，密度 `cells_per_decoration` |
| `props` | `Prop` | 同上，`cells_per_prop` |
| `bushes` | `Bush` | 同上，`cells_per_bush`，朝向全随机 |
| `vines` | `Vine` | 只贴 `IsOuterEdge` 的临空外墙，位置取围栏中点，Y 在 `ground_height*[0.5,1]` |
| `obstacles` | `Obstacle` | 锚在虚空格，允许压地面但不能整块在地面上，底面 Y 在 `obstacle_base_min_y ~ obstacle_base_max_y` |
| `obstacleDecorations` | `ObstacleDecor` | 虚空格 + 格内随机偏移，Y 在 `0~ground_height` |
| `floatingDecorations` | `Floating` | 全图随机 XZ，Y = `ground_height + rand*floating_extra_height` |
| `fishSchools` | `Fish` | 同漂浮装饰，朝向固定 |

其它字段：`fenceYawOffset`、`vineYawOffset`（朝向补正）、`variantSeed`（整体换一套搭配）。

### 7.2 坐标约定（重要）

数据里的坐标**直接就是地图坐标**，`c = cell_size`，`cx0 = MapMin + c/2`（0 号格中心）：

- 格子 (x,z) 中心 = `(cx0 + x*c, cz0 + z*c)`
- 格子最小角 = 中心 `- c/2`，地形在 XZ 上从 `MapMin` 起铺，范围 `MapMin ~ MapMin + SizeX*c`
- 该式为**格心**，不是格角——写围墙/石柱位置时最容易在这里多偏半格

`TerrainRoot` 与 `TerrainCuller` 都在世界原点，不再抬高或偏移，数据坐标即世界坐标。

### 7.3 生成顺序

1. 地面 → 2. 围栏 → 3. 石柱 + 支撑 → 4. 建筑 → 5. 装饰 → 6. 摆件 → 7. 灌木 → 8. 藤蔓 → 9. 障碍 → 10. 障碍装饰 → 11. 漂浮装饰 → 12. 鱼群

- 4~7 是"后放的避让先放的"：间距 = 两者包围盒水平半径之和 + `prop_gap_padding`；
- 4~7 的落点受 `random_prop_position` 控制：配 1 时随机地板格 + 格内随机偏移（同格可多件），配 0 时每格居中一件；
- 障碍之间允许重叠，但重叠面积 ÷ 较小者面积 ≥ 0.5 时跳过；
- 障碍与建筑的**生成点格**会记入 `reserved`，漂浮装饰与鱼群落在同一格时跳过（只判生成点，不判模型体积）。

## 8. 数据与运行时

### 8.1 缓存文件

- 路径：`StreamingAssets/TerrainGenerator/terrain_{seed}_v{version}.bin`
- 格式：二进制，magic `TGRN`，格式版本 1
- 内容：seed、version、cell_size、ground_height、sizeX/sizeZ、物件数组（kind / prefabIndex / position / yaw / scale）、点位数组（cell / kind）
- 单条 25 字节；按当前配置（64×64、密度见第 9 节）约 11.8k 个物件、21 个点位，约 290 KB

### 8.2 生成入口

```csharp
// 客户端：建 TerrainRoot 与 Points，物件交给 Culler 按区块流式取还
TerrainPropCuller TerrainGenerator.Generate(BuildingSettings, BuildingKitSet, out Transform contentRoot)

// 服务器：一次性铺满整张图（除地面外只留碰撞体），不建 Culler
void TerrainGenerator.GenerateServer(BuildingSettings, BuildingKitSet, out Transform contentRoot)
```

| 场景 | 行为 |
| --- | --- |
| 编辑器未播放 | `Bake` 写 bin，**返回 null**（调用方忽略返回值） |
| 运行时有缓存 | `TryLoad` 读取 seed+version 对应的 bin |
| 运行时无缓存 | `LogWarning` 后现场生成（不写盘） |
| 客户端 | `TerrainRoot` 建在**场景根**，世界位置为原点（数据已是地图坐标）；`TerrainCuller` 同为**场景根**独立物体；`Points` 由生成层建好后 `Initialize(data, kit, root.transform)`，返回该 Culler |
| 服务器 | 只建 `TerrainRoot` 与 `Points`，**不建 Culler**；`TerrainAssembler.SpawnColliderOnly` 逐个物件实例化并按下面的规则精简 |

服务器铺设规则（`TerrainAssembler.SpawnColliderOnly`）：

- 只铺预制体上有 `enabled` 碰撞体的类别（灌木 / 藤蔓 / 障碍装饰 / 漂浮装饰 / 鱼群被跳过），判定只看 `enabled`，不看 `activeInHierarchy`；
- 地面（`TerrainItemKind.Ground`）原样保留模型；
- 其余类别实例化后立即精简：子物体先 `SetActive(false)` 再 `Destroy`（`Destroy` 延迟到帧末，不关会多渲染一帧），根上的 `MeshRenderer` 全部销毁，根 `BoxCollider` 保持原样——碰撞体统一在根物体上（见第 6 节），所以销毁子物体不影响物理；
- 精简后的场景里只有地面带模型，房屋 / 围栏 / 石柱 / 障碍等只剩根物体 + 碰撞体，供 `TerrainSpawns` 点位与 `ground_layer` 向下射线使用。

### 8.3 Culler（客户端剔除）

- 场景层级：`TerrainRoot`（内容根，**场景根物体**，`ModularTerrainGenerator` 不充当它的父级）与 `TerrainCuller`（**场景根独立物体，无父级、无子物体**）互不为父子。**判定中心是主相机位置**（`Camera.main.transform.position`），与 Culler 自身的 transform 无关；移动 Culler 不会带走任何地形，也不需要外部每帧写它的位置。主相机直接取 `Camera.main`，**不做缺失兜底**——场景必须有 MainCamera；
- `TerrainRoot` 下分三块：`Pool`（空闲实例，全部 `SetActive(false)`）、`Chunk_{x}_{z}`（视野内区块，实例挂这里）、`Points`（点位，常驻不剔除）；
- `Initialize` 只按区块把物件定义分组进 `chunkDefs`（kind / prefabIndex / 地图坐标 / yaw / scale），**不实例化任何预制体**；
- 区块进入判定半径才 `LoadChunk`：按该区块的定义逐件 `Take`（池命中直接复用，池空才 `Instantiate`），设好位置 / 朝向 / 缩放后 `SetActive(true)`；
- 区块离开判定半径 `UnloadChunk`：逐件 `SetActive(false)`、挂到 `Pool`、压回按预制体分桶的空闲栈；`Chunk_{x}_{z}` 节点保留待复用，不销毁；
- 池按预制体分桶，同类型物件可跨区块复用；命中路径只有一次 `SetParent` + transform 赋值，零 Instantiate、零 GC；
- `LateUpdate` 中累加 `Time.unscaledDeltaTime`，未到 `checkInterval`（默认 0.25s）直接 return；到了间隔但**相机位移**小于 `quietDistance`（默认 1m）且半径未变时也直接 return（静默），不做任何遍历；
- 判定：区块中心（`MapMin + (i + 0.5) × chunkSize`）到**主相机位置**的距离 ≤ `visibleDistance + chunkSize` 视为可见，只对可见性翻转的区块做取还，不做增量差分；
- `chunkSize` 取配表 `terrain_chunk_size`（当前 24），`visibleDistance` 默认 50 → 判定半径 74m。地形边长是 `cell_size × mapCells`（当前 6×64 = 384m），半径超过地形半对角（约 271m）时以任何相机位置都会覆盖全部区块，初始化会打一条警告；
- 贴边物件的世界坐标可能因浮点误差正好等于 `MapMax`，判为图外；这类坐标按最近区块夹取（越界轴取 `0` 或 `chunkCount - 1`，未越界轴保留原索引），与普通物件一样跟随区块显隐；
- `ModularTerrainGenerator.Clear()` 与工具窗口的「清空场景」会删除 Culler 节点与 `TerrainRoot`；服务器没有 Culler，内容根由 `ModularTerrainGenerator` 自己记着。

### 8.4 使用流程

1. 编辑器打开工具窗口 → **预览布局** 看平面；
2. 满意后点 **烘焙数据**，生成 bin；
3. **客户端**：进战斗加载时（`ClientLoadingManager.OnLoadingStart`，即 `SCLoadingStart` 到达、加载界面已显示）调 `Tool.ModularTerrainGenerator.Generate()` 读数据 → 建内容根与点位、把物件定义分进区块 → 返回 Culler；之后由 Culler 按主相机位置取还区块，物件在区块首次进入视野时才实例化；
4. **服务器**：场景启动时（`ModularTerrainGenerator.Start`，判定 `Tool.Instance.isServer`）调 `GenerateServer()`，一次性铺满整张图、只放有启用碰撞体的类别，除地面外只保留根物体与碰撞体，不建 Culler；
5. **销毁**：客户端离开战斗页（`BattlePage.Exit`：退出战斗回首页、结算后回大厅）调 `Tool.ModularTerrainGenerator.Clear()`，Culler 与 `TerrainRoot` 一起销毁、`TerrainSpawns` 复位；服务端启动生成后不再销毁；
6. 地形不会跟着相机移动，只切换可见区块。

### 8.5 TerrainSpawns（点位出口）

- `TerrainSpawns.Build(data)` 在 `TerrainGenerator.Generate` 读数据后调用，`ModularTerrainGenerator.Clear()` 调 `Reset()`；
- 点位来源：主守护点 ×1、副守护点（下标 = 雕像 value）、防御塔位（每个守护点 3 个）、普通点位派生出的防守出生点（离主守护点最近）、进攻出生点（最远）、中立雕像候选（其余）；
- `TrySampleGroundY` / `TryGetGroundPos` / `TrySampleSpawnPoint(InRing)` 全部走 `InfoManager.ground_layer` 层的向下射线，命中高度与 `ground_height` 相差 ≤0.5m 才算合法；未命中即失败（不兜底）。

### 8.6 NavMesh 烘焙与注入

- 地形是运行期生成的，编辑器烘焙时场景里没有物件可烘，所以走「工具窗口烘一次 → 存 Resources → 运行时注入」：
- 面板按钮「烘焙 NavMesh」先检查场景是否干净：任何 `MeshFilter` / `SkinnedMeshRenderer` / `Terrain` / `Collider` 都算污染（含上次运行留下的地形），不干净直接报错终止，并把第一个污染对象的名字打出来；
- 场景干净时用 `TerrainAssembler.SpawnColliderOnly` 按服务器那套铺一次地形（只铺有启用碰撞体的类别、除地面外只留根碰撞体），所以装饰物不会参与烘焙；
- 烘焙：`SpawnColliderOnly(..., stripMeshes: false)` 铺一遍——**类别过滤照旧**（只铺有启用碰撞体的物件），但保留完整网格；然后遍历生成物下所有 `MeshFilter`，按 `shape = Mesh + mesh + localToWorldMatrix` 合成 `NavMeshBuildSource`，交给 `NavMeshBuilder.BuildNavMeshData(...)`；agent 参数取 `NavMesh.GetSettingsByID(0)`，bounds 取所有 `MeshRenderer.bounds` 的并集外扩 2m，Y 夹到「地面高度 ±6m」；
- 不要改回 `CollectSources(PhysicsColliders)`（编辑器态刚生成的碰撞体没同步进物理场景，会收错）或 `BoxCollider` 包围盒（每个物件糊成实心块，门洞/柱隙全丢）；
- 存盘：`Assets/Resources/Nav/NavMesh-Terrain.asset`，路径常量在 `TerrainNavMesh.Folder` / `AssetName`，每次烘焙覆盖；
- 烘完 `DestroyImmediate` 掉临时根，场景恢复干净；
- 运行时客户端与服务器一样：`TerrainGenerator` 建好内容根后调 `TerrainNavMesh.Attach`，在 `TerrainRoot` 下挂 `NavMeshSurface`，`navMeshData = Resources.Load<NavMeshData>("Nav/NavMesh-Terrain")` 后 `AddData()`；资源缺失直接 `LogError`（不兜底），此时所有 `NavMesh.CalculatePath` 都会失败、AI 不动；
- 改 `seed` / `version` 或调整素材表后必须重新烘一次，否则寻路用的是旧地图的导航面。

## 9. 参数速查（terrain_generation.csv）

全部来自 `StreamingAssets/ConfigData/terrain_generation.csv`；`seed` / `version` 不在此表，仍在 `Config/BuildingSettings.asset`。

| 分组 | 字段 | 作用 |
| --- | --- | --- |
| 网格 | `cell_size` / `ground_height` | 格子边长、地块高度（可行走面 Y） |
| 网格 | `map_cells_xz` | 地图格数（X 与 Z 相同） |
| 房间 | `max_room_cells` / `min_room_cells` / `room_margin` | 房间尺寸与内缩 |
| 房间 | `corridor_max_width` / `min_room_links` / `extra_link_chance` / `notch_chance` / `open_along_corridor` | 走廊与房间形态 |
| 点位 | `point_open_radius` / `point_edge_margin` | 空置判定半径、离边距离 |
| 点位 | `sub_guard_count` | 副守护点数量 |
| 点位 | `extra_point_min` / `extra_point_max` / `point_spacing` | 普通点数量与间距 |
| 点位 | `tower_count_per_guard` / `tower_min_distance` / `tower_max_distance` / `tower_spacing` | 防御塔点 |
| 摆放 | `cells_per_building` / `cells_per_decoration` / `cells_per_bush` / `cells_per_prop` | 平均多少格放一个（0 = 不生成） |
| 摆放 | `prop_gap_padding` / `random_prop_position` | 间距余量、随机落点开关 |
| 摆放 | `vine_chance` | 每条临空外墙边贴藤蔓的概率 |
| 障碍 | `cells_per_obstacle` / `obstacle_base_min_y` / `obstacle_base_max_y` | 数量与底面高度范围 |
| 障碍 | `cells_per_obstacle_decoration` / `prop_scale_range` | 障碍装饰数量、随机缩放幅度（0.5 = 0.5~1.5 倍） |
| 漂浮 | `cells_per_floating_decoration` / `cells_per_fish_school` / `floating_extra_height` | 数量与抬升范围 |

数量公式：`RoundToInt(区域格子数 / cells_per_xxx)`。建筑/装饰/摆件/灌木用**地板格数**，障碍/障碍装饰用**虚空格数**，漂浮装饰/鱼群用**地图总格数**。

### 9.1 地图范围与区块（global_variables.csv）

| key | 示例 | 含义 |
| --- | --- | --- |
| `terrain_size` | `0;384` | XZ 范围 `最小;最大`，边长 = 最大 − 最小 |
| `terrain_height` | `0;32` | Y 范围 `最小;最大`，高度 = 最大 − 最小 |
| `terrain_chunk_size` | `24` | 区块边长（米） |
| `terrain_chunk_size_count` | `16` | 每边区块数 |

加载时校验 `chunk_size × count == 边长`，不满足直接抛 `FormatException`。地形代码不设常量类：地图起点、边长、区块尺寸与块数都在调用点直接读这四项配表。

### 9.2 TerrainCuller 参数

运行时创建（只有客户端有），字段默认值即生效值。

| 字段 | 默认 | 作用 |
| --- | --- | --- |
| `visibleDistance` | 50 | 可见半径（米，以主相机为心），实际判定半径 = 该值 + `chunkSize`（配表 `terrain_chunk_size`，当前 24） |
| `checkInterval` | 0.25 | 判定间隔（秒），`0` = 每帧判定 |
| `quietDistance` | 1 | 静默阈值（米），相机位移不足该值且半径未变时本轮直接 return |

## 10. 约束与坑

1. **改生成逻辑或调整素材表条目顺序后，必须递增 `version`**。数据里存的是"类别 + 列表下标"，素材表顺序变了旧数据会指向错件。
2. **生成期禁止网格测量**。需要尺寸的类型必须有根物体 BoxCollider（跑碰撞体预处理）；没有就告警跳过，不会退化成遍历网格。
3. 剔除 / 池化粒度是配表 `terrain_chunk_size`（当前 24m）的区块：整块一起取用与归还，块内物件不单独判定，跨越边界时可能有一次 `Instantiate` 或 `SetParent` 的尖峰。`visibleDistance` 要比相机可视范围略大，否则视野边缘会看到区块被回收。
4. 地图范围与区块全部来自 `global_variables.csv`（见 9.1）：`MapMin` 取 `terrain_size` 的最小值，`chunkCount` 直接取 `terrain_chunk_size_count`，`chunkSize` 取 `terrain_chunk_size`。地形生成区域的最小角对齐 `MapMin`，尺寸由 `terrain_generation.csv` 的 `map_cells_xz × cell_size` 决定；两者不一致时，超出地图的物件按最近区块夹取，仍随区块一起回收。
5. 点位是空物体 + Gizmo，正式包里没有可见表现，需要的话由战斗逻辑自行读 `Points` 子节点。
6. 数据文件写在 `StreamingAssets`，属于资源目录，别在运行时写入（当前运行期生成不落盘）。
7. `PrefabBounds` 的 `TryGetMeshBounds` 只允许编辑器工具调用；在运行时调用它会重新引入网格遍历。
8. **服务器启动即一次性铺满整张地形**（`GenerateServer`），物件全部实例化，启动会有一段明显卡顿与内存占用；这是"全图射线可用"的代价。只铺有启用碰撞体的类别，除地面外实例化后立即只剩根物体 + 根碰撞体，所以服务器场景里只有地面带模型。**该精简以"碰撞体在根物体上"为前提**（见第 6 节）：若某素材的碰撞体还挂在子物体（嵌套预制体里的，碰撞体预处理会告警跳过），销毁子物体会连碰撞体一起丢掉，新增素材后要先跑一遍碰撞体预处理。
9. 判定中心直接取 `Camera.main`：客户端在加载界面期间相机可能还在首页/大厅机位，首帧装载的是相机附近区块，相机移到战斗位姿后由 `LateUpdate` 自动换块，属正常行为。

## 11. 扩展指南

### 新增一类物件

1. `TerrainItemKind` 加枚举值；
2. `BuildingKitSet` 加列表 + 在 `GetList` 里补映射；
3. `PropPlacer`（或 `BuildingDecorator`）里加摆放函数，用 `Add(kit, items, kind, prefab, pos, yaw, scale)` 写数据；
4. `PropPlacer.PlacePlan` 里按需要的顺序调用；
5. `ColliderPreprocessor.Entries` 加一条（决定 BoxEnabled / BoxDisabled / RemoveOnly）与对应菜单；
6. **递增 `version`**，重新烘焙。

新增的类别不需要改 `TerrainPropCuller`：池按预制体分桶、区块按数据分组，类别只是数据里的一个枚举值。

### 新增一个生成参数

1. `terrain_generation.csv` 加一行 `key,说明,value`；
2. `ConfigManager.TerrainGenerationConfig` 加同名静态字段，并在 `Apply` 的 switch 里补一个 case（漏配会在加载时抛 `FormatException`）；
3. 生成代码直接读 `ConfigManager.TerrainGenerationConfig.xxx`；
4. 只改数值不必递增 `version`，改生成逻辑才需要。

### 调整地图形态

- 房间更密 → 减小 `max_room_cells`；
- 房间更规整/更碎 → 调 `notch_chance`；
- 路线更丰富 → 提高 `min_room_links` 与 `corridor_max_width`，保持 `open_along_corridor = 1`；
- 想改切分算法本身 → 动 `BuildingField.Split` 与 `PickCut`，其它层不依赖切分方式。
