# 地形生成（战斗地图）

> 代码位置：`Assets/Scripts/TerrainGenerator/`
> 菜单：`Tools/模块化地形/建筑生成器`（工具窗口）、`Tools/模块化地形/碰撞体预处理/*`（素材预处理）

本文只描述**当前实现**。改代码前先看第 8 节「扩展指南」和第 10 节「约束与坑」。

---

## 1. 这个系统做什么

输入两三个 ScriptableObject（生成参数 + 素材表），输出**一份纯数据**：

- 一张由房间、走廊、围墙组成的战斗地图；
- 每个物件的位置 / 朝向 / 缩放 / 用的是素材表里哪一项；
- 若干战斗点位（主守护点、副守护点、普通点、防御塔点）。

生成过程**不实例化任何预制体**。实例化在运行时由 `TerrainPropCuller` 按区块动态完成。

不负责的部分：地形贴图、Unity `Terrain` 组件、Landscape 区块系统本身、单位寻路网格烘焙。

## 4. 布局生成（BuildingField）

### 4.1 数据结构

| 成员 | 含义 |
| --- | --- |
| `Layer[x,z]` | `-1` 无地面，`0` 有地面（当前全图同一高度） |
| `Region[x,z]` | `>=0` 房间号，`-1` 走廊，`-2` 虚空 |
| `Door[x,z]` | 该格是门洞（不建墙） |
| `Rooms` | 房间矩形列表 |
| `Points` | 点位列表 |
| `SizeX / SizeZ` | 地图格数 |

### 4.2 切分房间

- BSP 递归二分，**切到每个叶子两条边都 ≤ `maxRoomCells`** 为止；
- 切点限制在**中间 1/3**（`PickCut`），避免 `2 + 62` 这类细长条，递归深度为 O(log)；
- `minRoomCells * 2 > maxRoomCells` 时自动把 min 收到 `maxRoomCells / 2` 并 `LogWarning`；
- 每个叶子按 `roomMargin` 内缩得到房间矩形。

### 4.3 走廊

- 沿 BSP 兄弟节点递归连通（`Connect`），路径为 L 形，宽度在 `1 ~ corridorMaxWidth` 之间每条独立随机；
- 起点用 `BorderPoint`：在朝向对方的房间边上随机取点，不是房间中心；
- `EnsureCycles`：每个房间强制再连上最近的 `minRoomLinks` 个未连通房间，形成环路；
- `AddExtraLinks`：按 `extraLinkChance` 再补随机环路；
- `PruneStubs`：迭代删除只有 1 个邻居、且不贴房间的走廊末端（死胡同）。

### 4.4 房间形状

`NotchRooms` 按 `notchChance` 在房间某个角挖掉一块，产生 L 形房间，避免所有房间都是同尺寸矩形。

### 4.5 门洞与墙

| 方法 | 判定 |
| --- | --- |
| `MarkDoors` | `openAlongCorridor = true` 时，房间格只要贴着走廊就整段开门；`false` 时只有走廊端点开门 |
| `NeedWallAt(x,z,d)` | 邻格无地面 → 建墙；房间格朝走廊且不是门洞 → 建墙；否则不建 |
| `IsOuterEdge(x,z,d)` | 邻格越界或无地面，即"地块外轮廓"（藤蔓只贴这种面） |
| `RegionGroup(x,z)` | 区域分组：房间用房间号，走廊用 8 格街区 `900000 + x/8*1000 + z/8`，保证同一区域取同一套素材 |

## 5. 点位选择（SelectPoints）

1. **空置度**：以"虚空格 + 走廊格"为障碍做多源 BFS，得到每格到最近障碍的曼哈顿距离 `openDist`；
2. **候选池**：有地面、`openDist >= pointOpenRadius`、且离地图边缘 `>= pointEdgeMargin` 格；
3. **主守护点 ×1**：在候选池里取 `-到中心距离*4 + min(空置度,12)` 最高者；
4. **副守护点 ×`subGuardCount`**：硬性约束**离地图中心 ≤ 0.25 × 边长**，在圆内做最远点采样（互相尽量拉开），并要求与已有房间不同；
5. **普通点 ×`extraPointMin~Max`**：最远点采样，间距 `pointSpacing`；
6. **防御塔点**：每个守护点周围 `[towerMinDistance, towerMaxDistance]` 环形范围内取 `towerCountPerGuard` 个，按角度扇区均分，扇区内取离守护点最远者；候选不足时搜索半径 +2 递增，仍不足则 `LogWarning` 并少放。

点位在运行时是**空物体 + Gizmo**，不产生渲染开销，也不参与剔除（常驻）。

## 6. 尺寸与碰撞体约定

### 6.1 生成期只读 BoxCollider

`PrefabBounds.TryGet` 的实现是：

```csharp
BoxCollider box = prefab.GetComponent<BoxCollider>();   // 仅此一次，O(1)
if (box == null) { LogWarning("没有 BoxCollider，已跳过"); return false; }
bounds = new Bounds(box.center * scale, box.size * scale);
```

**不做任何网格遍历**，结果按 prefab 缓存。缺 BoxCollider 会明确告警并跳过该件，不会静默改用其它算法。

`BuildPlan` 结束时输出一行汇总日志，写明本次只用 BoxCollider、无网格计算。

### 6.2 哪些类型需要 BoxCollider

| 需要（读尺寸） | 不需要（纯生成点） |
| --- | --- |
| 建筑、装饰、摆件、灌木、障碍 | 藤蔓、障碍装饰、漂浮装饰、鱼群 |
| 用于底面对齐、互相间距、障碍重叠判定 | 只用格子坐标与参数算位置 |

### 6.3 碰撞体预处理菜单

`Tools/模块化地形/碰撞体预处理/{类别}` 与「全部处理」：读素材表 → 逐个 `LoadPrefabContents` → 清空所有 Collider → 在根物体写一个 BoxCollider（尺寸由一次 Mesh 包围盒算出）→ 保存。

| 模式 | 含义 | 适用 |
| --- | --- | --- |
| `BoxEnabled` | 写启用的 BoxCollider | 地面、围栏、矮/高石柱、支撑、建筑、装饰、摆件、障碍 |
| `BoxDisabled` | 写的 BoxCollider `enabled = false`，只供生成期读尺寸 | 灌木 |
| `RemoveOnly` | 只删碰撞体，不加 | 藤蔓、障碍装饰、漂浮装饰、鱼群 |

这是**唯一**会遍历网格的地方，只在手动执行菜单时运行，有进度条与汇总日志。

## 7. 素材表与摆放规则

### 7.1 素材表（BuildingKitSet）

| 列表 | 类别枚举 | 摆放规则 |
| --- | --- | --- |
| `ground` | `Ground` | 每格一块，底面中心对齐格心 |
| `fences` | `Fence` | 沿 `NeedWallAt` 的边，位于边中点，东西向的边转 90° |
| `shortPosts` / `tallPosts` | `PostShort` / `PostTall` | 每段栏杆的两个端点各一个，格角去重；同区域固定高或矮（`UseTallPost`） |
| `supports` | `Support` | 只在**高石柱**下方，原点为柱顶中心，放在地块下表面 y=0 |
| `buildings` | `Building` | 格心，密度 `cellsPerBuilding` |
| `decorations` | `Decoration` | 同建筑，密度 `cellsPerDecoration` |
| `props` | `Prop` | 同上，`cellsPerProp` |
| `bushes` | `Bush` | 同上，`cellsPerBush`，朝向全随机 |
| `vines` | `Vine` | 只贴 `IsOuterEdge` 的临空外墙，位置取围栏中点，Y 在 `groundHeight*[0.5,1]` |
| `obstacles` | `Obstacle` | 锚在虚空格，允许压地面但不能整块在地面上，底面 Y 在 `obstacleBaseMinY~MaxY` |
| `obstacleDecorations` | `ObstacleDecor` | 虚空格 + 格内随机偏移，Y 在 `0~groundHeight` |
| `floatingDecorations` | `Floating` | 全图随机 XZ，Y = `groundHeight + rand*floatingExtraHeight` |
| `fishSchools` | `Fish` | 同漂浮装饰，朝向固定 |

其它字段：`fenceYawOffset`、`vineYawOffset`（朝向补正）、`variantSeed`（整体换一套搭配）。

### 7.2 坐标约定（重要）

地图以**中心为原点**排布，`c = cellSize`，`ox = (SizeX-1)*c/2`：

- 格子 (x,z) 中心 = `(x*c - ox, z*c - oz)`
- 格子最小角 = 中心 `- c/2`
- 该式为**格心**，不是格角——写围墙/石柱位置时最容易在这里多偏半格

### 7.3 生成顺序

1. 地面 → 2. 围栏 → 3. 石柱 + 支撑 → 4. 建筑 → 5. 装饰 → 6. 摆件 → 7. 灌木 → 8. 藤蔓 → 9. 障碍 → 10. 障碍装饰 → 11. 漂浮装饰 → 12. 鱼群

- 4~7 是"后放的避让先放的"：间距 = 两者包围盒水平半径之和 + `propGapPadding`；
- 4~7 的落点受 `randomPropPosition` 控制：勾选时随机地板格 + 格内随机偏移（同格可多件），取消时每格居中一件；
- 障碍之间允许重叠，但重叠面积 ÷ 较小者面积 ≥ 0.5 时跳过；
- 障碍与建筑的**生成点格**会记入 `reserved`，漂浮装饰与鱼群落在同一格时跳过（只判生成点，不判模型体积）。

## 8. 数据与运行时

### 8.1 缓存文件

- 路径：`StreamingAssets/TerrainGenerator/terrain_{seed}_v{version}.bin`
- 格式：二进制，magic `TGRN`，格式版本 1
- 内容：seed、version、cellSize、groundHeight、sizeX/sizeZ、物件数组（kind / prefabIndex / position / yaw / scale）、点位数组（cell / kind）
- 单条约 25 字节；64×64 图约 5~6k 物件，约 150~250 KB

### 8.2 生成入口

```csharp
TerrainPropCuller TerrainGenerator.Generate(BuildingSettings, BuildingKitSet, Transform parent = null)
```

| 场景 | 行为 |
| --- | --- |
| 编辑器未播放 | `Bake` 写 bin，**返回 null**（调用方忽略返回值） |
| 运行时有缓存 | `TryLoad` 读取 seed+version 对应的 bin |
| 运行时无缓存 | `LogWarning` 后现场生成（不写盘） |
| 两种情况都成功 | `TerrainRoot` 挂到 `parent` 下，世界位置取地形半尺寸 `(sizeX*cellSize/2, 0, sizeZ*cellSize/2)`，使**生成区域的最小角贴世界原点**；`TerrainCuller` 建在**场景根**（无父级、无子物体），初始位置与 `TerrainRoot` 相同；调用 `Initialize(data, kit, root.transform)`，返回该 Culler |

### 8.3 Culler

- 场景层级：`TerrainRoot`（内容根，挂在 `ModularTerrainGenerator.container` 下）与 `TerrainCuller`（**场景根独立物体，无父级、无子物体**）互不为父子。`TerrainCuller` 的 transform 纯粹是显隐判定中心，移动它不会带走任何地形；
- 区块划分与物件数据在 `Initialize` 时只做分组（`chunkDefs`），**不实例化任何预制体**；
- 区块进入视野才调用 `LoadChunk`：按该区块的物件定义从池里取实体（池空则 `Instantiate`，否则复用），设好位置/朝向/缩放后 `SetActive(true)`；
- 区块离开视野调用 `UnloadChunk`：整块每个实例 `SetActive(false)`、挂到 `TerrainRoot/Pool`，压回按预制体分桶的空闲栈；区块节点 `Chunk_{x}_{z}` 保留待复用，不销毁；
- 池命中时零 Instantiate、零 GC，复用实例只是重设 transform；池按预制体分桶，所以同类型物件可以跨区块复用；
- `LateUpdate` 中累加 `Time.unscaledDeltaTime`，未到 `checkInterval`（默认 0.25s）直接 return；
- 到了间隔但位移小于 `quietDistance`（默认 1m）且半径未变时也直接 return（静默），不做任何遍历；
- 每轮判定是逐块比对：块中心到本物体的距离 ≤ `visibleDistance + chunkSize` 就 `SetActive(true)`，否则 `SetActive(false)`；不做增量差分也不缓存状态；
- 判定半径 = `visibleDistance + 40`。地形尺寸是 `cellSize × mapCells`（当前 6×64 = 384m，半对角约 271m），半径超过该值时任何位置都会覆盖全部区块，初始化会打一条警告；
- 点位挂在 `TerrainRoot/Points` 子节点，常驻不剔除；
- 落在 `Landscape` 地图范围外的物件挂 `TerrainRoot/OutOfMap`，始终显示并只告警一次；
- `ModularTerrainGenerator.Clear()` 与工具窗口的「清空场景」会同时删除 Culler 节点和它记录的 `ContentRoot`。

### 8.4 使用流程

1. 编辑器打开工具窗口 → **预览布局** 看平面；
2. 满意后点 **烘焙数据**，生成 bin；
3. 进播放模式，`ModularTerrainGenerator.Generate()`（或 `generateOnStart`）读取数据 → 生成 → 返回 Culler；
4. 每帧把 `TerrainCuller` 的 `transform.position` 写到玩家/相机的位置；地形不会跟着动，只切换可见区块。

## 9. 参数速查（BuildingSettings）

默认值以字段初始值为准；**实际生效值以资产 `Config/BuildingSettings.asset` 为准**。

| 分组 | 字段 | 作用 |
| --- | --- | --- |
| 网格 | `cellSize` / `groundHeight` | 格子边长、地块高度（可行走面 Y） |
| 网格 | `mapCellsX` / `mapCellsZ` | 地图格数 |
| 房间 | `seed` / `version` | 随机种子、数据版本号 |
| 房间 | `maxRoomCells` / `minRoomCells` / `roomMargin` | 房间尺寸与内缩 |
| 房间 | `corridorMaxWidth` / `minRoomLinks` / `extraLinkChance` / `notchChance` / `openAlongCorridor` | 走廊与房间形态 |
| 点位 | `pointOpenRadius` / `pointEdgeMargin` | 空置判定半径、离边距离 |
| 点位 | `subGuardCount` | 副守护点数量 |
| 点位 | `extraPointMin` / `extraPointMax` / `pointSpacing` | 普通点数量与间距 |
| 点位 | `towerCountPerGuard` / `towerMinDistance` / `towerMaxDistance` / `towerSpacing` | 防御塔点 |
| 摆放 | `cellsPerBuilding` / `cellsPerDecoration` / `cellsPerBush` / `cellsPerProp` | 平均多少格放一个（0 = 不生成） |
| 摆放 | `propGapPadding` / `randomPropPosition` | 间距余量、随机落点开关 |
| 摆放 | `vineChance` | 每条临空外墙边贴藤蔓的概率 |
| 障碍 | `cellsPerObstacle` / `obstacleBaseMinY` / `obstacleBaseMaxY` | 数量与底面高度范围 |
| 障碍 | `cellsPerObstacleDecoration` / `propScaleRange` | 障碍装饰数量、随机缩放幅度（0.5 = 0.5~1.5 倍） |
| 漂浮 | `cellsPerFloatingDecoration` / `cellsPerFishSchool` / `floatingExtraHeight` | 数量与抬升范围 |

数量公式：`RoundToInt(区域格子数 / cellsPerXxx)`。建筑/装饰/摆件/灌木用**地板格数**，障碍/障碍装饰用**虚空格数**，漂浮装饰/鱼群用**地图总格数**。

## 10. 约束与坑

1. **改生成逻辑或调整素材表条目顺序后，必须递增 `version`**。数据里存的是"类别 + 列表下标"，素材表顺序变了旧数据会指向错件。
2. **生成期禁止网格测量**。需要尺寸的类型必须有根物体 BoxCollider（跑碰撞体预处理）；没有就告警跳过，不会退化成遍历网格。
3. 剔除粒度是 40m 区块，块内物件不会单独判定，边缘可能整块闪现一次；`visibleDistance` 建议比相机可视范围大一些。
4. 地形位置与尺寸只由 `BuildingSettings` 的 `mapCells × cellSize` 决定：生成区域最小角贴世界原点，不随配表 `terrain_size` 居中。区块划分用 `Landscape.chunkSize`（常量 40m）。
5. 点位是空物体 + Gizmo，正式包里没有可见表现，需要的话由战斗逻辑自行读 `Points` 子节点。
6. 数据文件写在 `StreamingAssets`，属于资源目录，别在运行时写入（当前运行期生成不落盘）。
7. `PrefabBounds` 的 `TryGetMeshBounds` 只允许编辑器工具调用；在运行时调用它会重新引入网格遍历。

## 11. 扩展指南

### 新增一类物件

1. `TerrainItemKind` 加枚举值；
2. `BuildingKitSet` 加列表 + 在 `GetList` 里补映射；
3. `PropPlacer`（或 `BuildingDecorator`）里加摆放函数，用 `Add(kit, items, kind, prefab, pos, yaw, scale)` 写数据；
4. `PropPlacer.PlacePlan` 里按需要的顺序调用；
5. `ColliderPreprocessor.Entries` 加一条（决定 BoxEnabled / BoxDisabled / RemoveOnly）与对应菜单；
6. **递增 `version`**，重新烘焙。

### 调整地图形态

- 房间更密 → 减小 `maxRoomCells`；
- 房间更规整/更碎 → 调 `notchChance`；
- 路线更丰富 → 提高 `minRoomLinks` 与 `corridorMaxWidth`，保持 `openAlongCorridor = true`；
- 想改切分算法本身 → 动 `BuildingField.Split` 与 `PickCut`，其它层不依赖切分方式。
