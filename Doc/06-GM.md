# 06 GM 功能清单

本文与当前代码对齐（2026-11-28 核对）。三处权威来源：

- 配表：`Config/Source/gm_command.xlsx`（表头 4 行说明 + 数据行，主键 = GM 指令 id）
- 客户端：`Scripts/GM/GmCommandId.cs`、`Scripts/GM/GmCommandRunner.cs`、`Scripts/UI/Logic/GmPanel.cs`
- 服务器：`Scripts/GameController/BattleManagerGm.cs`（`BattleManager` 的 partial）

====================================================
一、入口

- 键盘：1 秒内连按 3 次 V 打开（`GameController/InputManager.TickGmHotkey`，`KeyCode.V`）。面板已打开、UI 抢占输入、正在编辑 FGUI 输入框、AI 接管时都不响应
- 关闭：只有面板右上角关闭按钮（`m_panel.m_close`），没有快捷键
- 每次打开都会 `BuildGroups()` 重建两级菜单并清空输出框
- 面板打开时 `UIManager.InputCaptured = true`，游戏输入被屏蔽
- 第二条通道：聊天面板「系统」页签的输入框按 GM 命令解析，格式 `命令名 副命令 [参数]`，如 `player tp 10,20,30`（见 `ChatPlugin.TrySendGmCommand`）

====================================================
二、面板结构

菜单与参数全部来自配表，代码里没有写死任何一条指令。

- 一级菜单 `m_firstMenu.m_button_list`（UI_GmButtonList）：按 `commandName` 去重，显示名取该组第一行的 `menuName`；`menuName` 缺失时 `GmCommandConfig.Bake` 直接抛异常
- 二级菜单 `m_secondMenu.m_button_list`：显示名取 `subMenuName`，顺序按配表主键升序
- 条目列表 `m_GmItemList`（GList，item = UI_GmItem），每条命令固定渲染 2 或 3 行：

| 下标 | m_type 档 | 内容 |
|---|---|---|
| 0 | 主栏 | `m_label_main_column` ← 配表 `des` |
| 1（仅 `paramType` 有值时才存在） | 副栏 | `m_label_sub_column` ← 配表 `paramDec`；`m_content` 档 ← 下表 |
| 最后一行 | 按钮 | 标题用 FGUI 设计稿文案（代码不覆盖），点击执行 |

- 输出框 `m_logOutput`：每次覆盖写入，非空文本同时进聊天系统栏（`Chat.AppendSystem`）

副栏内容档（`GmPanel.ContentPage`）：

| paramType | m_content 档名 | 输入控件 |
|---|---|---|
| 0 int | `int` | 输入框 `m_input`，整数 |
| 1 bool | `bool` | 复选框 `m_checkbox`（勾选 = 1，未勾 = 0） |
| 2 float | `float` | 输入框，小数 |
| 3 Vector2 | `v2` | 输入框，`(x,y)` 或 `x,y` |
| 4 Vector3 | `v3` | 输入框，`(x,y,z)` 或 `x,y,z` |

GList 会复用 item，所以渲染副栏时必须清上一条的状态：bool 清 `m_checkbox.selected`，其余清 `m_input.text`。

三、配表 gm_command 字段

| 列 | 变量 | 类型 | 说明 |
|---|---|---|---|
| 1 | key | int | 主键 = `GmCommandId` 常量值，也是 `CSGm.type` |
| 2 | commandName | string | 一级菜单分组键 |
| 3 | des | string | 主栏描述 |
| 4 | subcommand | string | 副命令，聊天通道用它定位；`(commandName, subcommand)` 全局唯一（`server/debug` 都有 `fps`，必须两个一起给） |
| 5 | paramType | int? | 空 = 无参数（不渲染副栏）；0 int / 1 bool / 2 float / 3 Vector2 / 4 Vector3 |
| 6 | paramDec | string | 副栏参数标签 |
| 7 | home | bool? | 未联网（Offline）时可用 |
| 8 | lobby | bool? | 已联网未开战（Lobby）时可用 |
| 9 | battle | bool? | 对局中（Battle）时可用 |
| 10 | menuName | string | 一级菜单显示名 |
| 11 | subMenuName | string | 二级菜单显示名，也用于提示文案 |

可用相位判定（`GmCommandRunner.Available`）：未联网取 `home ?? false`；联网后按 `NetworkManager.BattleRunning` 取 `battle` 或 `lobby`（都是 `?? false`）。连上 / 退出世界 / 重开 / 开战都会重建菜单，所以相位一变菜单立即跟着变。

====================================================
五、执行链路

1. 面板点按钮 / 聊天栏发命令 → `GmPanel.TryBuildArg`（面板）或 `ChatPlugin.TrySendGmCommand`（聊天）产出 `GmCommandRunner.Arg`
   - 面板：`paramType == bool` 读复选框（勾=1、未勾=0）；其余类型走 `TryParseParam` 解析输入框文本
   - 聊天：一律走 `TryParseParam` 解析文本，bool 接受 `1/0`、`true/false`、`t/f`
2. `GmCommandRunner.Run(row, arg, output)`
   - 先试 `RunLocal(row, arg, output)`，本地指令命中即返回（**不联网也生效**）
   - 否则要求 `Online`（`NetworkManager != null && CanSendWorldCommand`），不满足则输出「需要联网执行」
   - 满足则发 `CSGm { type = row.key, i, v0, v1, v2 }`
3. `NetworkManager.SendGm` → `CallFuncRpc(ServerReceiveGmLocal, SendTo.RoomOwner, Reliable)` → `BattleManager.ExecuteGm(clientId, gm)`
4. 服务器回包：`SendGmResult` → `SCGm { type, i, v0 }` → `ClientReceiveGmLocal` → `ClientEvent.OnGmResult(10311)` → `GmPanel.OnGmResult`

协议字段（`Transport/GM/CSGm.cs`、`SCGm.cs`）：

- `CSGm`：`type`（int，配表主键）+ `i`（int，装 int/bool）+ `v0~v2`（float，装 float 或 Vector3 分量；Vector2 只用 v0、v1）
- `SCGm`：`type`（int）+ `i`（int）+ `v0`（float）

`[Rpc]` 由 Ens 代码生成器产出，改协议必须重新生成，否则服务端收不到指令且无任何报错。

====================================================
七、开关类参数（paramType = 1）

- 面板副栏已换成复选框（GmItem 的 `bool` 内容档，页面切换自带显隐，代码不再手动设 visible）
- 语义是「目标状态」不是「取反」：勾选发 `i = 1`（开）、未勾发 `i = 0`（关），服务端一律按 `gm.i != 0` 判断
- 因此判断当前状态要看服务端行为，面板本身不显示开关的现存状态；要关掉一个已经打开的开关，必须把复选框取消勾选再点按钮
- 聊天通道仍用文本：`god fly 1` / `god fly 0`

====================================================
八、备注与已知问题

- 「存档-临时凭证」（id 39）是纯本地项，只开在 Home：`SaveManager.UseTemporaryCredential` 重随机令牌与名字、选角回 0、`ClientSettings.ResetToDefault`，并置 `temporaryCredential` 让 `Save()` 整局直接返回，退出不覆盖原有 PlayerPrefs 存档；同机双开时两个进程令牌不同，服务器不再互相顶号。换完需重新点连接才生效
- 「外挂-无敌」只把伤害判为 0，不免疫击退与受击动作；「外挂-极速」是移速 buff，死亡重建实体会丢，需要重开
- 「实体刷新-天使/恶魔雕像」的 `paramDec` 写了「刷新数量」，但服务端忽略数量、且场上最多 1 个中立雕像
- `paramDec` 在 id 33 / 34 / 35 / 36 这 4 行填了「客户端帧率 / 实体数量 / 客户端时间 / 模型面数」，但它们没有 `paramType`，面板不会渲染副栏，这些文本属于历史残留、当前无任何作用
- 主键 24 / 37 是空号（历史上删掉的条目），不影响运行
- 查询类都是服务器权威值（客户端数不到全部鲛人，昼夜时长还会被防守方角色被动改过），所以走联网通道由服务器回包，不在本地读取
