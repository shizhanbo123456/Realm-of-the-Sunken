# 05 UI（FGUI 界面接线说明）

> 配套：`Assets/Resources/GUI/Main_fui.bytes`（包名 Main）+ `ScriptsGenerated/Main`（生成类，命名空间 **Ros.UI.Main**，引用需 `using Ros.UI.Main;`）。
> 本文档 = 字段含义 / 档位表 / 接线映射的参考。逻辑接线在 `UI/UIManager.cs` + `UI/PageBase.cs` + `UI/Logic/*`。

## 一、页面根与整体结构

| 部件 | 组成 |
|---|---|
| **UI_HomePanel** | 单页，角色与属性常驻：m_connectPanel(UI_HomeConnect) + m_playerInfo(UI_PlayerInfo) + m_label_character_name（选中角色名）+ m_character_selection_panel(UI_CharacterSelectionPanel) + m_character_attr_panel(UI_CharacterAttributePanel) + m_btn_open_guide（打开图鉴） |
| **UI_LobbyPanel** | m_btn_joinAttack / m_btn_joinDefense（两块 UI_LobbCampOperation）+ m_btn_prepare + m_btn_exit + m_spectate_current_member_count（观战人数） |
| **UI_BattlePanel** | m_world_element_container(UI_empty_container，最底层，场景 UI 挂它) + m_Minimap + m_eventBanner + 复活进度（m_showRegenerationBar + m_regeneration_progressbar）+ m_barPanel(UI_BattleBarPanel，主点 + 3 副点) + **m_playerPanel(UI_PlayerPanel：技能栏、血量条、经验条、buff、头像遮罩)** + **m_CampInfoPanel(UI_CampInfoPanel，攻/守/观战三行)** + **m_BattleInfoPanel(UI_BattleInfoPanel，剩余时间、昼夜指针、设置按钮、快捷指令按钮与其轮盘)** + **m_list_selectCard(待抽卡悬浮按钮列表)** + m_onlook 控制器 + m_onlookComboBox + m_showBanner / m_showHit 转场 |
| 全局子界面（挂 GRoot，不挂页面） | SettlementView(UI_SettlementPanel：内含 BattleResult 标题面板 + BattleResultDetail 明细列表，条目为 BattleResultDetailItem)、ConfirmView(UI_ConfirmPanel，全屏拦截层在面板内部)、加载界面(UI_LoadingPanel)、全局飘字(UI_NoticePanel)、ChatPlugin(UI_ChatPanel)、GmPanel(UI_GmPanel)、SettingsView(UI_SettingsPanel)、RuleView(UI_RulePanel)、GuideView(UI_GuidePanel) |
| 战斗内独立界面（挂 GRoot，层级 15） | SkillSelectView(UI_SkillSelectPanel，技能选择)、LargeMinimapView(UI_LargeMinimapPanel，大地图)、GodViewView(UI_GodViewMinimapPanel，上帝视角)、SelectCardView(UI_SelectCardPanel，抽卡)。四个界面各自管开合、状态机与刷新；`BattlePage` 只提供会话状态（`MyCamp` / `OwnEntityId` / `TryGetSelfYaw` / `TryGetMinimapCenter` / `Minimap` / `QuickMarks` / `CardButtonList`）、快捷键分发与技能栏刷新回调 |

- 页面统一由 `PageBase` 管：缩放恒为 `Screen.height / 1080`；布局由 `page` 表的 `alignMode` 决定 —— **0 = 全屏**（高度保持 1080 不变，宽度按当前窗口宽高比重设，缩放到刚好铺满整屏）、**1~9 = 非全屏**（尺寸不动，按九宫格贴到屏幕上，`marginX` / `marginY` 是贴边留白）。九宫格编号：1 左下 / 2 正下 / 3 右下 / 4 左中 / 5 正中 / 6 右中 / 7 左上 / 8 正上 / 9 右上。世界坐标 → 面板坐标用 `PageBase.WorldToPanel`（Unity 左下原点 ↔ FGUI 左上原点翻转）。
- **场景 UI 层**：`m_world_element_container` 是战斗面板最底层子物体，实体血条与战斗飘字都挂在它上面，所以被所有 HUD 元素遮挡；面板坐标经 `BattlePage.ToWorldLayer` 换成容器局部坐标。容器需 位置(0,0)、缩放(1,1)、overflow = visible，否则血条会被裁。技能 / buff 悬浮提示仍挂面板根（保持最上层、跟随页面缩放），但**摆位边界是屏幕而不是面板**：`TipLayout` 按屏幕矩形夹取，提示可以画到所在面板之外；因此页面根的 overflow 必须是 visible，否则面板外的部分会被裁。
- **通用底框关闭**：`PageBase.BindFrameClose(UI_panel_2 frame, GComponent target)` —— 底框自带关闭按钮 `m_close`，点了把 target 收起；显示关闭按钮的面板直接调它，不必各配按钮。
- 切页：`UIManager.ShowPage / HidePage / IsPageVisible(pageEnum.xxx)`，由 `ClientEvent`（OnConnect / OnBattleStart / OnRestartGame / OnExitWorld）驱动；切页时自动收起未决的确认弹窗。
- **界面配置全在配表**：`Config/Source/page.xlsx`（表名 `page`）一行一个界面（`home / lobby / battle / chat / robot_tv / gm / settings / rule / guide / confirm / loading / skill_select / large_minimap / god_view / select_card`），六列 = `order`（层级）/ `blackMask`（显示黑屏遮罩）/ `closeOnOutsideClick`（点面板外部收起）/ `alignMode`（适配模式）/ `marginX` / `marginY`（贴边留白）。界面类只声明 `PageKey`，其余全部由 `PageBase` 读 `PageConfig`，代码里没有界面枚举、层级与摆位常量；枚举 `pageEnum` 同样由配表主键生成。每个界面 `InitPage` 时复制一份 `PanelBackground` 全屏遮罩挂在面板最底层，两个开关决定是否显示黑图、是否点外部 `HidePage`。当前值：home / lobby / battle / loading / select_card 走全屏；chat 左下、robot_tv 右下（70 / 15）；gm / settings / rule / guide / confirm / skill_select / large_minimap / god_view 居中；战斗内四个界面层级都是 15（同层互斥）。

## 二、组件规则

### 首页

> 没有局外养成：首页只做"选角色 + 改名字 + 连接"，不显示等级、经验、解锁与品质。

| 组件 | 规则 |
|---|---|
| **UI_PlayerInfo** | **m_label_playerName**（只读显示玩家名）+ **m_btn_editName**（修改名字按钮）；两者点击都打开改名弹窗 |
| **UI_RemanePanel**（改名弹窗，挂 GRoot） | 设计自带全屏半透明遮罩 + m_panel(UI_panel_2，标题「更改名称」，`show_close` 档位 1 = **关闭按钮可见**) + m_input（GTextInput，单行，`maxLength` = `name_length_max`）+ m_confirm（「确认」）。**确认时强校验**：`Trim()` 后长度不在 `name_length_min ~ name_length_max` 就只飘字、弹窗不关；合法才写 `ClientSelection.playerName` 与 `SaveManager.playerName`、刷新 m_label_playerName 并关闭。**关闭按钮 = 放弃修改**。弹窗开时 `opaque` 吞点击，进/退首页都会收起 |
| UI_HomeConnect | m_input_ipaddress.m_content 读 IP（`onChanged` 每次都写 `SaveManager.lastServerIp`，不点连接也记）+ m_btn_connect（连接前校验玩家名 2~8 字符） |
| **UI_CharacterSelectionPanel**（m_character_selection_panel） | m_current_selected_camp 控制器（0 进攻 / 1 防守）+ **m_tab_attacker / m_tab_defenser**（两个页签，点击切阵营，`GButton.selected` 互斥）+ **m_characterList**（GList，条目 UI_RoleHead，`numItems` = 当前阵营角色数；列表下标 + 阵营偏移 = 存档下标，进攻 0~5 / 防守 6~11）。点条目只浏览：右侧名字、属性、特殊能力与场景预览跟着变，浏览状态只留在页面内（不写 `ClientSelection`、不进存档），不写出场选择；进入首页固定展示进攻方已选角色，切页签展示该阵营已选角色 |
| UI_RoleHead | m_headIcon（角色头像；图标未导入时置空）+ m_roleName + m_confirm（组队界面准备勾选：0 未勾 / 1 已勾；首页标在该阵营真正已选中的角色上，与浏览角色分开）+ m_show_default_icon（0 角色头像 / 1 默认头像，观战条目用 1）。**m_level / m_lock / m_quality 不再使用**（没有等级、没有解锁、没有品质） |
| **UI_CharacterAttributePanel**（m_character_attr_panel） | **m_character_selcted** 控制器（0 = 显示「选择该角色」按钮 / 1 = 显示「已选择该角色」；按当前浏览角色是否等于该阵营已选角色判断）+ **m_attrList**（6 行固定顺序：生命 / 攻击 / 暴击 / 暴伤 / 视野 / 技能槽，条目 UI_AttrItem）+ **m_special_ability_list**（条目 UI_HomeSpecialAbility.m_label，内容 = 初始技能 + 被动描述（`entity.csv` 的 `passiveSkillDes` 列），见 `UI/Logic/GuideCatalog.cs`）+ **m_btn_select_character**（点它才把浏览角色写进 `ClientSelection.selectedAttackIndex / selectedDefenseIndex`，刷新列表勾选与控制器档位，并飘字「已选择 {角色名}」） |
| **UI_AttrItem** | m_attrName + m_attrValue（数值取整，后缀由 `AttrSuffixes` 决定：暴击与暴伤 `%`、视野 `m`）+ **m_progressBar**（GList，条目 UI_AttrValueItem，**固定 10 格**）。格数 = `attr_range.csv` 的区间比例 × 10 向上取整（最小值 = 0 格、最大值 = 10 格，非零至少亮 1 格） |
| **UI_AttrValueItem** | m_filled 控制器：1 = 点亮 / 0 = 熄灭（格数由所在属性条算，条目自己不持有数值） |

### 大厅

| 组件 | 规则 |
|---|---|
| **UI_LobbCampOperation**（m_btn_joinAttack / m_btn_joinDefense 各一块） | m_quit_mode 控制器（0 未加入 → 显示 m_join / 1 已加入 → 显示 m_quit）+ m_join（加入该阵营）+ m_quit（退出该阵营）+ m_label_AI_count（`xN`）+ m_add_ai / m_remove_ai。两块同构，只有阵营不同 |
| UI_LobbyPanel | 两块 UI_LobbCampOperation + m_btn_prepare（准备/取消，按 `GButton.selected` 表示状态）+ m_btn_exit（退出房间）+ m_spectate_current_member_count（观战人数） |

已准备（含开战倒计时）时不允许切阵营与改人机数量：拦截并飘字「请先取消准备」。

大厅场景摆位只认真人成员（`clientId ≥ 0` 且已选角色），按成员表顺序占 `LobbyDisplayArranger` 的 6 个攻方 / 2 个守方锚点；AI 与观战不摆模型，成员列表变化即重建。

### 战斗

| 组件 | 规则 |
|---|---|
| **UI_SkillList** | m_content（横向单行，defaultItem = UI_SkillListItem）。条目数 = 本地角色技能槽位数（`weaponSlotCount`），代码额外设列表宽度 = 全部条目宽度之和。内容 = 服务器下发的槽位表（`ClientSkillManager.ActiveSkills`），槽位空则 `m_empty=1` |
| **UI_SkillListItem** | m_loader_iconBase（底图）+ m_loader_icon（图标 + `fillAmount` = 本轮恢复进度）+ m_key（键位，`Config.skill_slot_keys` = U I O L H Y）+ **m_storeList（GList，`numItems` = 已存可用次数）** + m_empty 控制器（0 有技能 / 1 空槽）。冷却与库存由服务器持有，客户端按服务器下发的根戳现算（栏外技能的冻结也在服务器侧） |

| **UI_btn_SelectCard**（m_list_selectCard） | 待抽卡悬浮按钮：m_level 控制器 = 档位（0 白银 / 1 黄金 / 2 炫彩）+ m_label_num（`×N` 剩余次数）。列表**只放仍有次数的档位**，点击打开抽卡界面 |
| **UI_SelectCardPanel**（SelectCardView） | 抽卡界面：m_list（3 张卡，条目 UI_Card）+ **m_current_luck**（种子里的幸运）+ m_discard（弃卡换经验）+ m_discard_description（`弃卡换经验 +N`）+ m_btn_close（关闭，**不消耗次数**）。`WaitForSeed(tier)` = 等待态：面板淡入立起、卡面清空、幸运暂时隐藏；种子到了 `Open(cards, tier, luck)` 再铺卡，卡片按 0.08s 间隔逐张播 m_show；**关闭不播任何退场/淡出动画，直接收起**；同一档还有剩余次数时面板不关，先回等待态再换下一组牌 |
| **UI_Card** | m_cardGraphic（UI_CardGraphic，整张卡面，卡名/描述/按钮/图标都在它内部）+ m_show / m_hide 转场 |
| **UI_CardGraphic** / UI_CardSkillDisplay | m_level 档位控制器（0 白银 / 1 黄金 / 2 炫彩，资源 card_back_silver/gold/holo）+ m_title（卡名）+ m_des（描述，技能卡的 `{0}` 已换成技能名）+ m_btn_select（选这张）+ m_skillpreview（UI_CardSkillDisplay，技能卡图标）+ m_show_skill_display 控制器（0 非技能卡 / 1 技能卡） / m_skillpreview 内的图标位 m_loader_icon。**m_skillpreview 悬浮出技能提示**（锚点就是组件本身，每次渲染重挂，列表复用条目） |

| UI_Minimap + UI_MinimapItem | 档位 0 自己 / 1 队友 / 2 敌人 / 3 中立雕像 / 4 珊瑚 / 5 水晶雕像 / 6 鲛人 / 7 精英鲛人 / 8 国王雕像 / 9 贤者雕像。雷达式：自身固定居中并随朝向旋转，上方 = 世界 Z+、右侧 = 世界 X+，当前显示半径铺满 mapBase（F 键循环 100/200/300，服务器 `SCMinimapRadius` 回应）；点位 `scale` 抵消上层缩放回到设计尺寸。**雷达圆心**：有本地实体 = 该实体；纯观战无实体 = 观战目标实体；**自由视角 = 相机自身**（相机脱离跟随点后圆心必须跟相机，否则点位按旧圆心换算会漂出雷达）。**m_minimapButton**：点击打开大地图（只负责开，关闭走大盘的底框关闭按钮）。**快捷指令点位**（`TickQuickMessages`）与点位同层挂在遮罩里，档位即指令 id，缩放 = 抵消上层缩放 × `global_variables.quick_message_pointer_scale`，超出显示半径即夹到遮罩圆边内侧（按「图标 + 箭头」内缩）并由箭头指真实方向 |
| **UI_LargeMinimapPanel**（LargeMinimapView） | m_panel(UI_panel_2，标题「小地图」，其 m_close 收起) + m_loader（整张 `AssetsManager.MapTexture`，`fill = Scale`）。点位直接铺雷达缓存（`UI_Minimap.CurrentPoints`），按整图换算（图左下 = 世界(0,0)、上 = 世界 Z+），档位与雷达同一套 `UI_Minimap.PageOf`；**纯展示不可点**，打开期间每帧重排，关闭时销毁全部点位。快捷指令点位（`RefreshQuickMessages`）同样按整图换算落在底图上，整张地图都在视野内，不做夹边 |
| **UI_GodViewMinimapPanel**（GodViewView） | m_panel(UI_panel_2，标题「小地图」) + m_largeMinimapContainer(UI_GodViewMinimapContainer，内含 m_loader) + m_scaleButtonList（倍率按钮，按 `global_variables` 的 `godView_scale` 生成，默认首档）+ 详情区。**入口：1 秒内连按 3 次 G**（`Config.god_view_open_key / press_count / window`，已打开或键盘被 UI 占用时不累计），关闭走底框 m_close。区域 = 中心 + 边长(`terrain_size / godView_scale`)：拖动容器平移中心并夹进地图，打开期间每 0.2s 请求一次、切档立即补一次；点位缩放 = 抵消上层缩放 × `godView_marker_scale` |

## 四、协议依赖

- `SCEntityDisplayInfo`：hasHealth → health/maxHealth；**hasBuffs → buffs（type+level，type 即 effect.csv 主键）**；hasSkills → skills（仅持有技能 id，无冷却/库存；只发给该实体所属客户端）。血条、名牌、buff 列表全部来自这一条包
- **哪些实体有头顶血条由 `entity.csv` 的「显示血条」列决定**（留空/0 = 不创建，1 = 创建）：`BattlePage.OnEntityDisplayUpdate` 按 `EntityConfig.GetByCategory(info.type).showHealthBar` 判断，不再按实体类别硬编码；名牌仍只给进攻/防守双方角色
- `SCBattleEvent`：type 决定 EventIcon 档位与条目版式；textId/textId2 为数字 id（<10000 查 notice.csv，≥10000 为玩家名，clientId = id − 10000）
- `SCCombatLabel`：amount（伤害量或治疗量）+ type（`CombatLabelType` 页号）+ targetId + 可选 hitPos
- `SCCampAliveCount`：attacker/defense 的 alive+total + spectatorCount
- `SCDefensePointProgress`：mainHealth / sub1Health / sub2Health / sub3Health（当前血量，-1 = 该守护点还没生成）+ healthScale（开局人数倍率，0 = 还没生成；上限 = `entity.csv` 生命 × 该倍率，名字读 `entity.csv`，百分比与守护层数由客户端算）
- `SCMinimapEntity` / `SCMinimapRadius`
- 上帝视角：`CSGodViewArea`（包围盒，客户端每 0.2s 请求一次）→ `SCGodViewEntities`（实体流）/ `SCGodViewCorals`（珊瑚流，同样带 id）；`CSGodViewEntityDetail` → `SCGodViewEntityDetail`（点选详情快照，`entityId = 0` 表示实体已消失）。两条流都按实体 id 逐条下发，客户端收到即落点位、3s 未再收到即清除；单包条数与字节预算见《02-代码架构》上帝视角条目
- `SCLobbyInfo`（members: camp/characterIndex/ready）+ `SCLobbyPlayerName` + `CSLobbyPlayerInfo`（玩家名上报）
- 加载期：`SCLoadingStart` → `SCLoadingPrepared` → `CSLoading*Request` / `SCLoading*Response` → `CSLoadingComplete` → `SCBattleStart`；战斗期的玩家名与玩家↔实体关系全部来自这套数据
- `SCReviveInfo`（复活进度）、`SCPlayerEntity`（玩家 ↔ 实体映射，-1 = 无实体）
- `SCPlayerProgress`：level / exp / silver / gold / holo（幸运随种子走，不在这里）；`CSCardAction`（tier + hasChoice + choice + requestSeed）是抽卡界面唯一的上行，`SCCardSeed`（valid + tier + luck + seed）是它的回包。服务器扣次数、结算效果后回推一条新的 `SCPlayerProgress`
- `EntityPlayerManager.TryGetAnchorPos(id, EntityAnchor, out pos)`：名牌/血条走 `Bar`，战斗飘字兜底走 `LabelFallBack`

## 五、玩家阵营（四分类）

- 枚举 `PlayerCampType`：`Attack=0 / Defense=1 / Spectator=2 / Neutral=3`，数值即协议值、也即 `PlayerCampIcon.m_player_camp` 与 `ChatItem.m_camp` 的档位。

- 实体血条显示时由 `UI_EntityBar.ToPlayerCamp` 转换：攻/守原样，其余（中立雕像、场景物件）一律取「中立」档。**敌对只看阵营：`camp` 与本地玩家阵营不同即为敌对**（`UI_EntityBar.IsEnemy`）——中立雕像、珊瑚对攻守双方都显示为敌；鲛人与水晶雕像的 `camp` 是防守方，因此进攻方看到为敌、防守方看到为友。**珊瑚当前不创建血条**（entity.csv 显示血条列为空），中立雕像有。
- 大厅当前提供攻/守/观战三个块，玩家还选不到中立；服务端开局判定、AI 分配、加载分包与视野仍按攻/守/观战三分类处理。

## 七、聊天

**需求**：三个协议频道 + 一个本地页签——全频道（所有人可见）、阵营频道（仅同阵营）、附近（发送者实体 `chat_nearby_radius` 米内的玩家，观战方没有实体，发不出也收不到）、系统消息（只读，战斗事件播报）。联网状态（大厅与战斗）都可用，首页不显示；自己的消息本地立即回显；面板无标题栏、无关闭按钮、无发送按钮，靠联网状态自动显隐。

**ChatPanel 成员**

| 成员 | 类型 | 说明 |
|---|---|---|
| m_show_channel_menu | Controller | 0 收起频道按钮（大厅）/ 1 展开（战斗） |
| m_input | GTextInput | 单行输入框，`onSubmit` = 发送（回车） |
| m_content | GList | 聊天列表，`itemProvider` 固定返回 UI_ChatItem（聊天与系统消息共用同一个条目），`overflow=scroll` |
| m_btn_allChannel / m_btn_campChannel / m_btn_nearby / m_btn_systemInfo | GButton | 页签 = 频道 0 全频道 / 1 阵营 / 2 附近，第 4 个是系统消息页签；发送频道跟随当前页签（系统消息页签不改发送频道），选中态用 `GButton.selected` |

**ChatItem 成员**：只有 m_content（GTextField，`UBBEnabled = true`，autoSize=height）。

**正文格式**：一行 UBB 文本 = 频道标签 + 发送者 + 正文，例如 `[附近] 路西法: 跟着我进攻`。三段颜色全部取 `InfoManager` 的聊天配色字段：

| 字段 | 用途 |
|---|---|
| chat_channel_color | 频道标签（`[全频道]` / `[阵营]` / `[附近]` / `[系统]`） |
| chat_name_attack_color / chat_name_defense_color / chat_name_spectate_color | 发送者名字，按发送方阵营三分类取（没有中立玩家） |
| chat_content_color | 正文 |

**数据流**

1. `UIManager` 启动创建 ChatPanel（ChatPlugin 持有，默认隐藏）；`OnConnect` 显示并清空，`OnExitWorld` / `OnRestartGame` 清空并隐藏。
2. 发送：`m_input.onSubmit` → 取文本并去首尾空白，按 UTF-8 正文字节数校验长度（范围取 `global_variables` 的 `chat_message_length`，当前 1~80 字节；字节数 = `StringSerializer.GetLength` 减去 1 字节长度头），短于下限飘字「发送的消息太短」、长于上限飘字「发送的消息太长」；1s 内只发一条（冷却静默忽略）。附近频道在自身没有实体时直接飘字「附近频道需要操控中的角色」并不发送。
3. 本地回显：先入表（阵营 = 自己），清空输入框，滚到最新。
4. 上报：`NetworkManager.SendChat(CSChat{channel, content})` → 服务器 `BattleManager.ReceiveChat` 组装 `SCChat`（补 senderClientId / 名字 / 阵营 / characterIndex）。全频道与阵营频道整房广播；**附近频道逐人单播**：取发送者实体，遍历房间内真人，只发给「所操控实体」在 `chat_nearby_radius` 米内的客户端（无实体的观战方跳过）。
5. 下行：`ClientReceiveChatLocal` → `ClientEvent.OnChatMessage` → ChatPlugin 过滤（自己发的忽略；阵营频道且发送方阵营 ≠ 自己且未开 GM「敌方对话」时忽略；附近频道不再做阵营过滤，距离已在服务器侧筛过）。
6. 渲染：按页签拼 UBB 文本；系统消息页签显示 `[系统] 文案`（战斗事件：玩家互杀拼「击杀者 击败了 受害者」，其余直接取 notice.csv；技能播报只进重要事件横幅，不进列表）；列表只保留最近 50 条聊天与整局系统消息。

**界面行为**：联网进大厅即显示（隐藏频道页签、默认全频道），切战斗展开页签；结算回组队时重新收起页签并切回全频道；断开/离开房间清空并隐藏；面板整体缩放 = 屏幕高/1080，x=0 贴左、纵向居中。

## 八、FGUI 运行时库补丁

`Assets/FairyGUI-unity-master` 是直接放在工程里的 FGUI 运行时源码，其中有一处项目自己的改动，不属于 FairyGUI 官方代码。**重新下载或覆盖该目录后必须重新打上，否则回弹会重新出现。**

| 文件 | 改动 | 效果 |
|---|---|---|
| `Scripts/UI/UIConfig.cs` 的 `defaultScrollBounceEffect` | `true` → `false` | 滚动面板默认关闭回弹：拖到任意一端即硬停，不会被拉出空白再弹回；鼠标拖拽滚动本身保留 |

机制：`ScrollPane.Init()` 用该默认值初始化 `_bouncebackEffect`，只有导出包里显式带「回弹 = true」标记位的面板才会覆盖它（`ScrollPane.Setup_BeforeAdd`）。要单独打开某个面板的回弹，就在该面板上写 `scrollPane.bouncebackEffect = true`。
