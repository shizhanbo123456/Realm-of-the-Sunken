## 一、项目概述

**[A]** 本项目为"多人非对称对抗 + MOBA 式地图攻防 + 局内技能构筑"玩法。

**[A]** 多个相对较弱的进攻方玩家，对抗防守方玩家（防守方人数不限定，见第三章）。

**[A]** 双方围绕多个外围防守目标和一个最终核心展开攻防；所有玩家一起开始、一起结束战斗。

**[A]** 玩家通过近战动作、主动触发技能直接参与战斗；**没有局外养成**，所有角色默认全部解锁，成长全部发生在单局内（局内等级 + 抽卡词条）。

**[A]** 尽可能减少难以感知的纯数值 Buff，强调可从画面和操作中直接理解的状态变化。

**[A改]** 标准对局推荐 4 进攻方 vs 1 防守方，但实际开发中**不限制具体人数**，双方均有人即可。

**[A改]** 单局时长 **10 分钟**。

## 二、动画与攻击事件 [A]

**[A]** 玩家输入首先请求一次攻击并播放本次攻击绑定的动作；实际伤害判定、子弹生成、投掷物脱手，在动作的指定攻击事件到达时执行。

**[A]** 一个动作可以包含一个或多个攻击事件，用于连续攻击或多段发射。

**[A]** 动画事件只表达"本次攻击到达触发时机"，具体生成哪种攻击由当前动作、当前技能和本次请求决定，不把具体技能逻辑硬编码进动画文件。

**[A改]** 动画被打断后，尚未到达的动画攻击事件不再生效——**由动画状态机处理，无需代码额外处理**。

**[A改]** 攻击上下文绑定的实现方式：每次触发时向角色动画组件传入新的事件（确保旧的事件已撤销）。各动作的攻击事件数量与用途由用户后续记录在角色动画组件中。

**[A]** 部分弹幕技能允许不播放角色施法动作；使用施法动作的技能可绑定短/中/长施法动作，并在事件帧生成子弹。

**[A改]【架构原则】** 客户端中给玩家看到的内容只需保持大致合理，**所有关键判断全部在服务器**；服务器和客户端都需要播放动画（服务器上不渲染、不实例化角色，只是空壳 prefab，用来触发动画事件）。

**[A改 2026-09-12]【动画同步】** 服务器与客户端**共用同一份动画状态机资产**，同步标识用**动画状态的完整路径 hash**（两端一致）；客户端据此定位片段，并按服务器给的**归一化播放进度**继续播放，**同一片段不重播**（让本地动画连续推进，避免每帧被拽回开头）。客户端**不需要也不传递角色类型**——播哪一套动作（女 / 男 / 鲛人…）完全由服务器决定。

## 三、游戏流程与房间 [A]

### 3.1 流程 [A]

```text
加入服务器（单个服务器 = 单个房间，无匹配功能）
→ 初始界面选择角色
→ 进入组队阶段（选角与组队同时进行，房间中可随时调整角色）
→ 双方人数均 > 0 时可开始游戏（不自动分配阵营，玩家自行商议选择）
→ 全员准备，3 秒倒计时
→ 加载阶段（客户端加载界面；逐步拉取玩家/AI 名单，加载完成的客户端才进入战斗视图）
→ 正式战斗
→ 达成胜负条件
→ 全员同时结算角色经验
→ 返回组队阶段
```

### 3.2 房间与阵营 [A]

**[A改]** 无阵营意向、无 PVP/PVE 队列、无自动 AI 补位：**房间中任意玩家可自由编辑双方的 AI 玩家数量，数量不限制**。

**[A改]** 不自动分配进攻/防守：组队时手动选择阵营；双方人数都 > 0 才能开局，否则无法开启游戏，由玩家自行商议。

**[A改]** 无解锁流程：所有角色**默认全部可用**；无匹配功能，只有加入服务器。

**[A]** 无倒地救援机制；玩家死亡即进入复活等待。

## 六、防守目标 [A]

### 6.1 守护雕像

**[A]** 地图 = 3 座**贤者雕像**（分布不同路线）+ 1 座**国王雕像**（位于防守区域）；守护雕像不可采集。四座雕像的位置来自**地形烘焙点位**（`TerrainSpawns`）：3 个副守护点（下标即雕像 value）+ 1 个主守护点。

**[A]** 国王雕像分层减伤：每座存活的贤者雕像提供 25% 减伤（3 座全存 = 75%，全毁 = 0）；国王雕像不无敌、可直接攻击，形成"先毁外围 vs 直捣王座"的战略分叉。

**[A]** 减伤状态表现为护盾叠层（75% = 3 层 / 50% = 2 层 / 25% = 1 层 / 0% = 无）。

**[A改]** 无回血原则**仅约束守护雕像**（确保进攻方进度不可逆）；水晶雕像等其他单位不在禁止范围。

**[A改]** 防守方 HUD **常驻显示每座守护雕像血量**；**无预警机制**，防守方通过血量变化自行判断哪座雕像正在被拆。

### 6.2 中立雕像（天使 / 恶魔）

**[A改 2026-10-21]** 场上同时只有一座**中立雕像**：**白天刷新为天使雕像、夜晚刷新为恶魔雕像**（按刷新那一刻的昼夜判定，刷出后不再随昼夜翻转改变）；两者属性与行为一致，外观与攻占奖励按类型区分（实体上用 `value` 区分：0 = 天使雕像，1 = 恶魔雕像）。

**[A改 2026-09-22]** 中立单位，双方争抢。**「攻占」= 把雕像击破**（雕像不属于任何一方，被击破后消失）：
- **归属**：把雕像**血量清零的那一次攻击的攻击者**获得对应祝福（天使雕像 →「天使祝福」，恶魔雕像 →「恶魔祝福」）；**被 Buff / DoT（固定数值伤害）打死的没有归属**，不给任何实体加成
- **奖励内容**：持续 **30s**，作用于获得者**的所有技能**（含防守方主动 / 大招），并每秒恢复生命值：**天使祝福** = 回血 200 / 出伤 +25% / 受伤 −25%；**恶魔祝福** = 回血 50 / 出伤 +100% / 受伤 +25%
- **刷新时序**：开战后 **30s** 刷第 1 座；此后每座被击破，**60s 倒计时**结束后在候选点随机刷新一座（白天天使 / 夜晚恶魔）

**[A改]** 中立雕像为中立，不属于任何阵营，**不提供视野**。

**[A改 2026-09-08]** 中立雕像**主动攻击**：对进入攻击范围的**进攻方与防守方**单位自动索敌施放技能（中立无友方，对攻守双方均敌对，谁靠近打谁；不打珊瑚与水晶雕像）；技能走全实体统一技能模型（见 13.1），施法行为由 store / CD / 索敌范围等配置调节。

## 七、资源系统：珊瑚 [A改 2026-10-21]

**[A改 2026-10-21]** 珊瑚分**小珊瑚 / 大珊瑚**两种尺寸，**同尺寸共用一套属性配置**（`InfoManager.CoralSmallInfo` / `CoralLargeInfo`），外观各用一组预制体列表（`CoralSmallGraphics` / `CoralLargeGraphics`，列表内随机取变体；服务器读 `AssetsManager`、客户端读 `ResourceManager`，两端同名同序），每个珊瑚的属性与表现只由尺寸决定。

**[A]** 珊瑚 = 局内经验产出资源，不属于胜负目标；**双方阵营均可摧毁**。

**[A]** 摧毁珊瑚 → 给击杀者**经验**（走 `entity.csv` 的「被击败时掉落的经验」列：小珊瑚 5 / 大珊瑚 20）并**回血**。珊瑚**不再掉技能**，技能改由抽卡产出（见第十四章）。实体手上/背上的武器外观固定，不随任何掉落变化。

**[A]** 技能栏仍然只由客户端决定：服务器只记"持有"，未持有即收入持有表、已持有不做任何变更；能否摆上技能栏由客户端决定（见 13.1「技能栏」）。

**[A改 2026-10-30]【技能栏】**
- 服务器只记"持有"，不知道也不校验技能栏；**技能栏（激活的那几个）纯客户端决定**，长度 = 角色技能槽位数。
- 新获得技能时：技能栏未满 → **自动加入**；已满 → **不自动选中**，只留在持有表里等玩家自选。
- **Tab 打开技能选择面板**：列出全部持有技能，默认勾选当前技能栏内容；勾满槽位数后再勾只提示「已达到技能选择上限」；关闭面板时把勾选结果应用为技能栏。

### 10.2 局内等级与经验 [A]

**[A]** **没有局外养成**：不存在玩家等级、角色等级、角色经验，所有角色默认全部解锁。唯一的成长容器是"这一局"。

**[A]** 局内等级 **1~20 级**（`character_upgrade_exp.csv` 逐级配"升到下一级所需经验"，配表加行即提上限）。经验**自动到账**（不生成经验球），当前等级内累计、升级后扣减。

**经验来源** = `entity.csv` 的「被击败时掉落的经验」列，击败任何实体都给：小 / 大珊瑚 5 / 20、鲛人 20、精英鲛人 200、进攻角色 100、防守角色 800、防御塔 150、副 / 主守护点 300 / 1000、天使 / 恶魔雕像 120。

**归属范围** = `entity.csv` 的「被击败时的掉落物生效范围」列：`0` 只给击杀者，`1` 给击杀方**全阵营所有玩家各一份**（进攻方拆塔、防守方被杀这类团队目标走这一档）。

**【经验增幅】** 按「守护点已扣除血量比例」与「已过时间比例」换算，两项都是百分数：

```
增幅基数(%) = (守护点已扣除血量比例% × 2 − 已过时间比例%) × 10
防守方经验获取 = max(30%, 100% + 增幅基数)
进攻方经验获取 = max(30%, (100% − 增幅基数) × 4 ÷ 进攻方人数)
```

含义：守护点掉得快（进攻方领先）→ 防守方吃增幅、进攻方被压；守护点掉得慢（防守方领先）→ 反过来。**这是一条追赶机制**，用于削弱 1v4 的人数差带来的滚雪球。

> 校准提示：中性点落在「守护点扣血比例 = 时间比例的一半」，因此常规对局里防守方容易长期贴在 30% 下限。若实测偏斜，把括号里的 `× 2` 去掉即可让中性点变成"按时间推进"。

### 10.3 局内等级压制 [A]

**[A]** 等级**不进生命 / 攻击表**，只参与伤害计算：每差 1 级，**增伤 +5% / 受伤 −5%**，等级差**夹在 ±3 级**（最大 ±15%，综合交换比 1.35 倍）。

**[A]** **对所有伤害计算生效**（含 PVE：珊瑚、鲛人、雕像、建筑，以及 DoT 与反伤）；没有攻击者的伤害（地形 / GM）不参与。写成一条式子即可覆盖双方：`1 + 0.05 × clamp(攻击者等级 − 目标等级, ±3)`。

**[A]** 死亡**不掉等级**，复活沿用当前等级；对局结束等级清空。

## 十一、状态与 Buff 系统

### 11.1 Buff 设计原则 [A]

1. 永久数值变化属于角色属性，不作为 Buff 显示。
2. 昼夜产生的阵营规则使用统一昼夜状态表达。
3. 只保留能从画面或操作中直接感知的状态；玩家无法理解的变化不做成独立 Buff。
4. 影响全局参数的被动（鲛人刷新等级等）开局一次性计算，**不进 Buff 系统**；受击类被动（防守方角色0 单次受伤上限、防守方角色1 低血挂盾）在伤害结算时即时判定，也不做成常驻 Buff。
5. 全局无回血原则**仅约束守护雕像**；其他单位的回血类效果不受此限制（如"水晶雕像缓慢回血"闲置效果）。

### 11.2 分类框架 [C 暂定]

护盾类 / 属性调整类 / 机制调整类 三类框架**暂定**，待 Buff 系统详细设计后定稿。

### 11.3 Buff 清单（总表）

> **Buff 的类型、效果、来源、特征与特效映射，只在《03-技能与Buff总表》二章维护**，本文件不重复列。
> 本策划案只保留规则：叠加语义由 effect.csv「叠加模式」列决定——**0 = 高等级覆盖低等级、相同等级刷新时间；1 = 多层分别生效、分别计算剩余时间；2 = 刷新时间并叠加等级；3 = 强制 1 级、重复添加仅取最大时间**。每个 Buff 必带等级与持续时长（无限 = 极大值）；属性修改类 Buff 只改属性不改其它状态；控制与霸体的表现由「禁止移动输入 / 禁止技能输入 / 冻结动画 / 霸体等级覆盖」四列决定，不按类型写死。

## 十二、玩家操作与基础战斗 [A]

**[A]** 移动状态只分"移动/静止"两态，无行走/奔跑之分。

**[A改]【重要】无固定连段模板**：没有"挥刀三连/出拳两连"的固定组合，但挥刀动作有三种——**同一类动作中具体触发哪个动作由具体技能确定**。左键普攻的规则：移动+当前技能为近战=挥刀动作；移动+非近战=出拳动作；静止=跃起砸地。

**[A]** 跃起砸地 = 静止站桩重击，效果在动画事件帧生效；**不支持蓄力**。

**[A改]** 近战统一进战斗判定链路（子弹/碰撞体，"攻击统一由子弹处理"）；子弹寿命不限定短（如飞踢子弹可 1~2 秒）。

**[A改 2026-09-12]【子弹穿透，命中不消失】** **不存在"单体命中即消失"的设定**——所有子弹**命中后都不消失**，只在**生命周期到期时**移除；同一发子弹对**同一目标只结算一次**（命中记录去重），途中命中的其它目标继续正常结算。

**[A改 2026-09-12]【判定方式：物理引擎 + 实体自身 Collider】** 实体自带 Unity Collider 并归入**统一实体层**，判定直接走物理引擎查询，不使用固定判定体积参数：
- **近战（含空手）**：以出手的**手部骨骼**为球心做球判定，命中球内**全部**敌方单位（非单体）；原地砸击等无手部骨骼的动作退化为以角色位置为球心。半径写在 skill.csv 第 9 列（只服务无特效近战）。
- **子弹**：以特效预制体 `BulletVfxInfo.hits` 定义的伤害球为准——可带局部偏移、多段各自独立时间窗；每段按"**上一帧球心 → 本帧球心**"的胶囊扫掠判定，覆盖整段路径，防止高速子弹穿模。
- 层掩码等仍是全局配置，不写在实体预制体上；**判定范围不在攻击数据里**——有本体特效的走命中球，无特效的近战才走配表半径。

**[A改 2026-11-15]【一动作一通道，移动语义在服务器，技能 id 在客户端】** 玩家操作按类别拆成独立包，全部尽力可靠（Strive）上行，**没有合并的按键位掩码**：
- **CSMove**：`yaw` = 角色要转过头并前进的绝对世界朝向。开始移动时发一次，移动中转向超过 3° 再补发
- **CSMoveStop**：无载荷，WASD 全部松开时发
- **CSJump**：`down`（空格 / 左 Alt 合成一个跳跃键的按下与抬起，飞行模式下转成上升长按）
- **CSSlide**：`down`（左 Shift 的按下与抬起，飞行模式下转成下降长按）
- **CSSkillCast**：`skillId`。右键取技能栏当前选中槽位的技能、左键取空手三连，客户端自己算好 id
- **CSSkillSelection**：技能栏槽位提交
相机模式**不再上行**：移动方向已经由 CSMove 的 yaw 表达，服务器不需要知道客户端是第三人称还是俯视。

服务器负责解释：`yaw` → 角色瞬时转向后沿自身前方移动（前后被屏蔽 = 不接受移动，朝向被屏蔽 = 只走不转身）；技能 id → **只校验是否持有 + 沉默/强控**，不校验冷却与库存；**瞄准点为"最近的敌方单位"，没有敌方时取角色前方 10m**（技能可忽略该点）。
> 已知取舍：操作走"尽力可靠"（同一条消息重发 3 次、不等待回应），`CSMoveStop` 极端情况下丢失会让角色一直走（已知情并接受此方案）。

**[A改]** 剑气弹道（有无/段数/射程）完全由具体技能效果决定，无固定模板。

**[A]** 动作选择不决定伤害数值；伤害/轨迹/击退来自技能配置。

**[A改]** 施法动作使用规则：**小技能用短施法，越大的技能用越长的施法**（跃起投掷本身也是施法动作；鲛人爪击/嘶吼也可作为绑定动作）。

**[A]** 近身攻击无打断功能。

### 12.1 受击与霸体系统 [A]

**[A改]** 被命中的角色在满足受击条件时进入受击状态并播放受击动作（未满足条件时只结算伤害，不进入受击）。

**【霸体系统】** 霸体只有两档：**无霸体 / 霸体**。所有攻击均携带「**破霸体**」bool 配置，是否进入受击状态由"目标当前是否有霸体"与"攻击是否破霸体"共同决定：

| 目标当前霸体 | 非破霸体攻击命中 | 破霸体攻击命中 |
| --- | --- | --- |
| 无霸体 | 进入受击（短受击） | 进入受击（长受击） |
| 霸体 | 不打断（不进入受击、不停位移），击退照常 | 进入受击（长受击） |

- 受击动作分两档：**破霸体命中一律长受击**；不破霸体命中无霸体目标为**短受击**。
- **受击动作与打断位移跟着这条判定走**，进入受击才会被打断。**击退不受这条判定约束**，且与受击动作并行：进入受击照常播受击动画并转身，击退不会取代受击表现。

**[A]【架构说明】霸体不是常驻属性，由当前动画片段声明**（`AnimEvent.Endure`，逐片段在 Inspector 配置，对应 `Assets/Scripts/Entity/Attribute/Endure.cs`）：

- `EndureType` 两等级：`None = 0`（无霸体）/ `Super = 1`（霸体）；
- 攻击片段默认带霸体（`AnimAttackEvent`）；起跳、滑铲、登场等片段按需配置；移动与受击片段不带霸体；
- `entity.csv` 的「霸体等级」是**下限**：填 1 的实体全程霸体（防守方即如此），任何来源都不得低于它；
- Buff 通过 effect.csv「霸体等级覆盖」提供或取消霸体，优先级高于动画片段（如冰冻期间锁移动但保留霸体，见 11.3）。

霸体判定基于实体自身的动画片段，玩家与 AI 等所有实体通用；它决定**是否进入受击状态**（受击动作 / 打断位移），**不影响伤害结算**（未进入受击时照常结算伤害，只是不播受击、不打断），**也不影响击退**。

**【击退】** 被带击退力度的攻击命中时，目标沿水平方向被推离攻击来源，不再有垂直方向。

- **方向**：优先取「目标位置 − 攻击者位置」压平 y 后的方向；攻击者实体不存在时取「目标位置 − 子弹位置」。两者重合时沿目标自身面向。**始终优先把目标推离攻击者**。
- **唯一阻断项是护盾**：身上有任意护盾（含雕像护盾）时完全不击退；霸体、冰冻等控制状态都不阻止击退。
- **飞行模式（GM）免疫击退**，与免疫受击打断一致。
- 力度由技能配置，一次命中产生持续数帧、逐渐衰减到零的推力；连续命中会累加。
- 击退不影响伤害结算：被护盾挡下击退的目标照常扣血。

## 十三、技能系统 [A]

### 13.1 技能统一模型

**[A]** 技能三要素：①武器表现（由实体固定武器 + 动画状态决定，技能不声明）②释放动作（可配置）③释放效果（必须）。

**【武器显示：手里拿的 / 收起的】**
- **每个实体固定持有一把武器**：武器编号写在 entity.csv（末列），该编号在 weapon.csv 里对应「武器动画类型」与「武器显示类型」；不随技能变化，编号留空 = 无武器。
- **没有常驻悬浮武器**：角色身边不摆任何武器外观，只有"手上拿的"和"收起的"两种显示，位置由当前攻击动画决定——有的攻击拿在手上，有的收在背上 / 腰间。
- **显示位置随动画状态走，不走网络**：各动画状态在 Inspector 配武器显示位置，两端跑同一套动画状态机，显示自然一致；武器外观不进同步包。
- **发射点与武器无关**：远程技能从技能自己的骨骼锚点发出（见《02-代码架构》锚点节），与手上拿什么无关。
- **投掷类**：把武器扔出去的技能抛的是该实体那把武器的**外观副本**，不改变手上 / 背上的显示。

**[A改]** **双方角色都初始携带攻击型技能**（可破坏珊瑚、攻击敌人），每个角色的初始武器各不相同。

**[A改]** 技能**不做分类**，一切由配置组合表达。

**[A改]** 触发方式仅主动触发（蓄力/引导不保留；自动触发归角色被动）。

**[A]** 生效时机统一 = **等待动画攻击事件**（无"输入立即生效"分支）。

**[A改]** 多攻击事件帧的响应行为、索敌规则、子弹轨迹、发射参数、目标类型、空间归属**均不预设全局枚举维度，取决于具体技能中的设置**。

**[A改 2026-09-08]【全实体统一技能模型】技能系统对**所有实体**统一：玩家角色、水晶雕像、中立雕像、鲛人等非人为操控实体与玩家使用**同一套技能逻辑**——技能存储（store）、冷却（CD）、轨迹、特效绑定模型完全一致。非玩家实体与玩家的唯一差异是**施法来源**：玩家 = 技能槽快捷键手动触发；非玩家实体 = AI 自动索敌、满足条件时触发。AI 实体的施法行为**只通过调整 store / CD / 索敌范围 / 触发条件等配置参数来调节**，不引入独立的"怪物施法系统"。store 用尽的规则同样适用于所有实体（用尽即暂时无法施放，按技能 CD 每 CD 秒恢复 1 点；非玩家单位 store = -1 表示无限制）。

### 13.2 配置维度参考（非封闭清单）

动作绑定（无/短/中/长施法/跃起投掷/近战/爪击/嘶吼）、生效时机（动画事件）、事件响应、索敌、轨迹、发射参数、目标类型、空间归属——各维度取值由具体技能自行定义。

> 实现注记（代码侧，非策划规则）：技能的**延时 / 多段 / 重复结算统一走 `Timer.AddTimer`**（`Utils/MonoUtils/Timer.cs`，由 `Tool` 每帧驱动，服务端与客户端都能用）——技能侧**不缺延时能力**，要"延迟若干秒再结算一次"（多段命中、延时爆炸、持续期结束等）直接调它即可；用法见《代码架构说明》的 Utils 节与 Skills 节。

## 十四、局内成长：抽卡与词条

技能与强化的唯一获取途径 = **抽卡**。局内没有货币，也没有商店。

### 14.1 抽卡机会从哪来

每次机会都是**先定档位、再把一次机会存进该档**，档位由来源决定（`entity.csv` 的「被击败时卡牌掉落权重」列，`白银;黄金;炫彩` 三个权重加权）：

| 来源 | 档位权重（白银;黄金;炫彩） | 归属 |
| --- | --- | --- |
| 升级（`card_gain_upgrade.csv`，按升级后等级的个位数） | 个位 1/2/4/5/7/8 → 必白银；3/6/9 → 必黄金；**0 → 必炫彩** | 自己 |
| 击败进攻角色 | 6;3;1 | 仅击杀者 |
| 击败防守角色 | 0;0;1 | 击杀方全阵营各一次 |
| 击败防御塔 | 0;1;0 | 击杀方全阵营各一次 |
| 击败副守护点 | 0;0;1 | 击杀方全阵营各一次 |
| 击败主守护点 | 0;0;0（不掉卡，只给经验） | — |
| 击败天使 / 恶魔雕像 | 0;6;1 / 0;8;1 | 击杀方全阵营各一次 |

**抽卡次数不设上限**：团队目标全队各得一份，进攻方靠"拆建筑 + 全队各得"，防守方靠"独享击杀"，两边单人的抽取量大致对齐。

### 14.2 一次抽取怎么定内容

1. **定档**：按上表权重滚出 白银 / 黄金 / 炫彩。
2. **筛池**：遍历 `card/card_option.csv`，取「该档的幸运区间包含当前幸运」且「阵营限制为空或等于本阵营」的行。
3. **出 3 张不重复**：按行内权重抽 3 张；同一档内不会重复。
4. **技能卡**：从武器技能段（`Config.weapon_skill_id_min~max`）里筛出**与卡面品质相同**、且玩家**尚未持有**的技能随机取一个；描述里的 `{0}` 替换成该技能名。该品质已全持有 → 这张卡不进入池子。

**幸运**只做一件事：**决定同一档位里能刷出"多深"的卡**（区间在 `card_option.csv` 三列里配）。幸运不给任何掉落加成、不影响档位，也没有上限。

### 14.3 卡牌效果与词条

每张卡在 `card_option.csv` 里带「类型（代码用）+ 值（词条等级）」，值表示**这次给该词条增加几级**：

| 类型 | 效果 | 每级系数（`global_variables.csv`） |
| --- | --- | --- |
| `luck_boost` | 幸运 | `card_coef_luck_boost` |
| `health_boost` | 生命上限 % | `card_coef_health_boost` |
| `attack_boost` | 攻击力（固定值） | `card_coef_attack_boost` |
| `crit_rate_boost` / `crit_damage_boost` | 暴击率 / 暴伤（百分点） | `card_coef_crit_rate_boost` / `card_coef_crit_damage_boost` |
| `damage_vs_player` / `damage_vs_coral` / `damage_vs_building` / `damage_vs_zombie` | 对玩家 / 珊瑚 / 防御塔与守护点 / 鲛人与精英鲛人增伤 % | `card_coef_damage_vs_*` |
| `tower_attack_boost` / `guard_reduction_boost` | 己方防御塔攻击 / 守护点减伤（读防守方全体累加） | `card_coef_tower_attack_boost` / `card_coef_guard_reduction_boost` |
| `instant_heal_boost` | 一次性回复生命 %（抽到即结算，不进属性） | `card_coef_instant_heal_boost` |
| `damage_below_half_hp` | 自身生命低于 50% 时增伤 % | `card_coef_damage_below_half_hp` |
| `damage_vs_higher_hp` | 对生命比例高于自己的目标增伤 % | `card_coef_damage_vs_higher_hp` |
| `skill_b` / `skill_a` / `skill_s` | 给一个该品质的技能（值填 0，实际技能 id 由客户端抽出后上报） | — |

**词条是玩家级数据**：同一词条多次获得则**等级累加**（力量 I 之后再拿力量 II = 3 级，攻击 +60），不设上限；角色死亡期间仍然生效。

**进攻方角色被动以词条层数落地**：进局时按所选角色预置初始层数，层数序列在 `global_variables` 的 `passive_attack_layer`（按角色 value 顺序，与每级系数的比值决定实际百分比），与抽卡层数叠加。防守方被动是全局参数或受击即时判定，不占词条，数值在 `global_variables` 的 `passive_defense_*`。

### 14.4 界面与出口

- 有待抽次数时，战斗界面**侧边显示悬浮按钮**（档位 + 剩余次数）。
- 点开进入**抽卡界面**：三张卡横向铺开，卡面含标题 / 描述 / 技能预览，显示当前幸运；卡片逐张播入场动画。
- **选卡**：消耗该档一次机会，效果立刻生效。
- **弃卡**：把这一次折算成经验（`card_discard_exp_silver/gold/holo`，默认 120 / 240 / 480），**不吃经验增幅**——弃卡永远亏，只是把废牌折成残值。
- **关闭**：不消耗次数，按钮留在界面上。

## 十六、昼夜系统

**[A改]** 白天 **90s**、夜晚 **90s**，一个完整昼夜周期 = **180s**（2026-09-12 定稿）；**黄昏 / 黎明不单独计时**——归一化昼夜模型下昼夜切换自带渐变过渡。

**[A改 2026-09-12]【昼夜表示与同步：客户端自行推演】** 昼夜用**归一化周期时间 [0, 2)** 表示：**0 与 2 = 午夜，1 = 正午**；光照归一值 = 1 − |周期时间 − 1|（≥ 0.5 为白天，即周期时间 ∈ [0.5, 1.5)）。**方向由周期时间自身推导**，不需要单独传：< 1 正在变亮、≥ 1 正在变暗。
同步只下发**三个摘要**——周期时间 + 白天时长 + 夜晚时长，客户端据此**自行推进**，服务器**不逐帧同步**（仅在战斗开始、时长/时间被改动、以及固定心跳时下发完整快照）。时长发生变化时客户端按新速率继续，**不会跳变当前时刻**。

**[A改]** 复活进度系统（**速率制**，防止复活时昼夜状态切换问题）：白天每秒积累 **1/8**（8s 攒满）、夜晚每秒 **1/60**（接近不可复活）；死亡次数 → 进度积累倍率：**1、0.8、0.6、0.4、0.3、0.2、0.2...**（第一次 1，最低 0.2）。复活**只有"等待复活进度攒满"这一条路径**，昼夜对复活的唯一影响就是上面两个速率（白天快 / 夜晚极慢）。

**[A改]** 防守方复活时长 = **25s（昼夜一样）**。出生点与复活点合并为同一个点：进攻方用 `TerrainSpawns.AttackSpawn`、防守方用 `TerrainSpawns.DefenseSpawn`——由地形普通点位中离主守护点**最远/最近**的一个派生，开局出生与死亡复活都用它，不做去重。珊瑚与鲛人出生点不走点位，运行时随机采样 + 向下射线判定合法性。

**[A]** 昼夜的**全局影响清单**限定为三条：①复活进度速率 ②鲛人刷新 cd 进度（夜间积累、白天不积累，见第九章）③**夜间自动为进攻方添加 Debuff = 小地图只显示己方阵营，敌方单位不显示**。其余一切昼夜相关效果全走技能/Buff。

**[A改]** 昼夜**不影响主动技能**；只有部分**被动技能**与夜晚相关。

**[A改]** "夜间拆雕像减速"后续依靠防守方为守护雕像提供 Buff 实现（非全局规则）。

**[A删]** "终局阶段"概念**彻底删除**，全程统一规则。

## 十七、死亡、复活与胜负结算

### 17.1 死亡与复活 [A]

**[A]** 复活进度系统见第十六章；玩家死亡即进入复活等待（无倒地救援）。**死亡后服务器直接摧毁该单位，复活时重新创建**（自然满血；Buff 随摧毁消失，不复活后重加；愈战愈勇由复活系统按死亡次数重新添加）。

**[A改]** 愈战愈勇：复活时按累计死亡次数叠加属性层（**暂不设上限**；后续配置"第 n 次复活 → 效果层数"）；**每次死亡清空该 Buff，复活时重新完整添加**；双方同规则；无外观表现；每层属性待定 [C]。

**[A改]** **AI 与真人玩家的所有判定完全一样**（死亡/复活/团灭/结算）。

**[A]** 防守方死亡不判负（死亡期间场上无人防守，等于让出拆雕像窗口）；防守方复活时长与位置待定 [C]。

### 17.2 胜负（分数制）[A]

**[A改]** 进攻方分数 = **对守护雕像造成的总伤害**（2026-09-06 拍板）；进攻方击杀不计分。

**[A]** 国王雕像被摧毁 → 进攻方必然获胜（拆除量满格，立即结束对局）。

**[A改]** 防守方分数 = **守护雕像剩余血量 × (1 + 0.1 × 击杀数)**（2026-09-06 拍板）。

**[A]** 进攻方全灭 = 立即结算当前分数并结束对局（**不直接判负**）；若进攻方此前拆除量已过半，按分数可能判胜。

**[A]** 时间耗尽 → 双方分数比较，高者胜。

**[A改]** **不单独处理平局**（分数相同按进攻方胜处理，通常认为不会发生）。

**[C]** 击杀分在防守方总分中的占比待定。

### 17.3 对局结算 [A]

**[A]** 对局结束后**不带出任何东西**：技能、词条、局内等级全部清空（没有局外养成）。结算界面只展示本局战绩：攻守双方分数、剩余时间、防守方击杀数、守护点剩余血量。

```text
→ 核心被摧毁 / 进攻方全灭（提前结算）/ 时间耗尽
→ 按分数结算胜负
→ 展示本局战绩，返回组队阶段（局内成长全部清空）
```
