AI 实时操控交互（命令行 + Lua）
====================================================

一、总体架构
----------------------------------------------------

控制权：决策在客户端，执行在服务器。
  客户端：命令行（外部 AI 的入口，命令集来自配表）+ Lua（状态机脚本 + 命令行拓展脚本）
  服务器：意图转发 + 行为层，不做任何决策

三条链路：
  1. 命令行 → 本地 C#（房间流程、聊天、查询类，不联网也能取）
  2. Lua 状态机 → 本地 C# → 意图上行 → 服务器意图转发器 → 行为层
  3. 服务器事件 / 用户操作 → 中断原因列表 → ai.interrupts（外部 ai.wait 轮询）

行为层复用现有三件套，不新写状态机：
  BehaviorArbiter + IBehaviorHost + IdleBehavior / MoveBehavior / AttackBehavior
  停步、朝向、动作未播完不许切（AttackBehavior.CanInterrupt = !host.IsActing）全部归行为层
服务器侧只有「意图转发器」，做「客户端意图 → BehaviorArbiter 请求」的翻译，不含决策

复用边界：
  不复用 GM 指令通道（CSGm / ExecuteGm）
  不复用上帝视角协议（CSGodViewArea 等）
  不复用 RobotAi（人机决策机）及其技能栏
  复用项目基础设施：BehaviorArbiter / IBehaviorHost / Behavior、EntitySkillController、Timer、EventManager

坐标与时间口径：
  位置只给 XZ（地形是平的），单位米；不传高度，服务器按地面吸附
  朝向为 yaw 度数，0° = +Z，与 PlayerEntityData 的 moveState.yaw 同口径
  昼夜用 BattleManager.CycleTime（0~2 单调，0/2 午夜、1 正午），白天落在 0.5~1.5

交互语义：
  命令一律立即返回（结果作为返回文本），没有阻塞式命令
  失败以「错误：…」文本返回，不抛出协议错误
  移动不做「到达」中断：到没到由 AI 自己查坐标，走不到会收到 MoveFailed
  无命令 = 服务器保持最后一个动作，不设超时兜底

二、命令行：ai_command 配表驱动
----------------------------------------------------

2.1 表结构（Config/Source/ai_command.xlsx，表名 ai_command）
  列：key / command / commandHelp / home / lobby / battle /
      param1Name / param1Type / param1Desc（param2、param3 同构）
  home / lobby / battle 为 bool?：填 1 = 该相位可用，留空 = 不可用
  参数类型只允许 int / float / bool / string / List<int>
  一张表 33 行，主键即命令 id

2.2 代码接线
  configtool.py 生成 ai_commandConfig.cs + ai_command.bytes，并写入 ConfigManager.LoadAll
  Config/AiCommandConfig（TableConfigs.cs）：content 字典 + ordered（按 key 升序）
  ConfigManager.InitExtensions 里 Bake，早于 ClientLogicManager.Awake（DefaultExecutionOrder -200）
  AiInterface/AiCommandId.cs：主键常量，配表增删或改 id 时同步改
  AiCommandLine.RegisterFromConfig：按 ordered 建命令表（名称 / 相位 / 用法串），byName 字典查表
  AiCommandLine.Dispatch：按 row.key switch 到具体处理函数
  配表有行但代码没接：返回「错误：命令 id=N 没有对应的处理逻辑」

2.3 参数规则
  全部在客户端校验，类型或个数不对直接本地拦截，不发服务器
  int / float：严格解析；float 拒绝 NaN / Infinity
  bool：true / false / 1 / 0
  string：单个 token；「最后一个且不是第一个」的 string 吃掉剩余全部 token（聊天内容、lua 参数）
  List<int>：吃掉剩余全部 token，空格或分号分隔，允许为空
  命令名大小写敏感

2.4 相位
  Offline = 未连上服务器（Home）
  Lobby   = 已连上、战斗未开始
  Battle  = 战斗进行中
  用错相位返回「错误：命令 X 在当前相位 Y 不可用」

2.5 命令清单（33 条，参数见括号）
  Home（Offline）
    setMyPlayerName(name:string)      设置本地玩家名称
    getMyPlayerName()                 读取本地玩家名称（三相位都可用）
    selectCharacter(camp:int,index:int) camp 0 进攻 / 1 防守，index 为该侧角色下标
    connectToServer(ip:string)        连接服务器，ip 必填
    takeover(enabled:bool)            true = AI 接管并锁本地输入，false = 还给人
  Lobby
    joinCamp(camp:int)                0 进攻 / 1 防守 / 2 观战
    lobbyPrepare(prepared:bool)       准备 / 取消准备
    exitRoom()                        离开房间
  通讯（Lobby + Battle）
    sendChatMessage(channel:int,message:string)  0 全频道 / 1 阵营 / 2 附近
    readChatMessage(channel:int,count:int)       0 全部 / 1 阵营 / 2 附近 / 3 系统
    quickMessage(messageId:int)                  对应 quick_message 主键 0~7
    quickMessageWithPosition(messageId:int,x:float,z:float)
  Battle 操作
    moveTo(x:float,z:float)
    collectCoral()                    攻击小地图上最近的珊瑚
    castSkill(skillId:int)            走 CSAiSkillCast 专用通道
    calculatePath(x:float,z:float)    客户端 NavMesh 预估
    startLuaStateMachine()            激活即整份重载拓展脚本 + 状态机脚本
    stopLuaStateMachine()             停决策并下发一次站立
  Battle 查询
    getSkillList()                    槽位 + 冷却进度 + 库存
    setSkillColumn(skillIds:List<int>) 服务器校验后回推快照，空列表 = 清空
    getInfo()                         自身 / 守护点 / 阵营人数 / 昼夜 / 小地图条数
    currentPos()
    getSelfStatus()                   实体 / 阵营 / 血量 / 坐标 / 朝向 / buff
    getGuardProgress()                四个守护点当前血量（上限读 entity.csv）
    getMinimapEntities()              小地图缓存逐条
    getDayNightInfo()                 昼夜 + CycleTime
    getCampCount()                    双方存活/总数 + 观战人数
    getPointInfo()                    守护点 / 防御塔 / 中立雕像 / 出生点
    setCameraRender(enabled:bool)     相机渲染开关
    screenshot()                      存到 <项目根>/Screenshots
  Lua（三相位都可用）
    reloadLuaCommand()                只重载 extensions.lua，不动状态机
    execLuaCommand(command:string,args:string)
    listCommands()                    当前相位可用命令 + lua 拓展命令名

2.6 错误口径
  空命令        → 错误：空命令
  未知命令      → 错误：未知命令 X（用 listCommands 查看）
  相位不符      → 错误：命令 X 在当前相位 Y 不可用
  参数个数不符  → 错误：参数数量不符，用法 <command> <name>:<type>…
  参数类型不符  → 错误：参数 X 必须是 Y
  业务前置不满足→ 错误：未联网 / 没有战斗会话 / 本地玩家实体未就绪 等

三、对外入口（StreamingAssets/AiCmd）
----------------------------------------------------

传输：本机 TCP 127.0.0.1:21928（runtime-bridge，随游戏自动开服，ini 在
      StreamingAssets/unity-python-bridge-runtime/runtime_bridge.ini）

目录：
  exec.bat       exec <命令> [参数...]，所有命令的统一入口
  ping.bat       连通性检测
  wait.bat       轮询 ai.interrupts 模拟阻塞等待
  _env.bat       公共前置：定位桥客户端与 python，导出 PYDIR / PY
  _call.py       exec 的实现：读 AI_LINE 环境变量，调 ai.exec
  wait.py        wait 的实现

实现要点：
  exec.bat 把整条命令行塞进 AI_LINE 环境变量再交给 _call.py，
  不在 bat 里做嵌套引号转义（带空格的聊天内容原样保留给 C# 的 SplitArgs）
  _env.bat 依次探测打包布局与编辑器布局，都找不到时用 AI_BRIDGE_PY，
  解释器优先随包的 ../python/python.exe，再退系统 python / py -3
  桥侧命令只有两个：ai.exec（执行一条命令行）与 ai.interrupts（取走中断）
  bat 必须 CRLF、正文纯 ASCII；中文只作为命令行参数传入
  退出码：0 正常（含超时）/ 1 连接或调用失败 / 2 参数错误

四、Lua 接口
----------------------------------------------------

环境：
  借用 LuaManager 的 LuaEnv（不自建），Env 重建后重挂 ai 全局
  AddLoader 把 require("a.b") 映射到 StreamingAssets/LuaInterface/a/b.lua
  入口脚本：state_machine.lua（必须定义 on_tick(dt)）、extensions.lua
  激活/停止/重载都整份重新执行入口脚本，不清理 package.loaded（require 的用户模块沿用缓存）
  脚本抛错 → LogError + LuaError 中断 + 停状态机 + 下发一次站立

ai 表（读：零成本，可每帧调）
  phase() / connected() / self_id() / self_camp() / self_alive()
  self_hp() / self_max_hp() / self_x() / self_z() / self_yaw()
  buff_count() / buff(i)
  map_count()（顺带刷新缓存）/ map_id(i) / map_cat(i) / map_val(i) / map_camp(i) / map_x(i) / map_z(i) / map_marked(i)
  slot_count() / slot_skill(slot) / slot_progress(slot) / slot_store(slot)
  held_count() / held_skill(i) / skill_info(skillId)
  guard_progress(index) 0~100 被打掉的血量百分比，index 0 主 / 1~3 副；无数据 -1
  is_night() / cycle_time()（0~2 单调，0/2 午夜、1 正午）

ai 表（写：只在值变化时上行）
  stand() / stop() / move_to(x,z) / attack(entityId)
  cast_skill(skillId)        走 CSAiSkillCast，不做技能注册校验
  signal(messageId) / signal_at(messageId,x,z)   8 种快捷消息，位置可选
  interrupt(text)            推一条 LuaTrigger 中断
  register_command(name,fn) / command_count() / command_name(i)

去重：移动/站立/攻击同值不重发；自身实体 id 变化（复活换实体）时缓存作废

五、服务器：接管与意图转发
----------------------------------------------------

接管来源：
  客户端在 Home 阶段用 takeover 选定控制模式，连接时随 CSLobbyPlayerInfo.aiTakeover 上报
  BattleManager.AddPlayer 按该标记把 clientId 记进会话级 AiClients
  出战与复活置 aiControlled 后立即 new AiIntentRelay（不等第一条意图）
  进房后不能再改模式（takeover 只在 Offline 相位注册）

接管效果：
  PlayerEntityData.aiControlled 决定 OnTickMove 走 TickRobotMove 的自动驱动分支
  KeyboardBlocked 为真 → 该客户端的键盘移动、技能键一律丢弃
  AiClients 只在玩家退场时移除

意图转发（AiIntentRelay，DecisionMachine + IBehaviorHost）：
  ThinkInterval = 0，RelayState 每拍重申意图，命令到达当帧就落到行为层
  站立 / 停止 → RequestIdle；移动到位置 → RequestMove；攻击目标 → RequestAttack
  出手顺序：持有技能按品质降序、同品质 id 降序；全不可用退空手拳
  目的地算不出路 → Stop + NotifyStuck → SCAiFeedback(kind=0) → 客户端 MoveFailed 中断

协议：
  CSAiIntent{intent 0 站立/1 移动到位置/2 攻击目标/3 停止, posX, posZ, targetId}
  CSAiSkillCast{skillId}                     AI 专用，接管期间键盘包被丢弃也不影响它
  SCAiFeedback{kind, posX, posZ, targetId}   目前只有 kind=0 移动失败

释放技能属于插队行为：停步 + 面朝（若有目标）+ TryUseSkill，保留原意图
攻击类不判距离：超距也会放出去，走到射程内是客户端状态机的职责
无命令 = 行为层「本拍没意见」，保持当前动作，服务器不做超时兜底

六、默认状态机（StreamingAssets/LuaInterface/state_machine.lua）
----------------------------------------------------

状态：站立、移动到位置、攻击敌人、逃跑、寻找珊瑚、追击珊瑚、攻击珊瑚
参数（脚本顶部常量）：CHASE_RANGE 12 / BREAK_RANGE 18 / AGGRESSION 0.5 / UNARMED_RANGE 2 / PULSE 0.2

规则（每 0.2 秒一拍，感知全部来自小地图）：
  血量 < (1 − 攻击性 × 0.7) 且附近有敌人 → 逃跑：朝背离敌人方向撤到脱离阈值外
  敌人进入仇恨范围（max(追击阈值, 当前有效射程)）→ 射程内 attack、射程外 move_to
  敌人拉出脱离阈值或消失 → 回站立
  视野内有珊瑚 → 射程内 attack、射程外 move_to（真敌人优先于珊瑚）
  都没有 → 站立
有效射程 = 有库存技能里最远的射程（ai.skill_info 的「射程=」），全部无库存时按空手拳 2m

注意：状态机激活期间，命令行的 move_to / collectCoral 会被状态机节拍覆盖；手动控制先 stopLuaStateMachine

七、中断系统
----------------------------------------------------

结构：
  C# 维护中断原因列表，每条 = 类型 + 若干上下文段；上限 16 条
  同类型在 2 秒窗口内合并为一条：保留最后一次的字段并带「×N」
  ai.interrupts 一次取走全部积压并清空；没有则返回空串

类型（只有这 6 种）：
  BattleStart   阵营
  BattleEnd     结算状态码
  ChatMention   发送者、频道、内容（内容里出现 @自己的名字）
  LuaTrigger    Lua 主动 ai.interrupt(text)
  LuaError      脚本名、错误消息
  MoveFailed    坐标、目标

语义：
  中断只记录，不打断角色当前动作，也不打断 Lua 执行
  外部阻塞等待由 ai.wait（wait.bat）轮询 ai.interrupts 实现，超时文本由脚本侧合成

八、Lua 命令行拓展
----------------------------------------------------

注册：Lua 侧 ai.register_command(命令名, 处理函数)，处理函数收一整串参数字符串、返回字符串
调用：execLuaCommand <命令名> <参数...>，与内置命令同一套切分
重载：reloadLuaCommand 清空注册表后重跑 extensions.lua，不动状态机与 on_tick
枚举：listCommands 末尾会列出已注册的拓展命令名
报错：拓展命令抛错进 LuaError 中断并作为返回文本，不影响状态机

十、已知限制
----------------------------------------------------

1. 连接/进房的最终结果不回传：connectToServer 立即返回「已发起连接」，成功失败都不是返回值；
   判断方式是过几秒发一条 lobby 命令，返回「相位不可用」说明还没进房
2. connectToServer 的 ip 必填，没有「省略就走本机」的写法
3. selectCharacter 是 camp + index：一次只设一侧的角色下标
4. takeover 只在 Offline 相位可用；接管期间本机键鼠、相机、战斗页快捷键、GM 快捷键全部失效，
   FGUI 也不响应点击；解除只能靠 exec takeover false
5. 攻击不判距离，超距会空放并进冷却
6. 移动没有「到达」通知，也只在意图变化时下发；失败后同一意图不重发
7. 状态机激活期间会覆盖手动移动/攻击命令
8. 停发命令 = 保持最后一个动作，不会自动停下
9. 小地图数据有延迟（1.5s 超时剔除），坐标是近似值
10. 昼夜是 0~2 的周期值，不是 0~1 的百分比；不要拿折返量当进度
